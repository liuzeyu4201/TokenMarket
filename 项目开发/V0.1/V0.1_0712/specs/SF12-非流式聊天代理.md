# Feature Specification: SF12 非流式聊天代理

**Feature ID**: `SF12`  
**Short Name**: `nonstream-chat-proxy`  
**Created**: 2026-07-13  
**Status**: Draft  
**Source**: 周度 Spec F04、路线图代理指标、Go 网关 API/流水线规范

## 目标与价值

为买家提供火山方舟非流式 OpenAI-compatible Chat Completions 代理入口。请求经过认证、授权、路由和兼容转换后发送至火山方舟，成功响应保持兼容语义，前置和上游失败返回稳定可关联错误。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完成一次非流式代理调用 (Priority: P1)

作为买家，我希望只替换 Base URL 和 API Key 就能调用火山方舟并获得兼容响应。

**Independent Test**: 以有效代理 Key 和标准非流式请求调用公开路径，验证选中非本人卖家 Key、上游响应语义和 request_id。

**Acceptance Scenarios**:

1. **Given** 代理 Key 有效且候选池有可用 Key，**When** POST `/v1/proxy/volcano/chat/completions` 且 `stream=false`，**Then** 返回兼容成功响应和 `X-Request-ID`。
2. **Given** 客户端提供合法 X-Request-ID，**When** 请求贯穿认证、路由、适配和响应，**Then** 同一标识用于全部阶段；未提供时由网关生成。
3. **Given** 火山方舟正常返回 usage，**When** 响应完成，**Then** usage 保持兼容并向 SF17 产生一次用量观察。

---

### User Story 2 - 获得确定的前置失败 (Priority: P1)

作为买家，我希望无效 Key、非法请求和无可用卖家 Key 能快速返回清晰错误，不产生上游调用。

**Acceptance Scenarios**:

1. **Given** 代理 Key 无效，**When** 调用，**Then** 返回 401 和 request_id，路由与火山方舟调用次数为零。
2. **Given** 请求不符合兼容 Schema，**When** 调用，**Then** 返回 400/422 契约错误，不发起上游调用。
3. **Given** 没有符合平台、所有权、健康和容量要求的 Key，**When** 调用，**Then** 返回 503，不崩溃也不泄露卖家信息。

---

### User Story 3 - 有界处理上游故障 (Priority: P1)

作为买家，我希望火山方舟超时或失败时请求在明确时间内结束，并能凭 request_id 排查。

**Acceptance Scenarios**:

1. **Given** 上游认证失败或权限失败，**When** 转发，**Then** 返回安全的 502 类平台错误并通知 Key 健康状态处理，不暴露原始 Key。
2. **Given** 上游 30 秒没有有效响应进展或整体请求达到 60 秒，**When** 截止触发，**Then** 返回 504 并释放连接和容量。
3. **Given** 上游 429，**When** 响应到达，**Then** 返回稳定限流错误并触发 SF14 冷却，不自动重放本次生成请求。

### Edge Cases

- `stream` 缺失、为 null、字符串或 true。
- 请求体为空、超出大小限制、JSON 非法或 messages 为空。
- 客户端在上游处理中取消连接。
- 上游成功但响应格式不合法或使用量缺失。
- 上游已接受请求后网络断开，自动重试可能造成重复消耗。
- 状态在路由选择后、发起请求前变为 paused/revoked。
- 响应包含不安全 hop-by-hop 或敏感头。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 公开入口 MUST 为 `POST /v1/proxy/volcano/chat/completions`，要求 Bearer 代理 Key 和 JSON 请求体。
- **FR-002**: V0.1 本功能 MUST 只接受 `stream=false` 或缺省的请求；`stream=true` 由 SF15 处理。
- **FR-003**: 请求 MUST 按版本化兼容 Schema 校验，并限制请求体大小、消息数量和字段范围。
- **FR-004**: 流水线顺序 MUST 保证请求标识、SF11 认证、SF05 授权、SF13 路由、SF14 容量、SF07 转换/调用、结果记录和响应。
- **FR-005**: 选中的卖家 Key MUST 在调用前再次确认未撤销/暂停且不属于当前 buyer。
- **FR-006**: 成功响应 MUST 保持 OpenAI-compatible 结构，不包裹业务响应 envelope；响应头包含 request_id 和安全的平台/模型信息。
- **FR-007**: 认证、参数和路由前置失败 MUST 使用统一错误结构 `{code,message,data,request_id,timestamp}`。
- **FR-008**: 上游错误 MUST 映射为稳定 HTTP/业务错误：429 限流、502 上游错误/非法响应、504 超时、503 无可用 Key。
- **FR-009**: 整体请求硬超时 MUST 为 60 秒；连接和无进展读取使用更短有界超时，具体值在契约中记录。
- **FR-010**: V0.1 MUST NOT 自动重放已可能被火山方舟接受的 Chat Completion，以避免重复消耗；可重试行为需独立证明幂等。
- **FR-011**: 客户端取消 MUST 传播到上游，释放容量并记录失败结果。
- **FR-012**: 请求/响应正文、代理 Key 和原始 Key MUST NOT 进入日志；必要诊断只记录大小、模型和脱敏标识。
- **FR-013**: 无论成功或失败，每个请求 MUST 至多产生一个供 SF17 使用的完成观察，重复记录由 request_id 幂等处理。

### Engineering Requirements *(mandatory)*

- **ER-001 — Contracts**: 公开兼容契约、错误 Schema、响应头和状态码须机器校验；流式成功是统一 envelope 的明确例外。
- **ER-002 — Security & Privacy**: TLS、输入 Schema、Header 允许列表、服务端认证/授权、秘密脱敏和请求体不落日志为强制要求。
- **ER-003 — Data Integrity**: request_id 唯一关联路由和用量；路由选择及完成结果不得产生重复计量事实。
- **ER-004 — Performance & Capacity**: 代理额外 TTFB P95 小于 800 毫秒；内部压测超过 100 QPS，100 次连续有效请求成功率大于 98%。
- **ER-005 — Reliability**: 超时、取消、连接池、背压和优雅关闭必须明确；不对非幂等上游生成请求自动重试。
- **ER-006 — Observability**: 记录 rate、errors、duration、saturation、上游结果、路由 Key 脱敏 ID 和 request_id；失败映射到可操作告警。
- **ER-007 — Accessibility**: 本功能为开发者 API；错误提供稳定代码、可读说明和 request_id，不依赖图形界面。

### Failure and Recovery Scenarios *(mandatory)*

1. **Given** 上游在可能接受请求后断开，**When** 网关无法确认结果，**Then** 返回明确不确定上游错误，不自动重放，并仍产生一条失败观察。
2. **Given** 客户端取消，**When** 取消传播，**Then** 上游连接和容量在有界时间内释放，计量记录状态为 cancelled。
3. **Given** 网关进程重启，**When** 新实例就绪，**Then** 从事实源/可重建缓存恢复认证与路由；在 readiness 前不接收流量。

### Key Entities

- **Proxy Request Context**: request_id、buyer、proxy_key_id、platform、model、选中 seller key 脱敏 ID 和时间边界。
- **Proxy Completion Result**: 上游状态、兼容响应状态、耗时、usage 完整性和结束原因。
- **Error Mapping**: 内部失败类别到公开 HTTP/业务错误的稳定映射。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100 次连续有效请求成功率大于 98%。
- **SC-002**: 代理额外 TTFB P95 小于 800 毫秒，内部压测持续吞吐超过 100 QPS。
- **SC-003**: 无效 Key、非法请求和无可用 Key 场景上游调用次数为 0。
- **SC-004**: 所有请求在 60 秒内完成、取消或返回超时，不泄漏连接与容量。
- **SC-005**: 每个请求的认证、路由、上游和结果均可通过单一 request_id 关联。
- **SC-006**: 日志和错误扫描不出现请求正文、代理 Key 或原始 Key。

## Scope

### In Scope

- 火山方舟非流式 Chat Completions 公开代理、前置错误、超时/取消和完成观察。

### Out of Scope

- 流式代理、自动上游重试、Embeddings、计费、余额扣减、多平台和前端。

## Test Requirements

- 单元测试覆盖流水线顺序、错误映射、超时和 Header 策略。
- 适配器/公开契约测试覆盖兼容请求与响应。
- 集成测试覆盖认证、路由、取消、无可用 Key 和进程 readiness。
- 压测验证 >100 QPS、>98% 成功率与 P95 目标，记录环境。
- 网关相关包至少 80% 行覆盖，授权、取消、超时和非重试分支直接覆盖。

## Assumptions

- 依赖 SF07、SF11、SF13；容量保护接入 SF14。
- SF17 可以稍后交付，但本功能从开始即产生唯一完成观察接口。
- 性能指标的“代理额外延迟”不包含模型生成耗时，测量方法在计划中固定。
