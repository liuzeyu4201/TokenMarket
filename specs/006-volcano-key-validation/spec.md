# 功能规格：火山方舟凭证与额度验证

**功能分支**: `006-volcano-key-validation`

**创建日期**: 2026-08-01

**状态**: 草案

**输入**: 用户描述："开启新分支，功能描述在 `项目开发/V0.1/V0.1_0712/specs/SF06-火山方舟凭证与额度验证.md`"

**源规格**: `项目开发/V0.1/V0.1_0712/specs/SF06-火山方舟凭证与额度验证.md`（SF06）；本规格将其内部凭证验证、额度与模型能力检查、稳定错误分类要求纳入 Spec Kit 可规划、可验收的功能规格。

## 目标与价值

为系统内部提供火山方舟凭证验证能力，在持久化或投入路由池之前确认凭证的认证状态、权限、剩余额度和可用模型。验证结果必须区分永久无效、零额度、限流和临时故障，防止把可恢复故障误判成永久失效。

本功能是卖家 Key 接入（SF08）与健康事实更新（SF16）的前置判定：接入侧据此决定是否接收凭证，健康侧据此更新可路由性，而不在本功能内完成持久化或代理转发。

## Clarifications

### Session 2026-08-01

- Q: 火山方舟无法提供官方额度时如何处理？ → A: 强制可信额度：官方额度可得则返回精确值；不可得或契约不符 → `quota_unavailable`，**不得**写成 `zero_quota` 或 `remaining_quota=0`。
- Q: 认证与额度均通过但无 V0.1 支持模型时如何分类？ → A: 不可路由：`error_category=no_supported_models`，`availability=unavailable`；`validity` 仍为有效（非 `invalid`）。
- Q: 谁负责「不得用临时失败覆盖最后一次可信认证事实」？ → A: 调用方负责：SF06 无状态单次结果；SF08/SF16 MUST 遵守合并规则（临时/限流/`quota_unavailable`/`no_supported_models` 不得写成永久 `invalid`）。
- Q: 并发验证的默认上限取多少？ → A: 默认全局 32、单凭证 1（可配置；测试锁默认与超限语义）。
- Q: 限流时上游未给出建议重试时间怎么办？ → A: 始终给出 `retry_after_seconds`：优先上游建议，缺失则默认 5 秒（可配置）。

### Session 2026-08-01（analyze 收口）

- I1: 非 `volcano` 的 `platform` → 契约接受字符串，业务 HTTP 200 + `unsupported_platform`（非 schema 422）。
- C1: 内部 `X-Internal-Token` 仅隔离网；test/prod 默认关路由，启用须回环/私网/mTLS，禁止公网仅靠静态 token；启动 fail-closed。

## 用户场景与测试 *(必选)*

### 用户故事 1 - 验证有效凭证和额度 (优先级: P1)

作为准备接入 Key 的卖家（经接入流程调用本能力），我希望平台快速确认凭证有效并得到真实剩余额度，以便判断它是否可用于 V0.1 代理服务。

**优先级理由**: 无法确认有效性与额度的凭证不得进入路由池；这是接入与健康检查的第一道可信门禁。

**独立测试**: 使用火山方舟测试环境或受控契约替身返回有效凭证、额度和模型列表，验证标准化结果字段完整且语义正确。

**验收场景**:

1. **Given** 凭证有效、具备所需权限、官方额度可得且余额大于零，**When** 发起验证，**Then** 在 3 秒内返回 valid、可用额度、支持模型和验证时间。
2. **Given** 凭证有效且官方额度明确为零，**When** 发起验证，**Then** 返回「凭证有效但不可路由」的零额度结果（`zero_quota`），而不是认证失败。
3. **Given** 上游返回可用模型列表，**When** 标准化结果，**Then** 只标记 V0.1 支持的 Chat Completions 模型能力。
4. **Given** 官方不提供额度接口、额度字段缺失或无法映射到声明单位，**When** 发起验证，**Then** 返回 `quota_unavailable`（或契约映射的等价协议/失败关闭分类），**不得**将 `remaining_quota` 填为 0 或归类为 `zero_quota`。
5. **Given** 凭证认证有效、额度可信且大于零，但标准化后 `supported_models` 为空（上游无模型或与 V0.1 集合无交集），**When** 发起验证，**Then** 返回 `no_supported_models`，`availability=unavailable`，`validity` 为有效，不得标为 `invalid`。

---

### 用户故事 2 - 获得稳定且安全的失败分类 (优先级: P1)

作为 Key 接入与健康检查能力，我希望根据失败类型采取不同状态转换，而不是依赖上游错误文本。

**优先级理由**: 错误分类直接决定是否写入「永久无效」等不可逆状态；分类错误会导致好 Key 被误杀或坏 Key 被误用。

**独立测试**: 模拟认证失败、权限拒绝、限流、超时、连接失败、格式错误和上游服务错误，验证错误分类与是否允许重试。

**验收场景**:

1. **Given** 上游判定凭证认证失败或无权限，**When** 验证凭证，**Then** 返回永久认证/权限失败分类，且不返回或记录完整凭证。
2. **Given** 上游判定请求被限流，**When** 验证凭证，**Then** 返回 `rate_limited` 与机器可读的 `retry_after_seconds`，不标记凭证永久无效。
2a. **Given** 上游限流但未提供建议重试时间，**When** 标准化结果，**Then** `retry_after_seconds` 为默认 5（可配置），不得省略该字段。
3. **Given** 上游超时、网络失败或暂时性服务错误，**When** 验证凭证，**Then** 返回暂时不可用分类，不声称余额为零或凭证无效。
4. **Given** 上游响应无法解析，**When** 验证，**Then** 返回上游协议错误并保留安全诊断信息（脱敏后）。
5. **Given** 认证看似成功但额度不可信（无官方源、字段缺失或契约不符），**When** 验证，**Then** 分类为 `quota_unavailable`，不得当作 `zero_quota` 或 `success`。

---

### 用户故事 3 - 取消与超时下的安全收尾 (优先级: P2)

作为调用方（接入或健康检查），我希望验证在截止时间或取消时能干净结束，不泄漏凭证、不占用连接。

**优先级理由**: 网关与健康调度会高频调用验证；取消与超时是常态，若收尾不完整会累积连接泄漏与敏感内存驻留。

**独立测试**: 在截止前取消请求、强制超时，以及并发同一凭证验证，确认取消传播、连接释放与并发上限生效。

**验收场景**:

1. **Given** 调用方在验证进行中取消请求，**When** 上游仍在处理，**Then** 取消传播到网络调用，并释放连接与敏感内存。
2. **Given** 验证已达到 3 秒硬截止，**When** 上游尚未完成，**Then** 以临时失败结束，不写入永久无效。
3. **Given** 同一凭证被多个接入请求同时验证，**When** 系统处理，**Then** 不突破单凭证与全局并发上限；各次调用独立返回当次分类（本功能无跨请求状态可竞态覆盖）。

### 边界情况

- 上游在 3 秒截止前部分返回数据但响应未完成。
- 余额单位、精度或字段缺失，与已知契约不一致。
- 同一凭证被多个接入请求同时验证。
- 请求取消后上游调用仍未结束。
- 上游返回成功状态但认证信息或模型列表为空：模型列表为空或与 V0.1 无交集时为 `no_supported_models`（有效但不可路由），不是 `invalid`。
- 错误响应正文包含用户原始 Key 或其他敏感头。
- 调用方请求的平台不是火山方舟（V0.1 仅支持该平台）。
- 上游成功但额度字段缺失或无法映射到声明单位：必须失败关闭为 `quota_unavailable`，不得猜测余额，不得填 0。
- 官方明确不提供额度查询：同样 `quota_unavailable`，禁止用「返回零值」占位实现。

## 需求 *(必选)*

### 功能需求

- **FR-001**: 验证输入 MUST 只接受内部调用传入的提供商凭证、`platform` 与请求标识。契约层 MUST 接受任意非空 `platform` 字符串（不得在 schema 层因非 `volcano` 直接 422）；V0.1 仅当 `platform=volcano` 时进入上游验证，其他平台 MUST 在业务结果中返回 `error_category=unsupported_platform`（HTTP 仍为成功完成验证的语义，见内部 OpenAPI）。
- **FR-002**: 验证 MUST 检查认证有效性、必要权限、剩余额度和 V0.1 所需模型能力；其中剩余额度 MUST 来自当期官方可信额度源。
- **FR-002a**: `supported_models` MUST 仅为上游模型集合与 V0.1 Chat Completions 支持集合的交集；不得透传未纳入 V0.1 的模型标识为「已支持」。
- **FR-003**: 正常验证 MUST 在 3 秒截止时间内返回；调用方取消时 MUST 立即传播取消。
- **FR-004**: 标准结果 MUST 至少包含 `validity`、`availability`、`remaining_quota`、`quota_unit`、`supported_models`、`checked_at` 和 `error_category`。仅当额度可信可读时，`remaining_quota`/`quota_unit` 才有值；`quota_unavailable` 时额度字段 MUST 为空或未设置，不得为 0。当 `error_category=rate_limited` 时 MUST 额外包含 `retry_after_seconds`。
- **FR-005**: 上游认证失败与权限拒绝 MUST 映射为认证或权限的永久失败；限流 MUST 映射为 `rate_limited`；超时、连接错误和暂时性上游错误 MUST 映射为临时失败。
- **FR-005a**: `rate_limited` 时 MUST 始终提供 `retry_after_seconds`：若上游给出明确建议重试间隔则采用该值（实现可对异常大值做合理上限钳制，钳制策略在计划阶段写明）；若上游未提供，则使用默认 **5** 秒。默认值 MUST 可配置，且默认 5 秒行为 MUST 有自动化测试。
- **FR-006**: 零额度 MUST 仅在官方明确返回剩余额度为零时使用，并与无效凭证区分，标记为不可接入/不可路由。
- **FR-006a**: 当认证有效且（若额度步骤已执行）额度可信，但 `supported_models` 为空时，MUST 返回 `error_category=no_supported_models`、`availability=unavailable`；`validity` MUST 仍为有效，MUST NOT 映射为 `invalid` 或 `forbidden`。该结果与 `zero_quota` 同属「有效但不可接入/不可路由」。
- **FR-007**: 本功能 MUST 为无状态单次验证：每次调用仅基于当次上游结果产出分类，MUST NOT 维护跨请求的「最后一次可信认证」缓存或状态机。
- **FR-007a**: 合并规则作为**调用方契约**（SF08/SF16 及后续健康/接入逻辑）：当消费 SF06 结果更新持久健康或接入事实时，MUST NOT 用 `rate_limited`、`temporary_unavailable`、`timeout`、`quota_unavailable`、`no_supported_models` 等非永久失败将既有可信认证结论覆盖为永久 `invalid`；仅 `invalid`/`forbidden`（及契约明确的永久类）可用于将认证事实标为无效。本功能通过稳定 `error_category` 使该规则可测，但不在本功能内执行持久合并。
- **FR-008**: 验证能力 MUST NOT 持久化完整凭证，也 MUST NOT 持久化验证结果；是否保存标准化结果由 SF08/SF16 决定。
- **FR-009**: 完整凭证 MUST NOT 出现在响应、错误、日志、指标、追踪、测试快照或异常信息中。
- **FR-010**: 暴露给调用方的错误类别 MUST 稳定，不依赖火山方舟原始错误文案。
- **FR-011**: 上游响应字段与契约不符时 MUST 失败关闭，不得猜测余额或权限。
- **FR-012**: 并发验证 MUST 具备全局与单凭证上限，避免触发上游滥用保护；超限时返回可重试的临时失败（非永久 `invalid`），且 MUST NOT 再发起会加剧上游压力的额外上游调用。
- **FR-012a**: V0.1 默认上限为：全局同时进行的验证 **32**、同一凭证同时进行的验证 **1**（同 Key 串行）。上限 MUST 可配置，但默认值与超限分类 MUST 有自动化测试锁定；调高配置不得取消上限本身。
- **FR-013**: 官方不提供额度查询、额度字段缺失、单位无法映射或无法建立可信额度读路径时，MUST 返回 `quota_unavailable`（失败关闭）；MUST NOT 将 `remaining_quota` 填为 0，MUST NOT 归类为 `zero_quota` 或 `success`。计划阶段 MUST 用当期官方文档确认是否存在可信额度源；若不存在，本功能仍按 `quota_unavailable` 交付，不得用占位零值绕过。

### 工程需求 *(必选)*

- **ER-001 — 契约**: 验证结果与错误分类须形成版本化内部契约；计划阶段必须根据当期火山方舟官方文档确认端点和字段，并用契约测试固定。错误类别至少覆盖：`success`、`invalid`、`forbidden`、`zero_quota`、`quota_unavailable`、`no_supported_models`、`rate_limited`、`temporary_unavailable`、`timeout`、`invalid_response`、`unsupported_platform`。`rate_limited` 结果 MUST 含 `retry_after_seconds`（秒，正整数）。
- **ER-002 — 安全与隐私**: 原始 Key 只在受控内存中短暂存在，使用后尽快释放；认证头和响应正文先脱敏再进入诊断路径。测试仅使用合成或专用测试凭证，不得把真实凭证写入夹具或仓库。内部 HTTP 的共享 `X-Internal-Token` **不得**作为公网唯一认证；路由默认关闭；启用时 MUST 仅暴露于回环或私网路径，非隔离环境 MUST 叠加服务身份（如 mTLS/网格）或保持禁用（宪章 II）。
- **ER-003 — 数据完整性**: 额度仅在可信官方源可读时使用整数基础单位或精确小数表示，必须携带单位和采集时间；不得使用二进制浮点表示价值或额度；不得用零值占位表示「未知」。
- **ER-004 — 性能与容量**: 单次验证硬截止 3 秒；并发默认全局 32、单凭证 1（可配置，见 FR-012a）；超限快速失败且不占用额外上游配额。
- **ER-005 — 可靠性**: 只对确认幂等且属于临时网络故障的读取进行有界重试；重试总时长不得突破 3 秒截止。
- **ER-006 — 可观测性**: 记录平台、结果类别、耗时、上游状态类别和请求标识；凭证仅可使用不可逆脱敏标识聚合。
- **ER-007 — 可访问性**: V0.1 无界面；错误分类和建议动作必须机器可读，便于未来界面区分「修正凭证」「补充额度」「更换/开通支持模型」和「稍后重试」（后者依赖 `retry_after_seconds`）。

### 失败与恢复场景 *(必选)*

1. **Given** 火山方舟超时或暂时性服务错误，**When** 验证运行，**Then** 3 秒内结束为临时失败，不创建永久无效状态，调用方可按策略稍后重试。
2. **Given** 调用方取消请求，**When** 上游仍在处理，**Then** 取消传播到网络调用并释放连接与敏感内存。
3. **Given** 适配契约升级导致字段无法解析，**When** 验证响应到达，**Then** 标记协议错误、触发告警信号并阻止该结果进入路由池。
4. **Given** 上游限流并返回建议重试时间，**When** 标准化结果，**Then** 分类为 `rate_limited` 且 `retry_after_seconds` 反映上游建议（受合理钳制），不得将凭证标为无效。
4a. **Given** 上游限流但无建议重试时间，**When** 标准化结果，**Then** `retry_after_seconds=5`（默认配置），字段不得为空。
5. **Given** 全局并发已达 32 或同一凭证已有 1 路验证进行中（默认配置），**When** 新验证到达，**Then** 以可重试临时失败拒绝，不发起额外上游调用。
6. **Given** 官方无额度接口或额度契约字段缺失，**When** 验证完成认证检查，**Then** 返回 `quota_unavailable`，`remaining_quota` 不为 0，且调用方不得据此写入零额度健康/接入状态。
7. **Given** 认证与额度均满足，但 V0.1 支持模型交集为空，**When** 标准化结果，**Then** 返回 `no_supported_models` 且 `availability=unavailable`，不得将凭证标为 `invalid`。

### 关键实体

- **Provider Credential Input（提供商凭证输入）**: 仅在一次验证期间存在的敏感输入；不得作为本功能持久实体。分类：高价值机密；不变量：用后即释、永不落盘（本功能范围内）。
- **Credential Validation Result（凭证验证结果）**: 单次验证的认证状态、可用性、精确额度（仅可信时）、单位、模型、采集时间、错误类别；`rate_limited` 时含 `retry_after_seconds`；可选脱敏遥测标识。分类：业务敏感；本功能不持久化；调用方（SF08/SF16）决定是否保存及如何与历史事实合并（FR-007a）。不变量：`quota_unavailable` 时不得携带伪造的零额度；结果不含跨请求状态。
- **Provider Error Classification（提供商错误分类）**: 稳定枚举：`success`、`invalid`、`forbidden`、`zero_quota`、`quota_unavailable`、`no_supported_models`、`rate_limited`、`temporary_unavailable`、`timeout`、`invalid_response`、`unsupported_platform`。不变量：分类不依赖上游原始文案；`zero_quota` 仅表示官方明确剩余为零；`quota_unavailable` 表示额度不可信/不可读；`no_supported_models` 表示有效但无 V0.1 可路由模型。

## 成功标准 *(必选)*

### 可度量结果

- **SC-001**: 契约/替身测试中，有效、认证失败、权限拒绝、限流、零额度、额度不可用、无支持模型、超时、暂时性上游错误和非法响应的分类准确率为 100%。
- **SC-001a**: 限流且上游无建议重试时间的样本中，100% 返回 `retry_after_seconds=5`（默认配置）；限流且上游有建议时，100% 返回反映该建议的正整数秒（允许文档化的上限钳制）。
- **SC-002**: 95% 正常验证在 3 秒内完成；所有请求均在 3 秒硬截止内结束或被取消。
- **SC-002a**: 在默认配置下，构造第 33 个全局并发验证与同一凭证第 2 个并发验证时，100% 被拒绝为可重试临时失败且上游调用次数不增加。
- **SC-003**: 当官方/替身提供可信额度时，有效凭证的额度与响应完全一致，不发生单位或精度丢失；无可信额度源时 100% 样本归为 `quota_unavailable` 且 `remaining_quota` 不为 0。
- **SC-004**: 在调用方合并契约的验收夹具中：连续「先 success 后 rate_limited/timeout/quota_unavailable/no_supported_models」时，持久层认证事实被写成永久 `invalid` 的次数为 0（本功能单测验证类别输出正确；合并行为由 SF08/SF16 夹具或契约测试覆盖）。
- **SC-005**: 日志、错误、追踪和测试输出扫描不出现任何完整火山方舟凭证。
- **SC-006**: 调用方取消后，验证侧不再持有该次调用的完整凭证明文，且无连接泄漏（可在受控测试中断言）。

## 范围

### 范围内

- 火山方舟凭证、余额、权限、模型验证及稳定错误分类
- 标准化验证结果字段与内部可调用验证能力
- 3 秒硬截止、取消传播、有界重试与并发上限
- 凭证脱敏与防泄漏（响应/日志/指标/追踪/测试）
- 供 SF08 接入决策与 SF16 健康事实更新消费的结果语义

### 范围外

- Key 持久化、加密与生命周期状态机（SF08 等）
- 代理转发与实际路由选择（网关/路由功能）
- 健康调度策略与周期探活编排（SF16）
- 多提供商平台适配（V0.1 仅火山方舟）
- 官方余额扣减、计费结算与买家侧计量
- 面向卖家的验证 UI 或自助控制台

## 假设

- 依赖 SF01 的网关工程基线；本功能不依赖账户或 Key 数据库表结构。
- 火山方舟官方接口细节属于易变外部契约，实施计划必须用当期官方文档复核端点与字段（含是否存在可信额度读路径）。
- SF08 使用本功能决定是否接入；SF16 使用本功能更新健康事实；二者负责结果的持久化与**状态合并**策略。若 SF06 返回 `quota_unavailable`，调用方不得当作零额度或成功接入/可路由。
- V0.1 仅支持火山方舟；其他平台统一 `unsupported_platform`。
- 「永久失败」指凭证本身不可恢复的认证/权限问题（`invalid`/`forbidden`）；临时类、`quota_unavailable`、`no_supported_models` 由调用方按 FR-007a 合并，不得据此将历史可信认证改写为无效。
- 模型能力范围限定为 V0.1 所需的 Chat Completions 兼容集合；未在该集合内的模型不标记为支持；交集为空时为 `no_supported_models`，由 SF08/SF16 拒绝接入或标为不可路由，而非永久吊销凭证。
- 工程草图中「无余额接口则返回零值」的实现方式被本规格明确否决。
- `success` 仅用于认证有效、额度可信且 > 0、且至少有一个 V0.1 支持模型的可接入/可路由结果。
- 并发默认全局 32 / 单凭证 1 可在运维配置中调整，但变更须保留「有上限 + 超限可测」不变量。
- 限流默认 `retry_after_seconds=5` 可配置；计划阶段可定义对异常大上游建议值的上限钳制（例如不超过 300 秒），但不得省略该字段。
