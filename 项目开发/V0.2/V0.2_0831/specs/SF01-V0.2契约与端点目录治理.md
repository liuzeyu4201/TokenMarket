# SF01 V0.2 契约与端点目录治理

**优先级：** P0　**依赖：** V0.1 契约基线

## 功能描述

建立 V0.2 所有跨服务契约及三厂商 Endpoint Catalog 的唯一事实源，使“厂商所有稳定数据面 API 全兼容”成为可枚举、可冻结、可测试的发布范围，而不是模糊承诺。目录由 Gateway、能力发现、路由、计量、文档和兼容测试共同消费。

## 功能要求

- 提供机器可读的版本化目录，字段遵循《API协议兼容基线》；生成的人类可读清单与机器目录来自同一数据源。
- 维护 Project、Provider Connection、route decision、usage、pricing、ledger、audit 的 HTTP/事件契约与兼容策略。
- 目录变更需要 schema 校验、评审记录、兼容影响和测试夹具；已发布版本只增补兼容字段，不原地改变含义。
- 明确 stable、preview/beta、control-plane、stateful、streaming、affinity 标签；未知端点和禁止端点返回统一平台错误。
- 所有消费者启动时校验支持的目录主版本；不兼容时失败关闭。

## 边界与异常

不自动抓取并上线厂商新 API；不纳入账号、组织、IAM、支付和厂商凭据管理控制面。厂商文档含糊时默认不进入 stable，保留评审证据后再决策。

## 验收标准

1. 三厂商冻结日稳定数据面端点 100% 被目录唯一记录，无重复 method/path/version。
2. schema 校验可拒绝缺少稳定性、状态性、传输、计量或测试夹具的记录。
3. stable、preview、control-plane 各至少一个自动测试证明允许/opt-in/拒绝行为。
4. Gateway、路由和兼容测试读取同一目录版本；人为制造主版本不兼容时服务拒绝启动。
5. 每条 stable 记录可追踪到官方文档、合同测试和负责 SF。
6. 目录生成物可重复生成，工作树无非确定性差异。

## 验收证据

目录文件与 schema、生成结果、官方来源快照、差异报告、消费者校验测试和发布冻结记录。
