# SF18 原生同协议透明代理核心

**优先级：** P0　**依赖：** SF01、SF02、SF03、SF11、SF12、SF14

## 功能描述

建立三厂商共用但不互相转换的透明代理内核。平台只替换 upstream 鉴权和目标地址，执行授权、路由、安全、计量所需的最小处理，并最大限度保留原生 HTTP/流语义。

## 功能要求

- 按 host/path/version 确定协议和目录端点，使用原始 method、query、body、内容类型和可透传 headers。
- 请求体采用流式或保留未知字段的处理方式；本地结构解析不能删除合法扩展。
- upstream 状态码、响应体、SSE/WebSocket 事件和安全允许的 headers 原样返回。
- 平台拒绝使用稳定、机器可识别错误 envelope，并与 upstream 原生错误明确区分。
- 执行请求大小、响应大小、超时、空闲超时和取消传播；客户端断开应取消可取消 upstream 请求。

## 边界与异常

严禁 OpenAI↔Anthropic↔Vertex 字段、工具或错误转换。安全要求可移除 hop-by-hop、credential、cookie 和内部网络 headers，但须列入契约。

## 验收标准

1. 三协议 golden fixture 对请求/响应字节或语义等价比较 100% 通过。
2. 未知合法 JSON 字段、multipart 元数据和 query 参数不会被静默删除。
3. upstream 4xx/5xx、429、超时、断连分别保留原生错误并附平台关联 ID。
4. 平台拒绝可由错误 code 明确识别，且不伪装为厂商错误。
5. 客户端取消在 1 秒内传播到 upstream（无法取消的端点除外并记录）。
6. 自动测试证明不存在跨协议路由或转换代码路径。

## 验收证据

golden fixture、header allow/deny 清单、取消测试、错误矩阵和协议隔离测试。
