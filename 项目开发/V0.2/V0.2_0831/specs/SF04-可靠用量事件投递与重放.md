# SF04 可靠用量事件投递与重放

**优先级：** P0　**依赖：** SF01、SF02、SF03

## 功能描述

确保每个进入可计量阶段的代理请求都产生可持久化、可幂等消费、可重放的用量事实，为同步/异步结算、对账和审计提供完整输入。

## 功能要求

- Gateway 与请求结果事实采用事务性 Outbox 或等价机制；禁止仅写进程内队列。
- 事件包含全局 event ID、request ID、Project、Connection、route/price/catalog version、协议、端点、状态和证据摘要。
- 消费者按 event ID 幂等，失败指数退避；超过阈值进入可观测死信并可审计重放。
- 保证同一 request 的生命周期事件有确定序号；跨 request 不要求全局顺序。
- 原始敏感内容不得进入事件；需要争议处理的证据采用脱敏摘要或加密引用。

## 边界与异常

投递为至少一次，业务结果必须通过幂等实现“效果一次”。队列不可用时不能悄悄丢事件；超过安全缓冲阈值时数据面按策略限流或失败关闭。

## 验收标准

1. 成功、upstream 4xx/5xx、超时、客户端中断各产生规定生命周期事件。
2. 同一批事件重复投递 10 次，账务和统计结果与投递 1 次一致。
3. Gateway 在响应前后不同故障点被杀死，最终不存在已结算请求无用量事实。
4. 队列停机 15 分钟后恢复，积压全部投递且顺序约束满足。
5. 死信可按权限查看原因、修复后重放并形成审计记录。
6. 事件 schema 兼容测试覆盖旧生产者/新消费者与新生产者/旧消费者允许组合。

## 验收证据

故障点矩阵、重复投递测试、积压恢复曲线、死信重放记录和 schema 兼容报告。
