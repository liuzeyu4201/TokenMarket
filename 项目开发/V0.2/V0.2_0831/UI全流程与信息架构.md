# V0.2 UI 全流程与信息架构

## 1. 产品入口

公开站点包含产品说明、协议能力、工作方式、安全与状态说明、注册/登录入口。不得展示可购买、充值、提现或法币等价的文案；V0.2 统一使用“测试额度”。

登录后采用统一应用壳，导航至少包含总览、Projects、代理 Key、用量与账单、连接供给、通知和账户安全。用户角色为买家、卖家或两者兼有；双角色用户通过明确的工作区切换进入买家或卖家视角。

## 2. 关键流程

### 注册与登录

手机号 → 发送验证码 → 验证。已有账号直接登录；新账号继续填写昵称和角色后自动登录。验证码发送与验证阶段对“账号是否存在”使用不可枚举响应。

### 买家流程

创建 Project → 选择共享或专享（创建后不可更改）→ 启用协议 → 配置 Provider Binding → 创建受限代理 Key → 获得原生 SDK 示例 → 发起测试 → 查看路由、用量、测试额度和账本结果。

### 卖家流程

创建 Provider Connection → 选择厂商与鉴权方式 → 安全提交凭据 → 验证与能力发现 → 选择共享或专享供给 → 在平台价格范围内报价 → 上架 → 查看健康、容量、调用和测试收益。

### 管理员流程

独立管理员登录 → 按 RBAC 进入运营域 → 管理用户/会话、连接、Project、价格版本、路由版本、专享更换、未决账务、冲正、告警和审计。高风险操作必须二次认证、填写原因并保留前后值。

## 3. 隔离与状态

- 工作区切换必须同时改变导航、默认查询范围和操作授权，不只替换视觉标签。
- 买家视图不得泄露卖家凭据或内部成本；卖家视图不得看到买家身份和请求内容。
- 管理员站点与普通用户站点使用独立身份域和路由前缀。
- 所有异步操作显示 pending/succeeded/failed/unresolved，不以“成功 toast”掩盖后台失败。
- 空状态、加载、局部失败、无权限、限流和可恢复错误均有明确动作。

## 4. 设计与可访问性

统一使用设计 token、表单、表格、状态标签、确认弹窗和错误模式。桌面与移动端关键流程可用；键盘可操作、焦点可见、语义标签完整、颜色对比和错误提示满足 WCAG 2.2 AA。危险操作不能仅靠颜色区分。

## 5. UI 验收证据

每条流程需有设计稿或实现截图、浏览器 E2E、权限负向用例、移动视口结果和自动/人工可访问性记录。关键链路至少覆盖 Chrome、Safari、Edge 当前稳定版；不存在阻断操作的控制台错误或未处理 Promise。
