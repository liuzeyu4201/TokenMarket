# TokenMarket V0.2_0831 实现总纲

> **版本定位**：可公开上线的交易沙盒产品
> **创建日期**：2026-08-31
> **状态**：需求基线
> **继承版本**：V0.1 技术验证版

## 1. 版本目标

V0.2 将 V0.1 的单平台 Chat Completions 技术链路升级为可供真实买家、卖家和运营
人员完整使用的平台。核心目标不是接入真实资金，而是验证以下产品与技术假设：

1. 买家能以 Project 为边界，在不改写厂商协议的情况下使用 OpenAI、Anthropic 和
   Google Vertex 的模型数据面 API。
2. 卖家能安全接入上游资源、受限报价，并通过共享池或专享绑定提供能力。
3. 平台能根据健康、延迟、容量和价格稳定分配共享请求，同时保持专享资源隔离。
4. 平台能从上游原始计费证据或 token 用量生成可复算、可对账的交易沙盒账本。
5. 完整 Web 流程、运营后台、可观测性、容量、安全和灾备达到公开上线标准。

| 角色 | 主要目标 | V0.2 核心能力 |

## 3. 端到端用户旅程

### 3.1 注册与登录

1. 访客输入手机号并获取验证码。
2. 验证前的响应不得暴露手机号是否已注册。
3. 验证成功后，已有账户直接登录；新用户填写昵称和角色后创建账户并自动登录。
4. 新登录原子撤销旧 Web 会话，每个账户最终只有一个有效会话。

### 3.2 买家共享 Project

1. 买家创建共享型 Project，启用一个或多个原生协议。
2. 买家创建代理 Key，并限制协议、模型、IP、测试额度和有效期。
3. 买家按厂商原生路径提交无状态请求。
4. 平台先执行硬性资格过滤，再按综合评分选择 Provider Connection。
5. 请求与响应同协议透传，用量进入沙盒账本并在买家工作区展示。

### 3.3 买家专享 Project

1. 买家创建专享型 Project 并选择协议。
2. 每个协议获得一个与其他买家隔离的 Provider Connection。
3. 买家可调用发布基线内全部稳定模型数据面端点，包括状态型资源。
4. 连接故障时 Project 进入降级状态，不自动切换到其他连接或共享池。
5. 买家确认更换后，新连接生效；平台明确提示旧文件、批任务、微调等资源不迁移。

### 3.4 卖家供给

1. 卖家创建 Provider Connection，提交厂商、认证材料、项目/区域和用途声明。
2. 系统验证凭据与能力并加密保存，原文只在提交时出现一次。
3. 卖家选择共享或专享模式；同一连接同一时间只能属于一种模式。
4. 卖家在平台允许区间内设置结算倍率。
5. 卖家查看健康、容量、请求统计和测试收益，但不能查看买家请求或响应内容。

### 3.5 运营与发布

1. 管理员审核连接、管理账户状态、价格范围、路由权重和专享绑定。
2. 管理员查看账本和对账差异；修正只能通过冲正与补记，不能改写原账目。
3. 系统持续监控容量、错误、延迟、结算积压和安全事件。
4. 发布负责人只有在全部发布门禁和独立渗透测试通过后才能公开上线。

## 4. 全局功能范围

### 4.1 范围内

- OpenAI、Anthropic、Google Vertex 原生同协议数据面透传。
- HTTP、SSE、WebSocket、multipart、二进制文件和异步任务等必要传输形式。
- 工具/函数调用、并行工具调用、结构化输出、推理/思考、缓存、多模态内容等
  厂商原生字段，按端点能力原样保留。
- Project、Provider Binding、代理 Key、共享池、专享绑定、综合评分路由。
- Provider Connection 加密接入、验证、健康、容量、模式和受限报价。
- 上游花费优先、token 费率回退、测试额度、预留、结算、对账和冲正。
- 公共站点、统一认证、买家工作区、卖家工作区、账户设置和独立管理后台。
- 500 RPS、500 并发长连接、水平扩展、故障隔离、SLO、备份恢复和发布回滚。
- 单元、契约、集成、E2E、白盒、黑盒、安全、性能、压力、耐久、故障注入、
  浏览器兼容和可访问性验收。

### 4.2 明确排除

- 任何跨协议格式转换或“统一请求格式”。
- 厂商账号、组织、IAM、支付、账单管理和上游 API Key 管理控制面。
- 未进入版本化端点目录的未知未来 API 自动开放。
- 真实充值、支付渠道、法币余额、1:1 人民币积分、Escrow、提现、发票和税务。
- 卖家自由绝对定价、买家逐请求挑选卖家、公开卖家身份市场。
- 专享连接的自动故障转移或上游状态型资源迁移。
- 企业组织、团队成员、子账户、SSO、原生移动应用和多语言国际化。
- 将 new-api 作为 TokenMarket 核心买家分配层；可参考其协议覆盖，但不引入其
  用户、渠道、额度和路由控制面。

## 5. 核心业务规则

### 5.1 Project

- 一个 Project 只能是 `shared` 或 `dedicated`，创建后不可原地切换。
- 一个 Project 可以启用多个协议；每个协议形成独立 Provider Binding。
- 共享 Project 只允许端点目录中标记为无状态的端点。
- 专享 Project 每个协议必须绑定一个独占 Provider Connection。

### 5.2 路由

- 先排除协议、端点、模型、状态、所有权、额度和容量不合格连接。
- 只有合格连接才进入健康、延迟、剩余容量、价格的综合评分。
- 权重、归一化和并列规则版本化；每次选择可追踪、可解释、可回放。
- 任何买家请求不得选中同一账户拥有的卖家连接。

### 5.3 计价与账本

- 上游响应明确提供货币花费时，以该金额为主要基础费用。
- 上游未提供货币金额但提供 token 用量时，按版本化费率计算。
- 非 token API 又无明确金额时进入 `unresolved`，不得记零或强制折算 token。
- 买家扣减、卖家收益和平台价差均使用精确最小单位；原账目不可修改或删除。

## 6. 非功能目标

| 维度 | 目标 |
|------|------|
| 非流式吞吐 | 500 RPS 持续 30 分钟；1,000 RPS 突发 5 分钟 |
| 长连接 | 500 条 SSE/WebSocket 并发连接持续 2 小时 |
| 身份规模 | 压测中至少 500 个不同买家身份同时活跃 |
| 数据面可用性 | 月度 ≥99.9%，平台原因单独核算 |
| 管理面可用性 | 管理 API 与 UI 月度 ≥99.5% |
| 灾备 | RPO ≤5 分钟，RTO ≤30 分钟 |
| 数据完整性 | 已接受请求的账本丢失和重复结算均为 0 |
| 协议完整性 | 发布基线稳定数据面端点兼容矩阵通过率 100% |
| 可访问性 | 关键 Web 流程满足 WCAG 2.2 AA |
| 安全 | 公开上线前 Critical/High 清零并通过独立渗透复测 |

## 7. 版本完成定义

V0.2 只有同时满足以下条件才可标记完成：

1. [功能清单与依赖矩阵](./功能清单与依赖矩阵.md)中的全部 P0 SF 完成且无替代占位。
2. 三家厂商稳定数据面端点目录冻结，契约、模拟上游和真实冒烟证据完整。
3. 注册登录、买家、卖家和管理员关键 E2E 全部通过。
4. 500 RPS、突发、长连接和恢复演练达到阈值。
5. 账本对账证明丢失、重复结算和不可解释差异为 0。
6. 独立渗透测试完成，Critical/High 为 0；Medium 按规则处置。
7. 生产部署、监控、告警、备份、恢复、回滚和责任人运行手册齐备。
8. 所有验收证据指向不可变构建版本和提交 SHA，可由另一名负责人复现。
