# V0.1_0712 子 Spec 索引

本目录将 `V0.1_0712_独立功能描述.md` 中的 19 个独立功能拆分为可分别规划、实现和验收的详细 Spec。每个文件只包含一个主要交付目标，不把依赖功能并入自身范围。

质量验证结果见 [requirements-checklist.md](./requirements-checklist.md)。

## 文档优先级

当来源文档冲突时，按以下顺序解释：

1. `.specify/memory/constitution.md`：安全、数据、架构、测试与交付的最高约束。
2. `项目开发/产品迭代路线图.md` 的 V0.1 范围：决定本期做与不做。
3. `V0.1_0712_功能开发Spec.md`：决定本期功能、边界和原始验收目标。
4. `项目开发/产品需求文档（PRD）.md`：补充用户价值、角色和长期产品语境。
5. `项目开发/1-项目架构与目录结构.md` 至 `4-前端与DevOps监控规范.md`：补充服务职责、契约、数据、并发、测试、部署和监控要求。

低优先级文档不得削弱高优先级约束。通用规范中属于 V0.2 及以后版本的计费、资金、Kafka 计量链路、前端页面、多平台和智能加权路由，不进入 V0.1。

## 已统一的冲突决策

| 主题 | 冲突 | V0.1 采用规则 |
|------|------|---------------|
| 敏感凭证 | 周度 Spec 曾写明文存储；宪章、路线图和 PRD 要求加密 | 卖家原始 Key 使用认证加密，密钥材料外部注入并版本化；日志、错误、测试数据不得出现完整凭证 |
| 登录 | 周度 Spec 曾允许仅凭手机号登录；宪章要求可靠认证 | 登录前必须验证手机号所有权；本地/测试可用合成验证码，但不可绕过验证步骤 |
| 用户角色 | 原文同时存在 `both` 和“不可同时买卖” | 允许 `buyer`、`seller`、`both`，但任何买家请求都排除同一账户拥有的卖家 Key；如产品改为角色互斥，应修改 SF03、SF05 和 SF13 |
| 代理 Key 映射 | F09 固定绑定单条原始 Key；F06 要求轮询 Key 池 | 代理 Key 绑定买家和平台，每次请求由 SF13 从可用池动态选择卖家 Key |
| 限流恢复 | F05 为 30 秒；F07 为 30 分钟 | 请求级 429 冷却 30 秒；健康检查级 429 暂停主动探测 30 分钟 |
| 健康检查周期 | 路线图为每分钟；周度 Spec 为 30 秒 | 采用更具体、更新的周度 Spec：每 30 秒一次 |
| API 响应 | 项目统一响应包络与 OpenAI-compatible 原样响应冲突 | 管理/业务接口使用统一包络；成功的代理响应和已开始的 SSE 流保持 OpenAI-compatible；代理前置失败使用统一错误结构 |
| 数据删除 | 全表软删除与敏感 Key 撤销后清除冲突 | 业务元数据软删除并保留审计；敏感密文执行加密擦除或不可恢复删除，不保留可解密副本 |

## 全局 V0.1 范围

- 仅支持火山方舟 Chat Completions；其他平台、Embeddings 和高级模型能力不在本期。
- 只提供 API 和开发/运维能力，不提供买家、卖家或管理员前端页面。
- 只采集与持久化 Token 用量，不计算价格、不扣余额、不生成账单、不处理资金或积分。
- 不引入 Kafka 作为 V0.1 的强制依赖；需要可靠异步持久化的能力必须定义可恢复的本地持久化或事务性机制。
- 所有修改操作都必须定义幂等键、并发行为和审计字段。
- 代理网关是代理流量唯一入口；用户和 Key 管理属于 API 领域服务；PostgreSQL 是持久事实源，Redis 只能保存可重建状态。
- 对外 HTTP 契约必须版本化并纳入 OpenAPI 或兼容契约测试；跨服务传递请求标识。
- 所有相关 Go、Python 领域包要求至少 80% 行覆盖，并直接覆盖授权、凭证、幂等、并发、迁移与恢复的负面分支。
