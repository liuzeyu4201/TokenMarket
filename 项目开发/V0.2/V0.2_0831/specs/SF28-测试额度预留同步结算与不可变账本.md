# SF28 测试额度预留、同步结算与不可变账本

**优先级：** P0　**依赖：** SF04、SF12、SF26、SF27

## 功能描述

在请求前原子预留测试额度，并对请求结束时已知成本同步结算；使用不可变复式或平衡分录表达买家扣减、卖家收益、平台价差、释放和冲正。

## 功能要求

- reservation 使用 request/idempotency key 唯一约束；同时检查 Project、Key 和账户可用测试额度。
- 成功响应若已有可信成本，在同一结算事务中消费 reservation、写入平衡分录并释放余量。
- 账本分录只追加，包含账户、方向、金额、单位、request、价格版本和证据引用。
- 在线余额是可验证投影；投影失败可从分录重建，不能直接 UPDATE 修正。
- 请求被平台拒绝或确认未产生 upstream 成本时释放 reservation。

## 边界与异常

测试额度不可购买、转移、兑换和提现。upstream 是否收费不确定时不能盲目释放，转入未决处理。

## 验收标准

1. 100 个并发请求竞争最后额度时，accepted reservations 总额不超过可用额。
2. 同一 idempotency/request 重试 10 次只产生一组业务效果。
3. 每个已结算事务借贷/来源去向平衡，buyer debit = seller earning + spread。
4. 任意时点余额从全量分录重建与在线投影精确一致。
5. 进程在预留、调用、结算各故障点退出后恢复，不重复扣费且状态可终结。
6. 数据库约束阻止修改/删除已发布分录，冲正只能新增相反分录。

## 验收证据

并发额度测试、幂等测试、平衡校验、投影重建、故障点注入和数据库权限测试。
