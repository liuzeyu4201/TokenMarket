# 功能规格：用户注册与初始界面

**功能分支**: `003-user-registration-ui`

**创建日期**: 2026-07-23

**状态**: 草案

**输入**: 用户描述："开启新分支，功能描述在 `项目开发/V0.1/V0.1_0712/specs/SF03-用户注册.md`，不仅如此还应该开始搭建 UI 界面"

**源规格**: `项目开发/V0.1/V0.1_0712/specs/SF03-用户注册.md`（SF03）；本规格在 SF03 账户注册能力上扩展 V0.1 首批可访问界面骨架与注册页。

## 目标与价值

为 TokenMarket 新用户提供可提交的最少必要账户注册能力，并提供可访问的注册界面与应用壳层，使访客能从空白脚手架进入“看到页面 → 填写信息 → 完成注册或得到明确失败反馈”的完整旅程。成功注册建立后续身份认证、角色授权和 Key 所有权的可信账户基础。

V0.1 本功能只采集手机号、昵称和角色；不包含实名认证、密码、个人资料编辑、角色变更、短信验证码或登录令牌签发。

## 澄清

### 会话 2026-07-23

- Q: 应用默认入口（根路径）应展示什么？ → A: 根路径为通用壳层/首页占位；注册仅通过导航或显式链接进入（非默认主推落地）。
- Q: 已软删除账户的手机号再次注册应如何响应？ → A: 返回专用错误（账户不可用/需恢复），仍不创建新账户；不与普通“已占用”混用同一对外语义。
- Q: 注册接口是否必须提供可验收的防滥用限流？ → A: 必须；超限拒绝且结果可机读，范围写入需求与成功标准（不延后到纯运维或仅指标）。
- Q: 手机号合法输入与规范化范围是什么？ → A: 仅中国大陆 11 位手机号；接受空格、+86/86 前缀、全角数字等噪声并规范为 11 位数字串；非大陆号一律格式错误。
- Q: 注册幂等键保留多久？ → A: 自首次受理起 24 小时内可安全重放；超过窗口后键失效，客户端须使用新键，不再返回首次业务结果。

## 用户场景与测试 *(必选)*

### 用户故事 1 - 通过界面完成首次注册 (优先级: P1)

作为新访客，我希望打开应用后找到注册入口，填写手机号、昵称和角色并提交，以便在平台上建立唯一账户并看到注册成功确认。

**优先级理由**: 没有可访问的注册路径，仅有后端接口无法对真实用户交付价值；这是身份能力与界面能力的交汇点。

**独立测试**: 在未登录状态下打开应用，进入注册页，使用未占用的合法手机号、合法昵称和支持的角色提交；验证界面显示成功结果，且系统中仅存在一条对应账户记录。

**验收场景**:

1. **Given** 访客打开应用根路径，**When** 页面渲染完成，**Then** 看到通用壳层/首页占位（非注册表单本身），且可通过主导航或显式链接进入注册页。
2. **Given** 手机号未注册且输入合法，**When** 用户在注册页提交手机号、昵称和支持的角色，**Then** 系统创建 active 账户，界面展示成功确认（含用户标识与所选角色，不展示完整手机号明文）。
3. **Given** 用户选择 `buyer`、`seller` 或 `both`，**When** 注册成功，**Then** 账户准确保存所选角色，供后续授权使用。
4. **Given** 注册成功，**When** 查询持久记录，**Then** 标识为 UUID，且审计时间、状态、软删除标记和并发版本完整。

---

### 用户故事 2 - 安全处理重复与非法注册 (优先级: P1)

作为平台，我希望重复、并发和非法请求不会产生重复账户或泄露已有账户信息；作为用户，我希望表单与服务错误以可读方式展示，且不暴露他人隐私。

**优先级理由**: 账户唯一性与隐私是安全基线；错误反馈质量决定首访转化与支持成本。

**独立测试**: 对同一手机号并发提交多次相同与不同幂等键的请求；再通过界面提交非法字段与已占用手机号；验证最多创建一条账户，且界面错误不披露已有账户昵称、角色或状态。

**验收场景**:

1. **Given** 同一幂等键已经创建账户，**When** 原请求被重放，**Then** 返回与首次一致的结果且不新增记录。
2. **Given** 手机号已经被**活跃**账户占用，**When** 使用新幂等键再次注册（接口或界面），**Then** 返回资源冲突，不披露账户昵称、角色或状态；界面显示中性冲突提示。
3. **Given** 手机号仅被**已软删除**账户持有，**When** 用户再次提交注册，**Then** 返回专用“账户不可用/需恢复”类错误且不创建新账户；文案不得暴露原昵称、角色或完整手机号；界面展示可区分于普通占用冲突的提示（可引导联系支持或后续恢复流程，但不在本功能内完成恢复）。
4. **Given** 手机号、昵称或角色不合法，**When** 提交注册，**Then** 返回字段级校验结果且不写入任何账户数据；界面在对应字段旁展示可理解错误。
5. **Given** 用户正在提交，**When** 请求尚未返回，**Then** 提交控件处于忙碌态，防止重复无意义连点造成额外冲突噪音。
6. **Given** 同一来源在时间窗内已达到注册尝试上限，**When** 再次提交注册，**Then** 返回可机读的限流/稍后重试结果，不创建账户；界面展示中性限流提示（可含请求标识），不泄露限流维度的内部细节。

### 用户故事 3 - 初始应用界面骨架可导航 (优先级: P2)

作为访客或开发验收人员，我希望应用具备基础壳层（入口布局、主路由、注册页与未实现页的明确占位），以便后续登录与业务页可在同一导航结构上扩展，而不是停留在“Developer scaffold”单页。

**优先级理由**: 用户明确要求开始搭建 UI；骨架降低后续功能页的集成成本，并让注册成为可演示的端到端切片。

**独立测试**: 启动前端应用后，验证根路径为通用壳层/首页占位且可通过导航进入注册页；访问未实现业务路径时显示友好占位或 404，而非空白崩溃；键盘可完成注册表单主要操作。

**验收场景**:

1. **Given** 应用已启动，**When** 访问根路径，**Then** 渲染通用壳层/首页占位（不是注册表单），并提供可见的注册导航或链接。
2. **Given** 用户通过导航或显式路径进入注册页，**When** 页面渲染完成，**Then** 注册页包含手机号、昵称、角色三个必填输入与提交动作。
3. **Given** 用户访问尚未实现的业务页面路径，**When** 路由解析完成，**Then** 显示明确的“暂未开放/未找到”信息，并提供返回入口或注册入口链接。
4. **Given** 仅使用键盘，**When** 用户完成注册表单填写与提交，**Then** 焦点顺序合理，字段标签与错误信息可被辅助技术关联（语义化表单）。

### 边界情况

- 手机号包含空格、`+86`/`86` 前缀、全角数字等噪声但指向同一大陆号码时，规范化后视为同一号并共享唯一性。
- 非大陆号码、错误位数、或无法清洗为 `1[3-9]` 开头的 11 位号时，仅格式错误、不触发占用/软删语义。
- 昵称仅含空白、超长、包含控制字符或可能污染日志的换行。
- 两个请求在唯一性检查后同时尝试写入同一手机号。
- 幂等键相同但请求体不同。
- 已软删除账户的手机号再次注册：必须失败且为专用错误语义，不得静默重建，也不得与普通占用冲突共用同一业务结果语义。
- 数据库提交成功但响应在到达客户端前中断；客户端以同一幂等键重试。
- 注册请求超时或服务暂时不可用时，界面展示可重试提示且不声称成功。
- 用户在成功页刷新或后退再提交时，不产生重复账户（幂等或冲突保护）。
- 幂等键超过 24 小时后重放：不再返回首次结果，须换新键；唯一性仍防止重复账户。
- 极窄视口下注册表单仍可完整操作（无需横滑才能看到提交按钮）。
- 短时间内对同一 IP 或同一规范化手机号的大量注册尝试触发限流后，后续请求均失败且无新增账户。
- 限流窗口滑动/重置后，合法请求应可再次被正常受理（在唯一性等其他规则仍满足时）。

## 需求 *(必选)*

### 功能需求

- **FR-001**: 注册请求 MUST 接收手机号、昵称、角色和幂等键；不得接收由客户端指定的用户 ID 或账户状态。
- **FR-002**: 手机号 MUST 先规范化再进行格式和唯一性校验；规范化规则必须形成可测试契约。
- **FR-002a**: V0.1 合法手机号范围 **仅中国大陆移动号码**：规范化结果 MUST 为 11 位数字且匹配 `1[3-9]\d{9}`。
- **FR-002b**: 规范化 MUST 至少处理：首尾与中间空白、全角数字转半角、可选国家码前缀 `+86` / `86`（前缀去除后余下部分再校验）；规范化失败或结果非大陆 11 位号时 MUST 返回字段级格式错误且不查重写库。
- **FR-002c**: 非中国大陆号码（其他国家码或无法规范为上述 11 位形式）MUST 拒绝为格式错误；唯一性比较 MUST 仅基于规范化后的 11 位串。
- **FR-003**: 角色 MUST 仅允许 `buyer`、`seller`、`both`，其他值返回参数错误。
- **FR-004**: 昵称 MUST 去除首尾空白，长度为 1–50 个可显示字符，不允许控制字符。
- **FR-005**: 成功注册 MUST 生成 UUID 用户标识并保存 active 状态、创建时间、更新时间、软删除标记和并发版本。
- **FR-006**: 同一规范化手机号在所有可恢复账户（含 active 与已软删除）中 MUST 唯一；软删除账户不得通过普通注册被静默替换或新建覆盖。
- **FR-006a**: 当规范化手机号仅匹配已软删除账户时，注册 MUST 拒绝创建，并返回可机读的**专用业务错误**（账户不可用/需恢复），其业务码与文案语义 MUST 区别于“活跃账户占用”的资源冲突；响应 MUST NOT 泄露原账户昵称、角色、状态细节或完整手机号。
- **FR-007**: 在幂等有效期内，相同幂等键和相同请求重放 MUST 返回首次结果；相同幂等键配不同请求体 MUST 返回冲突。
- **FR-007a**: 注册幂等键自该键**首次成功受理**（含创建成功或在写路径上已建立幂等记录的确定业务结果）起保留 **24 小时**；窗口内适用 FR-007。超过 24 小时后该键 MUST 视为失效：不得再返回首次业务结果，客户端 MUST 使用新幂等键；对失效键的重放 MUST 返回可机读的过期/请换新键类错误（或等价明确失败），且不得误创建重复账户（唯一性约束仍兜底）。
- **FR-008**: 并发注册同一手机号 MUST 最多成功一次，其余请求返回确定的冲突结果。
- **FR-009**: 成功与失败的注册业务响应 MUST 使用版本化业务接口统一包络，包含业务码、消息、数据载荷、请求标识和时间戳，供客户端可靠解析。
- **FR-010**: 注册 MUST NOT 签发访问令牌或建立已登录会话；会话签发属于后续登录功能。
- **FR-011**: 注册结果和审计日志 MUST NOT 回显完整手机号；面向用户的必要回显应脱敏。
- **FR-012**: 应用 MUST 提供可导航的注册页面，包含手机号、昵称、角色输入与提交；角色选项与后端允许值一致。
- **FR-013**: 注册页 MUST 在客户端先做基础必填与明显格式提示，但仍以服务端校验为最终权威；字段级错误须映射到对应输入。
- **FR-014**: 注册成功后界面 MUST 展示成功确认（用户标识、角色、创建完成语义），并明确提示“尚未登录、需后续验证登录”，不得暗示已获得访问权限。
- **FR-015**: 应用 MUST 提供最小界面骨架：根路径为通用壳层/首页占位（不得默认渲染完整注册表单）、全局可发现的注册导航或链接、通往注册页的稳定路径、以及未实现路由的友好占位/未找到页。
- **FR-016**: 每次注册提交 MUST 使用客户端生成的幂等键；同一用户操作的安全重试在 24 小时窗口内复用同一键，新的独立提交或键已过期后 MUST 使用新键。
- **FR-016a**: 注册页 HTTP 客户端 MUST 对单次注册请求设置有界超时（默认 **10 秒**）；MUST NOT 对注册 POST 做自动重试。超时或网络失败时界面 MUST 显示失败（不得显示成功），并允许用户手动重试；手动重试在键未过期前 MUST 复用同一幂等键。
- **FR-017**: 界面与接口错误文案 MUST NOT 泄露其他账户的昵称、角色、状态或是否精确匹配到某内部记录细节以外的信息；占用冲突使用中性表述。
- **FR-018**: 系统 MUST 对注册尝试实施可配置但默认可验收的防滥用限流，至少同时覆盖：**来源 IP** 与 **规范化手机号** 两个维度；任一维度超限即拒绝本次注册且不写入账户。
- **FR-019**: 默认限流阈值（可在受控配置中调整，但验收以默认为准）：同一来源 IP 每 15 分钟最多 **20** 次注册尝试；同一规范化手机号每 15 分钟最多 **5** 次注册尝试。尝试计数包含校验失败与业务拒绝（占用、软删不可用、参数错误），不仅计成功创建。
- **FR-020**: 限流拒绝 MUST 返回可机读的限流/稍后重试结果（与校验错误、占用冲突、软删不可用语义区分），MUST NOT 创建或修改账户；界面 MUST 展示中性限流提示并可关联请求标识。
- **FR-020a**: 限流不得成为账户枚举旁路：**来源 IP** 维度对每次注册尝试计数（含校验失败）；**规范化手机号** 维度仅在手机号规范化成功后计数。限流响应 MUST 统一为 `RATE_LIMITED` 中性语义与稳定包络形状，MUST NOT 因目标号是否已注册、是否软删而改变业务码、HTTP 状态或可区分文案。

### 工程需求 *(必选)*

- **ER-001 — Contracts**: 注册契约须进入版本化、可机读的 HTTP 契约；活跃手机号重复映射资源冲突；软删除手机号再注册映射专用“不可用/需恢复”错误；非法字段映射请求校验错误；响应保持全局错误码规则；前端消费的类型与契约字段一致，并能区分占用冲突与软删不可用两类失败。
- **ER-002 — Security & Privacy**: 手机号属于个人数据；日志、错误、指标、测试夹具与界面展示必须脱敏或使用合成号码；服务端拒绝客户端伪造角色外的权限字段；界面不得在 URL 查询串中传递完整手机号或幂等敏感载荷；注册路径必须具备 FR-018–FR-020a 的限流，且限流响应不得通过码、状态或文案差异泄露号是否已注册/软删。
- **ER-003 — Data Integrity**: 关系型数据库是账户事实源；规范化手机号唯一约束和幂等约束必须由持久层兜底，写入在单一短事务中完成。
- **ER-004 — Performance & Capacity**: 在正常本地集成环境下，95% 注册请求应在 500 毫秒内完成（不含外部短信验证）；注册首屏在常规开发机本地预览下应在 3 秒内可交互。**首屏 3s 以手工/quickstart 验收为准**，不作为 flaky CI 硬门禁；API p95 由自动化测试或可跳过环境的微基准覆盖。
- **ER-005 — Reliability**: 仅数据库提交成功才返回成功；客户端重试通过幂等键恢复，不对非幂等写入自动重试；界面在不确定结果时不得显示成功。
- **ER-006 — Observability**: 记录请求标识、结果码、耗时和脱敏用户标识；手机号冲突率和注册失败率可计量；界面错误态可展示或复制请求标识以便排障。
- **ER-006a — Alerts & runbook**: 注册路径 MUST 提供可部署的 Prometheus 告警规则（至少覆盖：注册 5xx/服务不可用率异常、限流后端不可用、异常升高的失败率），明确 severity、owner（API Service）、检测信号与 runbook 处置步骤；告警与日志 MUST 保持脱敏，不得包含完整手机号。
- **ER-007 — Accessibility**: 注册表单控件具备可见标签、错误与字段的程序化关联、可用键盘完成主流程；主要操作对比度满足常规可读性；目标为桌面与移动浏览器基本可用，不要求完整无障碍认证级合规。

### 失败与恢复场景 *(必选)*

1. **Given** 数据库在提交前不可用，**When** 用户注册，**Then** 返回可重试的服务错误且不存在部分账户记录；界面提示稍后重试并保留用户已填非敏感字段（昵称、角色；手机号可保留于表单控件内但不写入本地长期存储）。
2. **Given** 两个并发请求注册同一手机号，**When** 唯一约束发生竞争，**Then** 一个成功、其余冲突，且没有未处理异常泄露。
3. **Given** 数据库已提交但客户端未收到响应，且距首次受理未满 24 小时，**When** 客户端以同一幂等键重试，**Then** 获得原用户标识而不是创建新账户。
3a. **Given** 距首次受理已超过 24 小时，**When** 客户端仍使用旧幂等键重试，**Then** 返回键过期/请换新键类失败，不返回首次成功包络；若手机号已占用则仍受唯一性约束，不产生第二账户。
4. **Given** 前端无法解析业务响应或网络中断，**When** 用户停留在注册页，**Then** 显示通用失败提示与可选请求标识，不清除全部输入，不声称账户已创建。
5. **Given** 注册尝试已触发限流，**When** 用户在窗口内继续提交，**Then** 持续返回限流结果且账户数不增加；窗口恢复后合法请求可再被受理。

### 关键实体

- **User（用户账户）**: 账户事实；关键属性为用户标识、规范化手机号（大陆 11 位）、昵称、角色、状态、审计时间、软删除标记和版本。手机号为个人数据，由 API 用户域拥有。不变量：可恢复账户（含软删）中规范化手机号唯一；角色 ∈ {buyer, seller, both}；新建默认为 active；软删后再注册不创建第二账户，须走独立恢复策略（本功能外）。
- **Registration Idempotency Record（注册幂等记录）**: 幂等键、请求摘要、结果用户标识、创建时间与过期时间（默认首次受理后 24 小时）；窗口内用于安全重放，不保存敏感请求明文；过期后不再提供首次结果重放。
- **Registration Form Session（注册表单会话，客户端）**: 用户在单次填写过程中的界面状态（输入值、校验提示、提交中、结果）；非持久权威数据，刷新后可丢失；不得作为账户是否存在的依据。
- **Registration Rate Limit Bucket（注册限流桶）**: 按来源 IP 与规范化手机号分别累计时间窗内的注册尝试次数；超限则拒绝；为防滥用控制面状态，不是账户事实源。

## 成功标准 *(必选)*

### 可度量结果

- **SC-001**: 100% 合法注册请求创建且只创建一条账户记录；对同一大陆号的噪声变体（空格/`+86`/全角）重复提交不产生第二条账户。
- **SC-002**: 对同一手机号发起 100 个并发请求时最多一个成功，不出现重复用户。
- **SC-003**: 在 24 小时窗口内，相同幂等请求重放 10 次均返回同一用户标识，账户记录数保持 1；窗口外使用旧键重放不得再返回该成功结果，且账户数不因过期重放而增加。
- **SC-004**: 95% 正常注册在 500 毫秒内完成，错误响应均包含可关联请求标识。
- **SC-005**: 自动化日志与响应扫描不出现完整手机号或其他凭证。
- **SC-006**: 未培训用户（或等价验收脚本）可在 2 分钟内从根路径首页占位经导航进入注册页，完成一次合法注册并看到成功确认。
- **SC-007**: 注册主路径的非法输入、活跃占用冲突与软删除不可用三类失败均在界面给出可读反馈（后两类语义可区分），且 100% 不展示其他账户的隐私字段。
- **SC-008**: 应用壳层提供至少根路径首页占位、注册页与未实现页三类可演示路由，手工或自动化 UI 检查均无白屏崩溃。
- **SC-009**: 在默认阈值下，同一 IP 在 15 分钟内第 21 次注册尝试、以及同一规范化手机号在 15 分钟内第 6 次注册尝试，均被拒绝且不产生新账户；限流响应可被自动化测试断言为区别于校验/占用/软删的限流类结果。

## 范围

### 范围内

- 手机号规范化、昵称与角色校验、唯一账户创建、幂等、统一业务响应和审计元数据。
- 注册 HTTP 契约与 API 服务侧注册用例。
- 前端应用最小壳层：根路径通用首页占位、入口布局与导航、路由骨架、注册页、未找到/未开放占位。
- 注册页与注册 API 的端到端联调路径（含加载、成功、校验失败、冲突、服务错误）。
- 注册相关单元、集成、并发、安全脱敏、限流与基础界面测试。
- 注册防滥用限流（IP + 规范化手机号双维度，默认可验收阈值）。

### 范围外

- 手机验证码、登录令牌签发、会话刷新、登出（后续登录功能）。
- 密码、实名认证、个人资料编辑、角色变更。
- 买家/卖家/管理业务工作台、额度市场、账单、Key 管理等业务页（仅允许占位）。
- 管理员开户或批量导入。
- 完整设计系统、主题切换、国际化多语言包、无障碍正式认证。
- 将业务服务并入本地依赖 Compose；注册联调仍遵循主机进程 + 已有本地依赖生命周期约定。

## 假设

- 依赖 SF01 的服务与前端脚手架、契约和测试入口；依赖 SF02 提供的本地依赖生命周期（若尚未激活，集成测试使用项目既有测试数据库策略）。
- V0.1 已决定允许角色 `both`，但消费路由必须由后续授权与撮合规则排除本人卖家 Key。
- 已删除手机号的再次注册需要独立账户恢复策略，不在普通注册范围；本功能仅返回专用“不可用/需恢复”错误并拒绝创建。
- 手机号：仅中国大陆 11 位（`1[3-9]…`）；输入侧允许空格、`+86`/`86`、全角数字等噪声清洗；国际号段扩展为后续增量，不得削弱已有唯一性与限流键语义。
- 注册成功后不自动登录；界面引导用户等待后续登录能力，可用占位“去登录”入口指向未实现或后续功能页。
- 界面文案以简体中文为主，与现有产品文档语言一致。
- “开始搭建 UI”解释为：**最小可导航壳层 + 可用注册页**，而非完整产品信息架构。
- 根路径默认是通用壳层/首页占位，不是注册表单；注册通过导航或显式路由进入。
- 注册限流默认阈值：IP 20 次/15 分钟、规范化手机号 5 次/15 分钟；阈值可配置但变更需走受控配置/评审，不得在无测试的情况下静默放宽。
- 完整设备指纹、验证码挑战、黑名单情报等高级风控不在本功能；限流为 V0.1 最小防刷能力。
- 注册幂等键默认保留 24 小时；清理过期记录不得破坏账户唯一性与审计事实。
- **数据备份与恢复（宪章 III）**：`users` 与 `registration_idempotency_records` 作为 API Service 拥有的 PostgreSQL 数据，**复用该实例/平台既有备份与非生产 restore 程序**，本特性不单独新增备份作业或独立恢复产品能力。软删除是业务态，不等于备份恢复；账户硬删、从备份点对点恢复用户、以及已删手机号的产品级「账户恢复」均 out of scope。幂等记录为 24h 控制面辅助数据，丢失后仅影响重放窗口，不以幂等表为账户事实源。
