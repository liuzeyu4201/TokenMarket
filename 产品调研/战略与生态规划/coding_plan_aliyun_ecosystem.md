## 一、阿里云百炼 Coding Plan

### 1.1 产品定位与推出背景

Coding Plan 是阿里云于 **2026年2月21日** 推出的编程模型订阅服务，依托阿里云百炼（Model Studio）大模型平台，为开发者提供固定月费的 AI 编码订阅方案。其核心卖点是**一次订阅、多模型通用**——整合了 Qwen3.5-Plus、Qwen3-Coder、GLM-5、Kimi-K2.5、MiniMax-M2.5 等多款主流编程模型，并兼容 Claude Code、Cursor、Cline、OpenClaw 等主流 AI 编码工具。

该产品定位为**高频编码场景的成本可控方案**，采用固定月费替代按量计费，避免开发者因 Token 消耗不可预测而产生的账单焦虑。

### 1.2 定价与套餐结构

| 套餐 | 原价（元/月） | 首月优惠价 | 续费优惠（历史） | 当前状态 |
|------|-------------|----------|--------------|---------|
| **Lite 基础版** | ¥40 | ¥7.9 | 次月5折（¥20） | 2026.3.20 起停止新购，4.13 起停止续费 |
| **Pro 高级版** | ¥200 | ¥39.9 | 次月5折（¥100），第三月恢复原价 | **唯一可新购档位**，每日 09:30 限量抢购 |

> **注**：首月优惠活动已于2026年终止，Lite 版全面下架。当前仅保留 Pro 版标准定价 ¥200/月。

### 1.3 额度机制详解

#### 请求次数配额（三层限流）

| 限额维度 | Lite 基础版 | Pro 高级版 | 重置规则 |
|---------|-----------|-----------|---------|
| **每 5 小时限额** | 1,200 次 | 6,000 次 | 动态刷新，消耗后 5 小时自动恢复 |
| **每周限额** | 9,000 次 | 45,000 次 | 每周一 00:00 (UTC+8) 重置 |
| **每月限额** | 18,000 次 | 90,000 次 | 订阅周期对应日 00:00 重置 |

#### 关键机制说明

| 机制维度 | 规则说明 |
|---------|---------|
| **额度单位** | 以"模型调用次数"为消耗单位，**非 Token 数量**。一次用户提问可能触发 5-30+ 次模型调用（取决于任务复杂度） |
| **Rollover（结转）** | ❌ **不支持**。月度额度按自然月或订阅周期清零，不结转至下月 |
| **过期机制** | 订阅到期后当月额度仍可使用至周期结束，到期自动停止服务 |
| **超额处理** | 额度消耗完毕后，**不会自动转为按量付费**，继续调用会失败报错，需等待下一周期额度刷新 |
| **退款政策** | 预付费订阅，不支持按日计费或中途退款 |
| **年付选项** | 暂无年付套餐，仅支持按月订阅 |

#### 额度消耗典型场景

| 任务类型 | 预估调用次数消耗 |
|---------|--------------|
| 简单问答/单行补全 | 5-10 次 |
| 代码生成/函数实现 | 10-20 次 |
| 代码重构/复杂调试 | 20-30+ 次 |
| 多文件理解与 Agent 任务 | 30-50+ 次 |

> 实际消耗受上下文长度、工具调用次数、Agent 规划步骤数等因素影响。

### 1.4 浪费可能性评估

#### 典型用户实际使用率分析

| 用户类型 | 月均编码天数 | 日均请求估算 | 月消耗估算 | 与 Pro 额度对比 | 浪费风险 |
|---------|-----------|-----------|----------|---------------|---------|
| 兼职开发者 | 8-10 天 | 50-100 次/天 | 400-1,000 次 | 远低于 90,000 | 🔴 **极高浪费** |
| 个人开发者 | 15-20 天 | 100-200 次/天 | 1,500-4,000 次 | 远低于 90,000 | 🔴 **高浪费** |
| 重度开发者 | 22-25 天 | 300-500 次/天 | 6,600-12,500 次 | 约 7%-14% | 🟡 中等 |
| 专业团队（共享） | 30 天 | 2,000-3,000 次/天 | 60,000-90,000 次 | 接近上限 | 🟢 低浪费 |

#### 社区用户反馈

- **"用不完"问题**：Pro 版 90,000 次/月额度对于个人开发者而言极为充裕，多数用户反馈实际使用量不足 10%
- **"月底清零"抱怨**：社区明确提及月度额度不结转，未用完部分直接清零，存在心理账户损失感
- **购买难度**：Pro 版每日限量抢购，部分用户反映抢购失败，造成需求无法被满足
- **配置误用导致额外扣费**：大量用户因误用通用 API Key（`sk-xxx`）而非专属 Coding Plan Key（`sk-sp-xxx`），导致按量计费扣费，被社区广泛讨论

#### 浪费主要原因

1. **使用频率不稳定**：开发者项目存在间歇性，忙时高峰、闲时几乎不用
2. **需求波动**：简单任务与复杂任务交替，无法预测月度消耗
3. **每5小时/每周限额设计**：短期限额可能导致"想用时没额度，不用时额度闲置"
4. **不可结转机制**：未使用额度完全作废，无法累积到高需求月份
5. **单用户订阅模式**：不支持多人共享，团队使用需分别购买，加剧个体浪费

### 1.6 商业模式特点

| 特征 | 说明 |
|------|------|
| **核心模式** | **固定订阅 + 请求次数限额**（非 Token 计费） |
| **与按量付费对比** | Coding Plan 仅按请求次数，不按 Token；通用 API 按 Token 计费（输入+输出分开） |
| **节省计划** | 百炼平台另有"节省计划"，承诺月消费金额换最高 5.3 折，抵扣所有模型推理费用，与 Coding Plan 独立 |
| **资源包** | 百炼提供按模型类型的预付费资源包（如图像生成资源包），与 Coding Plan 不互通 |
| **免费版转化漏斗** | 百炼新用户每个模型赠送 100 万 Token 免费额度（90 天内），先用免费额度再引导购买 Coding Plan |
| **企业版池化** | Coding Plan 本身不支持团队共享额度；需通过 Token Plan 团队版实现弹性用量包跨坐席共享 |
| **折扣机制** | 早期有首月 2 折、次月 5 折优惠；当前已取消，仅 Pro 版标准价 |
| **Batch 折扣** | 按量付费模式下支持 Batch 批量调用（50% 折扣），Coding Plan 不支持 |

## 二、通义灵码（Qoder CN）

### 2.1 产品演进与更名

通义灵码（Lingma）是阿里云推出的 AI 编码助手 IDE 插件，2026年5月20日正式更名为 **Qoder CN**，同时从单一 IDE 插件升级为覆盖编码（Qoder CN IDE/插件）、办公（QoderWork CN）、终端（Qoder CN CLI）的全场景 AI 智能体产品矩阵。更名伴随计费机制从"免费/固定席位"全面转向 **Credits 配额制**。

### 2.2 定价与套餐结构

#### 2026年5月20日调整后定价

| 版本 | 月费（元） | Credits 额度 | 核心功能 | 起购要求 |
|------|----------|-------------|---------|---------|
| **个人社区版** | **免费** | 有限智能补全 + 体验资源 | 基础代码补全、每月有限 Agent 会话 | 阿里云主账号 |
| **个人专业版** | **¥59/月** | 2,000 Credits/月 | 不限代码补全、RepoWiki、Quest、Experts | 阿里云主账号 |
| **企业标准版** | **¥99/席位/月** | 3,000 Credits/席位/月 | Pro 全部 + 企业知识库 + 组织代码库增强 | 须主账号购买 |
| **企业 VPC 版** | **¥199/席位/月** | 3,000 Credits/席位/月 | Teams 全部 + VPC 部署 + IP 白名单 + 专有网络 | **最低 50 席位起购** |

#### 历史价格对比（更名前后）

|------|-----------------|-----------------|------|
| 个人专业版 | 限时免费 | ¥59/月 | 从 0 → 59（无限大） |
| 企业标准版 | ¥59/席位/月 | ¥99/席位/月 | **+67.8%** |

#### 资源包（超额补充）

### 2.3 额度机制详解

| 机制维度 | 规则说明 |
|---------|---------|
| **Credits 定义** | 全产品统一资源计量单位，代码补全、对话、文件处理、自动化任务均消耗 Credits |
| **重置周期** | **按月重置**，当月未使用额度不累计至下月 |
| **Rollover** | ❌ **不支持**，月底清零 |
| **过期机制** | 订阅 Credits 按月过期；资源包 Credits 按购买后 1/3 个月过期 |
| **超额处理** | 当月额度用完后，可购买资源包继续使用；无资源包则相关功能受限（但代码补全在部分版本中仍可用） |
| **池化分配** | 2026年7月更新后，企业版支持**共享资源池**，管理员可动态分配 Credits 给成员或计费组，减少低使用率席位的浪费 |
| **单日上限** | 企业管理员可设置单账号单日消耗上限，避免资源浪费 |
| **产品间互通** | ❌ Qoder CN 与 QoderWork CN 的 Credits **不能跨产品共享** |

### 2.4 浪费可能性评估

#### Credits 消耗效率

| 操作类型 | 消耗 Credits | 个人专业版可完成次数 |
|---------|-------------|------------------|
| 简短代码补全 | 低 | 极高（补全不计入限额） |
| 普通问答/Chat | 中 | 约 100-200 次 |
| 长文本生成/项目分析 | 高 | 约 20-50 次 |
| 多轮复杂 Agent 任务 | 很高 | 约 10-20 次 |

#### 社区反馈与浪费抱怨

| 反馈类型 | 具体内容 |
|---------|---------|
| **免费变付费反弹** | 个人专业版从"限时免费"转为 ¥59/月，社区出现大量"不如用 Cursor/Trae"的讨论 |
| **Credits 不互通** | Qoder CN 与 QoderWork CN 独立计费，用户抱怨同一账号两套额度无法共享 |
| **企业版涨价** | 企业标准版涨价 67.8%，引发中小企业预算重新评估 |
| **功能与额度错配** | 核心能力（RepoWiki、Quest、Subagent）宣称"不限次数"，但 Credits 额度有限，实际使用存在隐性约束 |
| **响应超时消耗** | 用户反馈请求超时或"虚假完成"（文件未实际修改）但 Credits 可能已扣除 |

#### 浪费原因分析

1. **个人开发者月均使用不均**：编码需求集中在项目冲刺期，闲时额度完全闲置
2. **Credits 与操作复杂度不透明**：用户难以预估一个任务消耗多少 Credits
3. **产品矩阵分散**：IDE、桌面、CLI 各自计费，多场景用户面临重复购买
4. **企业席位利用率不均**：部分团队成员高频使用，部分几乎不用，固定席位配额造成结构性浪费

### 2.5 用户画像与市场规模

### 2.6 商业模式特点

| 特征 | 说明 |
|------|------|
| **核心模式** | **Credits 配额制**（类 Token 但非 Token，是平台自定义资源单位） |

## 三、Qwen-Coder API 定价与计划

### 3.1 模型矩阵与定位

Qwen-Coder 是阿里云通义千问系列中专为编程场景优化的模型家族，通过阿里云百炼平台（DashScope）提供 API 服务。采用**纯按量付费**（Pay-as-you-go）模式，按输入/输出 Token 数量计费。

### 3.2 按量付费定价（中国内地 - 华北2北京）

| 模型 | 输入单价（元/百万 Token） | 输出单价（元/百万 Token） | 适用场景 |
|------|------------------------|------------------------|---------|
| **qwen3-coder-next** | ¥0.144（≤32K）<br>¥0.216（32K-128K）<br>¥0.359（128K-256K） | ¥0.574（≤32K）<br>¥0.861（32K-128K）<br>¥1.434（128K-256K） | 日常编程主力，性价比首选 |
| **qwen3-coder-30b-a3b** | ¥0.216（≤32K）<br>¥0.323（32K-128K）<br>¥0.538（128K-200K） | ¥0.861（≤32K）<br>¥1.291（32K-128K）<br>¥2.151（128K-200K） | 轻量快速响应 |
| **qwen3-coder-480b-a35b** | ¥0.861（≤32K）<br>¥1.291（32K-128K）<br>¥2.151（128K-200K） | ¥3.441（≤32K）<br>¥5.161（32K-128K）<br>¥8.602（128K-200K） | 复杂推理、大型项目 |
| **qwen-coder-plus（早期）** | ¥3.5 | ¥7 | 已被新模型替代 |

#### 国际站定价（新加坡/美国）

国际地域价格显著高于中国内地，约为国内价格的 **2-3 倍**，部分模型无免费额度。

### 3.3 额度机制与折扣

| 机制 | 说明 |
|------|------|
| **免费额度** | 新用户开通百炼后，主流模型各赠送 **100 万 Token**，有效期 **90 天** |
| **新用户总赠送** | 开通百炼可免费领取超 7000 万 Token（多个模型叠加） |
| **Batch 批量折扣** | 支持批量调用模式，输入输出单价均按实时价格的 **50%** 计算 |
| **上下文缓存（KV Cache）** | 部分模型支持缓存命中折扣，长对话重复调用可大幅降低输入费用 |
| **阶梯计价** | 部分模型按单次请求输入 Token 总量分档计费，超长上下文进入更高单价档位 |
| **费用抵扣顺序** | 免费额度 → 资源包 → 其他模型节省计划 → AI 通用型节省计划 → 按量付费 |

### 3.4 浪费可能性评估

| 场景 | 分析 |
|------|------|
| **免费额度浪费** | 90 天有效期，轻度用户可能未用完即过期；但抵扣顺序优先，新用户先消耗免费额度 |
| **资源包过期** | 预付费资源包有有效期，到期未用完清零 |
| **按量计费不可控** | 无订阅上限，重度使用或 Agent 循环可能导致账单激增 |
| **Batch 折扣利用不足** | 实时交互场景无法使用 Batch 模式，用户可能未充分利用 50% 折扣 |
| **缓存配置浪费** | 未开启上下文缓存导致重复输入 Token 重复计费 |

### 3.5 商业模式特点

| 特征 | 说明 |
|------|------|
| **核心模式** | **纯按量付费（Token 计费）** |
| **与 Coding Plan 对比** | Coding Plan 按请求次数固定月费；API 按 Token 量计费。两者互斥：Coding Plan 额度用完不转 API 按量 |
| **节省计划** | 承诺月消费金额换最高 5.3 折，适合稳定用量企业 |
| **资源包** | 预付费资源包（如图像生成资源包）按类型区分，不通用 |
| **定价策略** | 国内价格极具竞争力，qwen3-coder-next 输入仅 ¥0.144/百万 Token，约为 Claude 的 1/33 |
| **无订阅套餐** | 无固定月费订阅模式，仅按量 + 节省计划 + 资源包三种方式 |

## 四、跨产品对比与生态关系

### 4.1 阿里云生态三款产品对比

| 维度 | 百炼 Coding Plan | Qoder CN（原通义灵码） | Qwen-Coder API |
|------|----------------|---------------------|----------------|
| **产品形态** | 第三方工具 API 订阅 | IDE 原生插件/全场景智能体 | 百炼平台 API |
| **计费单位** | 请求次数（次/月） | Credits（自定义资源单位） | Token（输入+输出） |

## 五、商业模式洞察与浪费经济学分析

### 5.1 订阅经济模式类型判定

| 产品 | 模式类型 | 特点 |
|------|---------|------|
| 百炼 Coding Plan | **固定订阅 + 硬限额** | 类似"健身房月卡"，用不完不退，超额即停 |
| Qoder CN | **Credits 配额制** | 类似"游戏币充值"，虚拟货币隔离真实成本感知 |
| Qwen-Coder API | **纯按量付费** | 类似"水电煤气"，用多少付多少 |

### 5.2 浪费机制设计分析

#### 阿里云生态的"浪费漏斗"

1. **免费额度诱饵**：百炼 7000 万 Token + Qoder 社区版免费 → 培养用户习惯
2. **低价首月锁定**：Coding Plan 首月 ¥7.9/¥39.9 → 降低决策门槛，次月恢复原价制造沉没成本
3. **月度清零机制**：Coding Plan 和 Qoder Credits 均不 rollover → 强制用户每月重新付费，无论是否用完
4. **产品矩阵割裂**：Coding Plan / Qoder / API 三套独立计费 → 多场景用户被迫重复购买
5. **限额分层设计**：5小时/周/月三层限额 → 制造"额度焦虑"，引导用户购买更高档位

#### 企业版池化的修正逻辑

Qoder CN 企业版 2026年7月引入资源池化，本质是对"固定席位浪费"问题的修正：
- 旧模式：10 人团队买 10 个席位，3 人高频使用、7 人低频 → 7 个席位额度大量浪费
- 新模式：共享 Credits 池，按需分配 → 减少结构性浪费，但增加了管理复杂度

## 七、结论与趋势判断

### 7.1 核心发现

1. **阿里云采用"三轨并行"策略**：Coding Plan（固定订阅请求次数）+ Qoder Credits（配额制 IDE 工具）+ API 按量（灵活计费），覆盖不同使用场景，但三套体系**互不相通**，存在生态内重复付费问题。

2. **从普惠到收割的转型**：2026年5月 Qoder 更名并取消免费专业版、企业版涨价 67.8%，标志阿里云 AI 编程产品从"用户获取期"进入" monetization（货币化）期"。

3. **浪费是设计的一部分**：月度清零、不结转、三层限额、产品割裂等机制，本质是订阅经济的经典利润杠杆——用户为"安全感"（不怕超额）和"便利性"支付溢价，实际使用率远低于购买额度。

4. **企业市场是盈利核心**：个人版竞争激烈（Trae 免费、DeepSeek 低价），但企业版凭借合规认证（ISO 27001、SOC 2、VPC 部署）和数据安全优势，具备更强定价权和客户粘性。

5. **价格竞争力仍在**：Qwen-Coder API 按量价格约为 Claude 的 1/33，即使在国内市场也属极致低价，这是阿里云挑战全球竞品的核武器。

### 7.2 趋势预测

| 趋势 | 判断 |
|------|------|
| Coding Plan 档位恢复 | 可能重新推出 Lite 档或中间档位，当前仅 Pro 档限制过窄 |
| Credits 互通 | 预计 2026 年内 Qoder CN 与 QoderWork CN 可能打通 Credits |
| 按量+订阅混合 | 可能出现"基础订阅 + 超额按量"的混合模式，替代纯硬限额 |
| 企业池化普及 | 团队共享额度将成为企业版标配，减少浪费抱怨 |
| 价格战持续 | 国内 Coding Plan 市场（阿里、腾讯、智谱、MiniMax）价格竞争将持续 |
