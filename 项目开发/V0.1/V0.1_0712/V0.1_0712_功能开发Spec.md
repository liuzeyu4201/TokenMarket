# V0.1_0712 功能开发 Spec

> **版本号**: V0.1_0712  
> **开发周期**: 2026-07-12 ~ 2026-08-12  
> **开发模式**: AI 驱动开发（Spec 约束）  
> **技术栈**: Go(代理网关) + Python/FastAPI(后端) + React(前端)

---

## 规范约束（全局）

1. **所有功能必须通过验收标准才算完成**。
2. **V0.1 不做安全、不做体验、不做计费、不做积分、不做前端 UI**。
3. **代码严格遵守 SOLID 原则**，接口优先于实现。
4. **所有数据写入必须幂等**，所有表必须软删除。
5. **接口响应统一格式**: `{ code, message, data, request_id }`。

## F02: 用户账户服务

### 功能描述
提供用户注册与登录能力。V0.1 阶段不做实名认证、不做密码加密（明文存储，仅用于技术验证）。用户分为买家和卖家两种角色。

### 输入
- 注册: `{ phone, nickname, role }`（role: buyer / seller / both）
- 登录: `{ phone }`（V0.1 简化，无密码验证）

### 输出
- 注册成功: 返回 user_id + token
- 登录成功: 返回 user_id + token

### 边界条件
- 同一手机号不可重复注册
- 角色 buyer 只能生成代理Key消费；角色 seller 只能接入Key挂售
- 用户不可同时作为买家消费和卖家挂售（避免自买自卖）

### 数据库表 `users`
| 字段 | 类型 | 约束 |
|------|------|------|
| id | UUID | PRIMARY KEY |
| phone | VARCHAR(20) | UNIQUE, NOT NULL |
| nickname | VARCHAR(50) | NOT NULL |
| role | VARCHAR(20) | NOT NULL |
| created_at | TIMESTAMP | DEFAULT now() |
| updated_at | TIMESTAMP | DEFAULT now() |
| is_deleted | BOOLEAN | DEFAULT false |

### 验收标准
| 编号 | 标准 | 验证方式 |

| F02-A1 | 调用注册接口，同一手机号重复注册返回错误 | 接口测试 |
| F02-A2 | 注册后数据库 users 表新增一条记录，id 为 UUID | 数据库检查 |
| F02-A3 | 登录接口返回 user_id 和 token，token 可用于后续认证 | 接口测试 |
| F02-A4 | 所有表记录包含 created_at / updated_at / is_deleted 字段 | Schema 检查 |

## F03: API Key 管理服务

### 功能描述
卖家将其从官方平台获取的原始 API Key 接入系统。V0.1 阶段 Key **明文存储**（不做加密），仅做技术验证。系统验证 Key 有效性后存入数据库。

### 输入
- 接入 Key: `{ user_id, platform, api_key }`
- 平台枚举: `volcano`（V0.1 仅支持火山方舟）

### 输出
- 接入成功: 返回 key_id + 当前剩余额度
- 接入失败: 返回具体错误原因

### 边界条件
- 仅支持火山方舟平台（`volcano`）
- 验证 Key 时调用火山方舟余额查询 API，3 秒内返回结果
- Key 验证失败（无效/余额为 0）拒绝存储
- 同一用户可接入多条 Key

### 数据库表 `api_keys`
| 字段 | 类型 | 约束 |
|------|------|------|
| id | UUID | PRIMARY KEY |
| user_id | UUID | FOREIGN KEY → users.id, INDEX |
| platform | VARCHAR(50) | NOT NULL |
| api_key | VARCHAR(500) | NOT NULL |
| remaining_quota | BIGINT | DEFAULT 0 |
| status | VARCHAR(20) | DEFAULT 'active'（active/paused/expired） |
| created_at | TIMESTAMP | DEFAULT now() |
| updated_at | TIMESTAMP | DEFAULT now() |
| is_deleted | BOOLEAN | DEFAULT false |

### 验收标准
| 编号 | 标准 | 验证方式 |
|------|------|----------|
| F03-A1 | 提交有效火山方舟 Key，系统调用官方 API 验证，3 秒内返回 key_id 和剩余额度 | 接口测试 |
| F03-A2 | 提交无效 Key，系统拒绝存储，返回 "Key 无效或余额不足" | 接口测试 |
| F03-A3 | 同一用户可接入多条 Key，数据库中可查询到多条记录 | 数据库检查 |
| F03-A4 | 卖家可暂停/恢复 Key 状态，暂停后 Key 不再参与路由 | 接口测试 |

## F04: 请求代理网关

### 功能描述
基于 OpenAI-compatible API 规范构建代理层。买家使用平台生成的代理 Key 调用 API，网关将请求转发至火山方舟官方 API，响应原样返回给买家。

### 输入
- 代理请求: `POST /v1/proxy/volcano/chat/completions`
- 请求头: `Authorization: Bearer {proxy_key}`
- 请求体: 标准 OpenAI ChatCompletion 格式

### 输出
- 成功: 火山方舟官方响应（流式或非流式）
- 失败: 统一错误响应 `{ code, message, data, request_id }`

### 边界条件
- 代理 Key 不存在或无效 → 返回 401
- 代理 Key 对应的所有原始 Key 均不可用 → 返回 503
- 支持 SSE 流式响应（`stream: true`）
- 请求超时: 60 秒

### 接口定义
```
POST /v1/proxy/{platform}/chat/completions
Headers:
  Authorization: Bearer {proxy_key}
  Content-Type: application/json
Body:
  {  // 标准 OpenAI ChatCompletion 格式
    "model": "string",
    "messages": [...],
    "stream": false
  }
```

### 验收标准
| 编号 | 标准 | 验证方式 |
|------|------|----------|
| F04-A1 | 使用有效代理 Key 调用 chat/completions，收到火山方舟正常响应 | 接口测试 |
| F04-A2 | 流式请求（stream=true）返回 SSE 格式数据，逐字输出 | 接口测试 |
| F04-A3 | 无效代理 Key 返回 401，错误信息包含 "invalid proxy key" | 接口测试 |
| F04-A4 | 代理网关处理请求延迟（TTFB）P95 < 800ms | 压测 |
| F04-A5 | 代理请求成功率 > 98%（100 次连续请求统计） | 压测 |

## F05: 火山方舟平台适配器

### 功能描述
实现 `PlatformAdapter` 接口，将 OpenAI-compatible 请求格式转换为火山方舟 API 格式，将火山方舟响应转换回 OpenAI-compatible 格式。

### 接口契约
```go
type PlatformAdapter interface {
    Name() string                              // 返回 "volcano"
    ValidateKey(ctx, key string) (*KeyInfo, error)  // 验证 Key 有效性，返回余额
    Forward(ctx, req *ProxyRequest, key string) (*ProxyResponse, error)  // 转发请求
    ParseUsage(resp *ProxyResponse) (*UsageInfo, error)  // 解析用量
}
```

### 输入
- `ValidateKey`: 原始 API Key 字符串
- `Forward`: ProxyRequest（含 method, path, headers, body）

### 输出
- `ValidateKey`: KeyInfo（valid bool, remainingQuota int64, models []string）
- `Forward`: ProxyResponse（statusCode, headers, body io.Reader）
- `ParseUsage`: UsageInfo（promptTokens, completionTokens int）

### 边界条件
- 火山方舟 API 返回 429（限流）→ 标记 Key 为限流状态，30 秒后恢复
- 火山方舟 API 返回 401/403 → 标记 Key 为无效，从路由池移除
- 火山方舟 API 超时（>30s）→ 返回 504 Gateway Timeout

### 验收标准
| 编号 | 标准 | 验证方式 |
|------|------|----------|
| F05-A1 | 火山方舟适配器实现 PlatformAdapter 接口全部方法 | 编译检查 |
| F05-A2 | 调用 ValidateKey 返回正确的余额信息（与官方一致） | 接口测试 |
| F05-A3 | 调用 Forward 成功返回官方响应，HTTP 状态码一致 | 接口测试 |
| F05-A4 | 官方返回 429 时，适配器正确解析并返回特定错误码 | Mock 测试 |
| F05-A5 | 新增平台时只需新增 adapter 文件，不修改路由核心代码 | 代码审查 |

## F06: 基础轮询路由

### 功能描述
将买家的代理请求按 Round-Robin 方式分发给可用的卖家原始 Key。V0.1 阶段仅实现最简单的轮询，不考虑延迟/性价比。

### 输入
- 目标平台: `volcano`
- 可用 Key 列表（来自健康检查）

### 输出
- 选中的卖家原始 Key ID

### 边界条件
- 无可用 Key → 返回错误，不转发请求
- Key 被标记为 paused / expired → 跳过
- 每个 Key 的并发请求不超过官方限速的 80%

### 路由算法
```
keys = 查询 platform='volcano' AND status='active' 的 Key 列表
if keys 为空:
    return 错误
selected = keys[nextIndex % len(keys)]
nextIndex++
return selected
```

### 验收标准
| 编号 | 标准 | 验证方式 |
|------|------|----------|
| F06-A1 | 2 条可用 Key，连续 10 次请求，每条 Key 被选中 5 次（轮询） | 单元测试 |
| F06-A2 | 所有 Key 不可用时，请求返回 503，不崩溃 | 单元测试 |
| F06-A3 | Key 被暂停后，不再被路由选中 | 单元测试 |
| F06-A4 | 路由选择延迟 < 10ms（Redis 缓存命中时 < 5ms） | 性能测试 |

## F07: 健康检查机制

### 功能描述
每 30 秒对所有接入的卖家 Key 执行健康检查：调用官方余额查询 API 验证 Key 是否仍然有效、余额是否充足。

### 输入
- 数据库中所有 `status = 'active'` 的 Key 列表

### 输出
- 更新 Key 状态（active / down / rate_limited）
- 无效 Key 从路由池移除

### 边界条件
- 健康检查失败（网络错误 / 官方 API 不可用）→ 重试 3 次后标记为 down
- 余额为 0 → 标记为 expired
- 官方返回 429 → 标记为 rate_limited，30 分钟后恢复检查

### 验收标准
| 编号 | 标准 | 验证方式 |
|------|------|----------|
| F07-A1 | 健康检查每 30 秒执行一次，覆盖所有 active Key | 日志检查 |
| F07-A2 | Key 连续 3 次健康检查失败后，状态变为 down，从路由池移除 | 单元测试 |
| F07-A3 | Key 余额为 0 时，状态变为 expired | 单元测试 |
| F07-A4 | 健康检查不阻塞正常请求处理（异步执行） | 代码审查 |
| F07-A5 | Key 恢复后（如官方 API 恢复），自动重新加入路由池 | 单元测试 |

## F08: 用量计量服务

### 功能描述
拦截代理请求和官方响应，解析 Token 使用量（输入 Token 数 + 输出 Token 数），记录到用量日志表。V0.1 阶段仅记录，不做计费扣减。

### 输入
- 请求体（包含 messages）
- 响应体（包含 usage 字段）

### 输出
- 用量日志记录（写入 `usage_logs` 表）

### 数据库表 `usage_logs`
| 字段 | 类型 | 约束 |
|------|------|------|
| id | UUID | PRIMARY KEY |
| proxy_key_id | UUID | FOREIGN KEY → proxy_keys.id, INDEX |
| api_key_id | UUID | FOREIGN KEY → api_keys.id, INDEX |
| user_id | UUID | FOREIGN KEY → users.id, INDEX |
| platform | VARCHAR(50) | NOT NULL |
| model | VARCHAR(100) | NOT NULL |
| prompt_tokens | INTEGER | DEFAULT 0 |
| completion_tokens | INTEGER | DEFAULT 0 |
| total_tokens | INTEGER | DEFAULT 0 |
| request_id | VARCHAR(100) | NOT NULL, INDEX |
| latency_ms | INTEGER | DEFAULT 0 |
| status_code | INTEGER | DEFAULT 200 |
| created_at | TIMESTAMP | DEFAULT now() |

### 边界条件
- 响应中无 usage 字段 → 使用 tiktoken 估算 Token 数
- 流式响应 → 在流结束时汇总 Token 数
- 请求失败（status_code != 200）→ 仍记录日志，total_tokens = 0

### 验收标准
| 编号 | 标准 | 验证方式 |
|------|------|----------|
| F08-A1 | 成功请求后，usage_logs 表新增一条记录，token 数与官方响应一致 | 数据库检查 |
| F08-A2 | 流式请求结束后，记录汇总后的总 token 数 | 数据库检查 |
| F08-A3 | 请求失败时，记录 status_code 和 latency，token 数为 0 | 数据库检查 |
| F08-A4 | 计量数据采集不阻塞响应返回（异步记录） | 代码审查 |
| F08-A5 | 1000 次连续请求后，usage_logs 表记录数 = 1000 | 压测 |
