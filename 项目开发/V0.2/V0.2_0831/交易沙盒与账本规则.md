# V0.2 交易沙盒与账本规则

## 1. 资产边界

V0.2 只提供不可购买、不可转让、不可兑换、不可提现的测试额度，用于验证完整交易和结算流程。测试额度与人民币或其他法币不存在 1:1 锚定；不提供充值、支付、托管、提现、发票和税务功能。

买家扣减、卖家测试收益、平台价差和冲正均通过不可变分录表达。任何余额视图都是分录聚合结果，禁止直接修改余额字段修账。

## 2. 定价规则

对一笔已解析基础成本：

```text
买家扣减 = 基础成本 × 买家倍率
卖家收益 = 基础成本 × 卖家报价倍率
平台价差 = 买家扣减 - 卖家收益
```

必须保证平台价差不为负。卖家报价受平台上下界约束；价格范围、买家倍率、卖家倍率和厂商费率均版本化。请求在进入网关时锁定价格版本，后续配置变更只影响新请求。

## 3. 基础成本优先级

1. upstream 响应明确提供可验证的货币花费时，以该金额为结算基础。
2. 否则使用厂商返回的 token/usage 维度乘以请求锁定的版本化费率。
3. 非 token API 若既无货币花费、又无适用费率，进入 `unresolved`，不得伪造为 0。
4. 金额和 usage 同时存在时，金额用于结算，usage 计算值用于差异检测与告警。

所有货币或测试额度计算使用定点小数和明确币种/单位，禁止使用二进制浮点。

## 4. 生命周期

请求前按预算和预估上限创建 reservation；请求结束创建 usage observation；可立即确定的费用同步 settle，不可立即确定的进入异步 reconciliation。超额、取消、超时、重复回调和迟到事件必须幂等处理。

账务状态至少包括 `reserved`、`settled`、`released`、`unresolved`、`reversed`。冲正通过相反分录完成，原始分录永不删除或覆盖。

## 5. 对账与审计

每笔分录关联 request_id、project_id、buyer、connection、route decision、usage source、rate version 和原始厂商证据摘要。管理员可按差异阈值查询未决和异常，并执行带原因、审批与审计的重算或冲正；管理员不能直接输入最终余额。

## 6. 验收

- 并发重试和重复事件不会重复扣减或收益入账。
- 所有已完成请求最终处于 settled、released 或明确 unresolved，无静默悬挂。
- 任意余额可从不可变分录重建，重建结果与在线余额一致。
- 价格变更前后的并发请求分别使用各自锁定版本。
- 对账差异、人工动作及冲正形成完整审计链。
- 不存在充值、提现、法币锚定或可兑现措辞和接口。
