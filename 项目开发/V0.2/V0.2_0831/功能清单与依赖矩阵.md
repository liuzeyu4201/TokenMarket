# V0.2 功能清单与依赖矩阵

## 1. 编号规则

- `SFxx` 是本版本的来源功能编号，只存在于 `项目开发/V0.2/V0.2_0831/specs/`。
- 开始实现时，每个 SF 再映射到一个根 `specs/NNN-short-name/` 目录。
- 一个根 Spec Kit 功能默认只实现一个 SF；确需拆分时在映射表中记录原因。
- 横切文档不是可跳过的建议，所有相关 SF 都必须满足其约束。

## 3. 建议实施批次

### 批次 A：契约与生产架构地基

SF01 → SF02 → SF03/SF04 → SF05。

本批次先解决 V0.1 进程内状态、同步用量回写和单实例部署无法证明 500 RPS 的问题。

### 批次 B：身份与产品壳

SF06 → SF07 → SF08 → SF09，同时准备 SF30 的管理员身份边界。

### 批次 C：买家与卖家领域基础

SF10–SF12 与 SF14–SF16。本批次只建立 Project、Binding、代理 Key、Connection 与
供给生命周期；SF13 的额度/账单体验和 SF17 的报价工作台必须等待交易沙盒定价基础，
不得用伪造金额提前激活。

### 批次 D：协议透传

SF18 → SF22 → SF19/SF20/SF21。三家厂商可并行实现，但必须消费同一透明代理契约，
不得复制三套路由、鉴权或计量规则。

### 批次 E：用量与定价基础

SF26 → SF27。先完成原生计量和版本化价格事实，避免路由评分、报价与账本分别实现
不一致的价格算法。

### 批次 F：供给工作台与路由

SF17/SF23 → SF24；SF25 可与 SF24 并行，但必须共享资格过滤和资源所有权事实。

### 批次 G：交易沙盒闭环

SF28 → SF29 → SF13。任何余额或收益 UI 在不可变账本和对账完成前不得激活。

### 批次 H：运营与上线

SF30 → SF31 → SF32 → SF33 → SF34。SF34 是版本发布门禁，不是可延期的测试收尾。

## 4. 每个 SF 的完成定义

每个 SF 必须同时具备：

1. 明确范围、非范围、依赖和失败行为。
2. 可独立执行的验收场景和稳定业务错误。
3. 先行版本化契约；数据变更有迁移、回退与兼容窗口。
4. 单元、契约、集成、并发和直接负向测试；适用时补性能、安全、恢复和 UI E2E。
5. 指标、日志、告警、责任人和运行手册。
6. 发布与回滚步骤，以及与根 Spec Kit 目录和测试证据的映射。
7. 未解决 Critical/High、安全凭据泄露、账本不可对账或破坏性迁移时不得完成。
