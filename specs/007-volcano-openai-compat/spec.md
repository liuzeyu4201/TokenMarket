# 功能规格：火山方舟请求与响应兼容

**功能分支**: `007-volcano-openai-compat`

**创建日期**: 2026-08-24

**状态**: 草案

**输入**: 用户描述："功能描述在 `项目开发/V0.1/V0.1_0712/specs/SF07-火山方舟请求与响应兼容.md`"

**源规格**: `项目开发/V0.1/V0.1_0712/specs/SF07-火山方舟请求与响应兼容.md`（SF07）；本规格将 OpenAI-compatible Chat Completions 与火山方舟之间的双向兼容、流式事件顺序、usage 完整性与稳定错误分类纳入 Spec Kit 可规划、可验收的功能规格。

## 目标与价值

在不向买家暴露火山方舟协议差异的前提下，为代理主链路提供 Chat Completions 请求、非流式响应、流式事件与错误分类的双向兼容。买家后续只需替换调用入口与代理 Key，不必为火山方舟重写请求或解析逻辑。

本功能是非流式代理（SF12）与流式代理（SF15）的前置适配能力：公开入口、买家认证、卖家 Key 选择与用量持久化由后续功能负责；本功能交付可独立验收的兼容转换与一次出站调用语义。

## Clarifications

### Session 2026-08-24

- Q: V0.1 对 Chat Completions 请求字段采取哪种策略？ → A: 扩展采样集：在 `model`、`messages`、`stream`、`temperature`、`max_tokens` 之上纳入 `top_p`、`stop`、`presence_penalty`、`frequency_penalty`；`n` 若出现必须为 1。顶层未声明字段（工具调用、`response_format` 等）仍拒绝，不得静默透传。`messages[].content` 形态以本 session 下一问为准。
- Q: `messages[].content` 在 V0.1 接受哪种形态？ → A: 接受任意 OpenAI-compatible content 形态并原样转发（含多模态 parts）；本功能不对 content 做形态校验或扁平化。上游无法处理时按既有错误分类返回，不得在本层改写或丢弃 content。
- Q: 上游已给出可用生成结果，但 `usage` 缺失或不自洽时如何交付？ → A: 仍返回兼容成功对象（保留 `choices` 等）；`usage` 以显式不完整/不自洽状态交给 SF17，不得填 0，也不得标为永久 `invalid`。
- Q: 调用方未提供截止时间时如何约束一次出站调用？ → A: 有截止则遵守（可再套上限）；缺失则默认 60 秒硬截止，到期按 `timeout` 结束并传播取消。
- Q: `stream=true` 时上游失败或超时按哪个分界处理？ → A: 未向调用方交出任何兼容事件 → 结构化错误（与非流式同类分类）。已交出至少一事件 → `truncated_stream`，保留已发生顺序，不补终止标记、不插入错误 JSON。
- Q: SC-002 转换 P95（5 ms / 1 ms）如何验收？ → A: **目标仍为** 非流式转换（不含上游等待）P95 < 5 ms、单事件转换 P95 < 1 ms。**CI 红线**是正确性 + 流式路径不得为转换而聚合完整响应（禁止 `ReadAll` 全上游字节）。P95 用 `go test -bench` 在记录的环境写入 `evidence/`，**不**把嘈杂墙钟 5 ms/1 ms 当作默认 CI 失败条件。合入必须附 bench 输出与环境（OS/CPU/`GOMAXPROCS`）。
- Q: SC-005「不少于 1 万个流事件」如何验收？ → A: **CI 红线**：内存确定性生成器产出 ≥10_000 个多样化 SSE 事件（含拆包、合包、注释、正常 `[DONE]`），断言零丢失、零重复、零补造终止。不依赖真实网络。模糊测试是补充，不能代替该计数门禁。

## 用户场景与测试 *(必选)*

### 用户故事 1 - 转换非流式聊天请求与响应 (优先级: P1)

作为代理调用方，我希望标准 Chat Completions 非流式请求经火山方舟执行后，仍返回兼容的成功响应，以便现有客户端无需改解析逻辑。

**优先级理由**: 非流式往返是 V0.1 代理主链路的最小可交付切片；请求字段语义或响应形状一旦漂移，买家客户端会静默出错或生成结果与意图不符。

**独立测试**: 使用标准兼容测试集与受控上游替身，输入仅含 V0.1 支持字段的非流式请求，对比转换前后的模型、消息顺序、采样参数、choices、finish_reason 与 usage 语义。

**验收场景**:

1. **Given** 请求只使用 V0.1 已声明支持字段（含扩展采样集）且取值合法，**When** 转换并向受控火山方舟契约发起非流式调用，**Then** 公开模型、消息顺序与已声明生成参数（含 `temperature`/`top_p`/`stop`/penalty）的语义保持一致。
2. **Given** 上游返回正常非流式结果且 `usage` 完整自洽，**When** 转换响应，**Then** 返回兼容的 `id`、`object`、`created`、`model`、`choices`、`finish_reason` 以及可用的 `usage`。
2a. **Given** 上游返回可读的 `choices` 但 `usage` 缺失，或 `total_tokens` 小于分项之和，**When** 转换响应，**Then** 仍返回兼容成功对象（`choices` 保留）；用量观察标记为不完整或不自洽，不得把 `usage` 填为 0，不得改为 `invalid_response` 或永久 `invalid`。
3. **Given** 请求包含未声明支持的顶层字段、未知 `role`、空 `messages` 或非法类型，**When** 转换前校验，**Then** 返回明确参数错误，不发起会改变用户意图的上游调用，也不静默丢弃这些字段后继续生成。
4. **Given** `messages[].content` 为字符串、文本 parts 数组或含非 text 的多模态 parts，**When** 转换请求，**Then** content 原样进入出站请求，本功能不因 content 形态拒绝或改写。
5. **Given** 公开模型名称与上游模型名称不一致，**When** 转换请求与响应，**Then** 出站使用映射后的上游名称，对调用方回传公开模型名称；映射关系可追踪。

### 用户故事 2 - 转换流式事件 (优先级: P1)

作为流式代理能力，我希望每个上游响应块被转换为有序兼容事件，并以唯一终止标记正确结束，以便客户端按到达顺序消费，而不必等待完整回复。

**优先级理由**: 流式是买家实时体验的核心路径；事件顺序、拆包/合包与终止标记一旦出错，客户端会卡死、重复或解析失败。建议与 US1 同批交付，否则主链路只能覆盖非流式。

**独立测试**: 以多块、拆包、合包、注释/空行、半个字符边界以及末块 usage 的受控事件流验证转换结果、顺序与终止行为。

**验收场景**:

1. **Given** 上游发送流式增量，**When** 转换事件，**Then** `role`、`content`、`finish_reason` 与 choice 索引语义保持一致，且事件顺序与上游完成顺序一致。
2. **Given** 上游正常结束，**When** 处理末块，**Then** 可用 `usage` 被保留（若缺失或不自洽则按不完整状态交给 SF17，仍输出终止标记），且只输出一次兼容终止标记（契约标识 `[DONE]`）。
3. **Given** 单个逻辑事件被拆成多个网络块，或同一网络块含多个事件，**When** 流解析，**Then** 在事件完整前不输出损坏片段；合包后按事件边界输出。
4. **Given** 流中存在注释、空行、多行 data、未知事件类型或半个字符边界，**When** 解析，**Then** 合法事件仍按序产出，非法或不完整片段不得变成看似成功的兼容 JSON。
5. **Given** `stream=true` 且尚未向调用方交出任何兼容事件时上游失败或截止到达，**When** 适配，**Then** 返回与非流式同类的结构化错误分类，不输出终止标记，也不开始一条空流。
6. **Given** `stream=true` 且已向调用方交出至少一个兼容事件后连接断开、超时或上游错误，**When** 适配，**Then** 以 `truncated_stream` 结束，保留已发生事件顺序，不补造终止标记，不在流上插入错误 JSON。

### 用户故事 3 - 稳定映射上游失败 (优先级: P2)

作为代理网关，我希望认证失败、权限失败、限流、超时、非法响应与截断流映射为稳定错误类别，以便 SF12/SF15 决定客户端响应、SF16 决定 Key 健康，且不把临时故障写成永久无效。

**优先级理由**: 错误分类直接决定是否冷却 Key、是否可重试、是否向买家暴露内部细节；分类错误会导致好 Key 被误杀或坏请求被重放。可在 US1 编排后独立验收。

**独立测试**: 模拟认证失败、权限拒绝、限流、超时、连接失败、非法响应、截断流与含敏感正文的错误，验证稳定分类、可重试语义与脱敏。

**验收场景**:

1. **Given** 上游判定凭证认证失败或无权限，**When** 适配响应，**Then** 输出永久认证/权限失败分类，并保留安全的上游状态类别，不返回原始凭证。
2. **Given** 上游判定请求被限流，**When** 适配响应，**Then** 输出 `rate_limited` 与机器可读的 `retry_after_seconds`，不标记凭证永久无效，且本功能不得自动重放本次生成请求。
3. **Given** 上游超时、连接失败、暂时性服务错误，或本层 60 秒硬截止到达，**When** 适配，**Then** 输出临时失败分类（截止到达为 `timeout`），不声称已成功生成，也不把 usage 填为 0。
4. **Given** 非流式上游响应缺少必需的 choices（或等价成功形状），**When** 转换，**Then** 输出 `invalid_response`，不得产出看似成功的兼容对象。
5. **Given** 流式连接在已交出事件之后中途断开，**When** 解析器收到结束，**Then** 报告 `truncated_stream`、保留已完成事件顺序，且不得补造终止标记、不得插入错误 JSON。
5a. **Given** `stream=true` 但尚未交出任何兼容事件，**When** 上游认证失败、限流、超时或协议错误，**Then** 返回结构化错误（如 `invalid`/`rate_limited`/`timeout`/`invalid_response`），行为与非流式同类失败一致。
6. **Given** 上游错误正文包含密钥、消息正文或其他敏感字段，**When** 生成对外错误与日志，**Then** 只包含脱敏摘要。

### 边界情况

- 空 `messages`、未知 `role`、空 `content`（content 形态本身不在本层校验）、超大请求体。
- 公开兼容模型名称与火山方舟模型名称不一致。
- HTTP 成功但响应缺少 `choices`（失败关闭）或缺少 `usage`（成功对象仍返回，usage 不完整）。
- `usage` 只出现在流末块、完全缺失，或 `total_tokens` 小于分项之和（后两者不丢弃 `choices`）。
- 流中存在注释、空行、多行 data、未知事件类型和半个字符边界。
- 调用方取消后仍到达的上游事件。
- 调用方未传截止时间：本层仍在 60 秒硬截止内结束。
- `stream=true` 且首个兼容事件尚未交出即失败：结构化错误，不开空流。
- `stream=true` 且已交出事件后失败：`truncated_stream`，不补 `[DONE]`、不插错误 JSON。
- 上游新增字段，或既有错误字段类型变化。
- 同一请求同时声明不支持的顶层字段（例如 `n>1`、工具调用、`response_format`）。多模态若只出现在 `messages[].content` 内，不在本层拒绝。
- 请求仅含扩展采样集内字段（`top_p`、`stop`、penalty）时应成功转换，不得当未知字段拒绝。
- 非 Chat Completions 的其他兼容端点被误交给本功能。

## 需求 *(必选)*

### 功能需求

- **FR-001**: V0.1 MUST 支持 OpenAI-compatible Chat Completions 的非流式与流式语义。本功能收到其他端点意图时 MUST 返回明确的不支持错误，不得猜测转换。
- **FR-002**: 请求转换 MUST 保留已声明支持字段的语义。V0.1 已声明支持字段为：`model`、`messages`、`stream`、`temperature`、`max_tokens`、`top_p`、`stop`、`presence_penalty`、`frequency_penalty`；`n` 可省略，若出现 MUST 等于 1。`messages[].role` 限于 `system`、`user`、`assistant`。`messages[].content` MUST 按调用方给定的 OpenAI-compatible 形态原样转发（字符串、文本 parts 或含非 text 的多模态 parts），本功能 MUST NOT 对 content 做形态校验、扁平化或部分丢弃。取值范围、默认值与是否允许省略（content 除外）MUST 写入版本化契约。
- **FR-003**: 未知顶层字段、未声明支持的顶层字段、未知 `role`、非法 JSON 类型、`n≠1`、工具调用或 `response_format` MUST 在出站前以明确参数错误拒绝。MUST NOT 静默丢弃会改变用户意图的顶层字段后再调用上游；MUST NOT 把未声明顶层字段原样转发给火山方舟。本条不适用于 `messages[].content` 的内部形态。
- **FR-004**: 非流式响应 MUST 标准化 `id`、`object`、`created`、`model`、`choices`、`finish_reason` 以及可用的 `usage`。缺少成功所必需的 `choices`（或契约规定的等价形状）时 MUST 失败关闭为 `invalid_response`。仅 `usage` 缺失或不自洽 MUST NOT 单独导致 `invalid_response`。
- **FR-005**: 流式响应 MUST 保持事件顺序、增量语义、choice 索引与唯一终止标记；解析 MUST 在事件完整之前不输出损坏 JSON，并正确处理跨网络块的拆分与合并。正常结束时即使 usage 不完整，MUST 仍输出唯一终止标记。失败分界见 FR-016。
- **FR-006**: `usage` MUST 标准化为非负整数 `prompt_tokens`、`completion_tokens`、`total_tokens`；当三分项均存在时，`total_tokens` MUST 不小于前两项之和，否则标记为不自洽，MUST NOT “修正”数值后当作官方计量，MUST NOT 因此丢弃已标准化的 `choices`。
- **FR-007**: 官方 `usage` 缺失或不自洽 MUST 作为显式完整性状态交给后续用量能力（SF17），MUST NOT 用 0 伪装官方计量结果。在 `choices`（或流式已完成增量）可读的前提下，MUST 仍向调用方交付兼容成功对象/已完成事件；MUST NOT 改写为 `invalid_response`、认证失败或永久 `invalid`。本功能 MUST NOT 估算 usage。
- **FR-008**: 上游认证失败、权限拒绝、限流、超时、暂时性服务错误、非法响应与截断流 MUST 映射到稳定错误类别，并保留是否可重试信息。限流 MUST 始终提供 `retry_after_seconds`（优先上游建议，缺失则默认 5 秒，与 SF06 一致、可配置）。
- **FR-009**: 出站请求头 MUST 采用允许列表；MUST NOT 把买家代理 Key、内部令牌或未允许的客户端头发送给火山方舟。卖家提供商凭证仅通过受控认证头使用。
- **FR-010**: 返回给调用方的头 MUST 采用允许列表，移除可能泄露上游基础设施或敏感信息的字段。
- **FR-011**: 本功能 MUST NOT 负责买家认证、卖家 Key 选择、凭证持久化、公开 HTTP 响应写入、健康状态机或用量账本写入。调用方（SF12/SF15 等）传入已选定的提供商凭证与请求标识。
- **FR-012**: 新增其他平台适配时 MUST NOT 修改本功能的火山方舟兼容规则；本功能 V0.1 仅覆盖火山方舟 Chat Completions。
- **FR-013**: 模型映射 MUST 确定：出站使用上游模型标识，对调用方回传公开模型标识；映射表 MUST 可配置且可追踪。公开模型不在 V0.1 支持集合内时 MUST 返回明确参数/不支持错误，不得擅自改成其他模型。
- **FR-014**: 每次出站 MUST 有界：调用方提供截止时遵守该截止（实现可对异常大值再套上限）；调用方未提供截止时 MUST 使用默认 **60** 秒硬截止。截止到达 MUST 分类为 `timeout`，传播取消、停止继续解析/出站，并释放连接与敏感内存；取消或超时后到达的上游数据 MUST NOT 再变成成功兼容对象或补造终止标记。默认 60 秒 MUST 可配置，且默认行为 MUST 有自动化测试。
- **FR-015**: 本功能对生成类请求 MUST NOT 自动重试（生成不可默认视为幂等）。仅转换/解析失败或出站前参数错误不得伪装成上游成功。
- **FR-016**: `stream=true` 的失败分界以是否已向调用方交出至少一个兼容事件为准：尚未交出时 MUST 返回与非流式同类的结构化错误（`invalid`/`forbidden`/`rate_limited`/`timeout`/`temporary_unavailable`/`invalid_response`/`unsupported_parameter` 等），MUST NOT 开始空流或补造终止标记；已交出后 MUST 以 `truncated_stream` 结束，保留已发生顺序，MUST NOT 补造终止标记，MUST NOT 在流上插入错误 JSON。该分界 MUST 有自动化测试。

### 工程需求 *(必选)*

- **ER-001 — 契约**: OpenAI-compatible 输入、非流式输出、SSE 事件、usage 观察与错误分类 MUST 有机器可校验的版本化契约与黄金测试。破坏性变化使用新契约版本。错误类别至少覆盖：`success`、`invalid`、`forbidden`、`rate_limited`、`temporary_unavailable`、`timeout`、`invalid_response`、`unsupported_parameter`、`unsupported_endpoint`、`truncated_stream`。`rate_limited` MUST 含 `retry_after_seconds`。字段名与枚举为契约标识，不是技术栈选择。
- **ER-002 — 安全与隐私**: 请求/响应消息正文默认不得记录；买家代理 Key、卖家原始 Key、内部令牌不得出现在日志、错误、指标、追踪或测试快照中。错误先脱敏再传播。测试仅使用合成夹具与受控替身。
- **ER-003 — 数据完整性**: Token 计数使用整数基础单位；禁止用二进制浮点表示 usage。模型映射必须确定且可追踪原始/公开名称。不得用 0 填补未知 usage。不得产出部分伪造的成功兼容对象。
- **ER-004 — 性能与容量**: 兼容转换自身不得成为可感知瓶颈：非流式转换（不含上游等待）P95 小于 5 毫秒；单个流式事件转换 P95 小于 1 毫秒（以记录环境的 bench 为证据，见 SC-002）。流式路径 MUST NOT 为了转换而聚合完整响应后再向调用方释放；该「不聚合」约束 MUST 有 CI 断言。
- **ER-005 — 可靠性**: 出站调用必须有界：`min(调用方截止, 配置上限)`，缺省硬截止 60 秒；到期为 `timeout`。取消必须传播。转换或协议失败不得生成部分伪造的成功响应。生成请求禁止自动重试。
- **ER-006 — 可观测性**: 记录平台、公开模型、流/非流、转换结果、错误类别、耗时与请求标识；不记录消息正文或凭证。兼容测试失败与 `invalid_response`/`truncated_stream` 须可告警。
- **ER-007 — 可访问性**: V0.1 无买家界面；兼容响应面向开发者客户端。错误 MUST 具备稳定代码与可操作说明（修正参数 / 更换模型 / 稍后重试），而非仅上游原始文案。

### 失败与恢复场景 *(必选)*

1. **Given** 非流式上游响应缺失必需的 `choices`（或契约规定的成功形状）或类型不符，**When** 转换，**Then** 返回 `invalid_response`，不输出看似成功的兼容对象，并发出可关联的协议错误信号。
1a. **Given** 非流式上游响应 `choices` 可读但 `usage` 缺失或不自洽，**When** 转换，**Then** 返回兼容成功对象，用量观察为不完整/不自洽，不得填 0，不得改为 `invalid_response`。
2. **Given** 流式连接在已向调用方交出至少一个兼容事件之后中途断开，**When** 解析器收到结束，**Then** 报告 `truncated_stream`，保留已完成事件顺序，不补造终止标记，不把已输出增量回滚，不在流上插入错误 JSON。
2a. **Given** `stream=true` 且尚未交出任何兼容事件，**When** 上游失败或硬截止到达，**Then** 返回结构化错误（与非流式同类分类），不输出终止标记，不开始空流。
3. **Given** 上游契约新增可忽略字段，**When** 现有兼容解析运行，**Then** 向后兼容字段可安全忽略；若新字段改变成功/失败语义，契约测试 MUST 阻止在未升版本情况下发布。
4. **Given** 调用方取消，或调用方截止 / 默认 60 秒硬截止已到，**When** 上游仍在发送，**Then** 以 `timeout`（截止）或取消语义停止继续转换与出站，释放连接与敏感内存，不得再写出完整成功响应。
4a. **Given** 调用方未提供截止，**When** 上游超过 60 秒仍未完成，**Then** 以 `timeout` 结束，不得无限等待。
5. **Given** 同一生成请求被重复提交到本功能，**When** 适配执行，**Then** 本功能不做跨请求去重或自动重放；幂等与重试策略由调用方在出站前决定。
6. **Given** 上游限流且未给建议重试时间，**When** 标准化错误，**Then** 分类为 `rate_limited` 且 `retry_after_seconds=5`（默认配置），不得省略该字段，不得自动重放本次生成。

### 关键实体

- **Compatible Chat Request（兼容聊天请求）**: 公开模型、消息、有界生成参数与 `stream` 标记。用户内容属于敏感数据，本功能不持久化。不变量：仅含契约已声明支持的顶层字段；未知/不支持顶层字段在出站前被拒绝；`messages[].content` 保持调用方原样，本层不校验其内部形态。
- **Provider Request/Response（提供商请求/响应）**: 火山方舟契约表示，只在一次调用期间存在。分类：含凭证与可能含用户内容，用后即释。
- **Compatible Stream Event（兼容流事件）**: 有序增量、完成原因、可选 usage 与终止状态。不变量：顺序稳定；终止标记仅在正常结束时至多一次；在已交出事件后的失败路径为 `truncated_stream`，不得补造终止、不得插入错误 JSON。尚未交出任何事件时不进入本实体的截断路径，而走结构化错误。
- **Usage Observation（用量观察）**: 官方返回的 Token 分项、完整性状态（完整 / 缺失 / 不自洽）与来源。不变量：缺失不得写成 0；不自洽不得“修正”后当作官方值；不完整 usage 不得否定已交付的兼容成功对象。本功能不估算、不持久化账本，由 SF17 消费。
- **Adapter Error Classification（适配错误分类）**: 稳定枚举（见 ER-001）。不变量：分类不依赖上游原始文案；临时类与截断不得写成永久 `invalid`。

## 成功标准 *(必选)*

### 可度量结果

- **SC-001**: 火山方舟兼容标准测试集（非流式请求/响应、流式事件、usage、错误分类）通过率为 100%。这是 V0.1 代理主链路的 Go/No-Go 指标。
- **SC-002**: 转换时延目标：非流式兼容转换（不含上游等待）P95 小于 5 毫秒；单个流式事件转换 P95 小于 1 毫秒。验收分两层：（1）**CI 红线**：流式路径不得聚合完整上游响应后再切事件；（2）**合入证据**：在记录环境跑 `go test -bench`，把输出与机器信息写入本功能 `evidence/`。默认 CI **不得**仅因共享跑机墙钟超过 5 ms/1 ms 而失败。
- **SC-002a**: 调用方不提供截止且上游阻塞时，100% 样本在 60 秒硬截止内以 `timeout` 结束，无无限等待。调用方提供更短截止时，100% 在该截止内结束。
- **SC-003**: 100% 已声明支持字段在往返测试中语义保持；所有未声明支持字段均得到确定的参数错误，而不是静默忽略或改写后再成功生成。
- **SC-004**: 认证失败、权限拒绝、限流、超时、暂时性上游错误、非法响应与截断流的分类准确率为 100%。其中 `stream=true` 且零事件失败的样本 100% 走结构化错误；至少一事件后失败的样本 100% 为 `truncated_stream` 且无补造终止标记、无错误 JSON 混入。
- **SC-005**: 在内存确定性生成器上，不少于 **10_000** 个多样化流事件（须覆盖拆包、合包、注释行与一次正常终止）的顺序、边界和终止标记测试为零丢失、零重复、零补造终止。该计数测试 **进入默认 CI**；模糊测试为补充。
- **SC-006**: 日志、错误、追踪和测试输出扫描不出现消息正文、买家代理 Key 或卖家原始 Key。
- **SC-007**: usage 缺失或不自洽、但生成结果可读的样本中，100% 仍交付兼容成功对象（或已完成流事件 + 终止标记），并以显式不完整/不自洽状态交给后续用量观察；0 条样本把未知 usage 写成全 0 官方计量，0 条因此被标为 `invalid_response` 或永久 `invalid`。

## 范围

### 范围内

- 火山方舟 Chat Completions 的请求转换、一次出站调用、非流式响应转换、SSE 事件转换、usage 观察与错误分类
- V0.1 支持字段清单（含扩展采样集：`top_p`、`stop`、`presence_penalty`、`frequency_penalty`、`n=1`）、模型名称映射、请求/响应头允许列表
- 流解析的拆包、合包、终止标记、截断与取消传播
- 供 SF12/SF15 消费的兼容结果与稳定错误；供 SF17 消费的 usage 完整性状态

### 范围外

- 公开代理 HTTP 入口与买家可见错误包络写入（SF12/SF15）
- 买家认证、授权、限流入口与卖家 Key 选择/路由（SF11/SF13 等）
- 凭证接入、加密与生命周期（SF08）
- Key 健康调度与周期探活（SF16）
- 用量账本持久化与估算规则落账（SF17）
- Embeddings、Models 列表、独立多模态端点、工具调用、`response_format`、多平台适配；不在本层规范化或拒绝 Chat Completions 的 `messages[].content` 形态
- 真实火山方舟作为默认 CI 上游（默认使用契约替身；真实联调为可选人工验收）

## 假设

- 依赖 SF06 已建立火山方舟客户端基线、错误分类习惯与当期官方契约复核方式；本功能复用其脱敏、限流 `retry_after_seconds` 默认 5 秒及临时/永久分类纪律，但覆盖 Chat Completions 而非仅 models 探活。
- V0.1 只承诺 Chat Completions；已声明支持字段以 FR-002 为准（扩展采样集），最终以本功能版本化兼容测试集清单锁定。清单扩容属于契约变更，不得靠静默透传或原样转发未声明字段实现。
- `n` 可省略，若出现 MUST 为 1；`n>1`、工具调用、`response_format` 等未纳入 FR-002 的顶层能力按 FR-003 拒绝。`messages[].content` 不做形态校验，原样转发；若火山方舟不接受某种 content，由上游错误经 FR-008 分类，本层不得预先改写 content。
- 公开模型集合与 SF06 的 V0.1 Chat Completions allowlist 对齐；名称映射在计划阶段用当期官方文档固化。
- SF12/SF15 负责公开传输与向买家写回；本功能遵守调用方传入的取消与截止，并在缺失截止时使用默认 60 秒硬截止（可配置，默认值由测试锁定）。SF12 若另有更短的公开入口上限，由调用方把更紧的截止传入本功能。
- SF17 负责 usage 持久化与（若产品需要）估算；本功能只提供观察与完整性状态，不估算、不因 usage 不完整而丢弃生成结果。
- 生成请求不可默认重试；本功能不做跨请求幂等去重。
- 流式失败分界「已交出至少一个兼容事件」属于适配层对调用方的交付观察，不是公开 HTTP 已写响应头；SF15 将此映射到「响应头发出后不得混入非流错误体」。
- 上游新增未知字段：成功路径可忽略不影响语义的额外属性；若缺少成功必需形状或类型变化导致无法标准化，则 `invalid_response`。
