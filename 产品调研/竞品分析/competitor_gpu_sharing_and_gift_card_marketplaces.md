## 1. Vast.ai

### 基本信息
| 字段 | 内容 |
|------|------|
| **产品名称** | Vast.ai |
| **网址** | https://vast.ai |
| **所属公司** | Vast.ai, Inc.（独立公司） |
| **产品形态** | P2P GPU 云市场平台（Marketplace） |

### 核心功能
- **全球GPU市场**：连接世界各地的GPU提供者与需求者，超过 20,000+ 块GPU、40+ 数据中心、68+ GPU型号。
- **三种实例类型**：
  - On-demand：固定价格，保证资源（高优先级）
  - Interruptible（可中断）：最低价格，可能被暂停（低优先级），拍卖式竞价
  - Reserved：预付费折扣，长期承诺可享最高50%折扣
- **Serverless 推理**：自动伸缩的GPU端点，按实际计算时间付费，无需运维。
- **API/CLI/SDK 原生**：全程支持程序化部署（Python SDK、CLI、REST API），5行代码即可启动实例。
- **DLPerf 评分系统**：硬件性能预测评分，帮助用户选择性价比最优的GPU。

### 商业模式
- **Marketplace 定价**：Host（GPU提供者）自行定价，供需驱动实时价格波动。
- **成本构成**：按秒计费，包含 GPU 计算费 + 存储费（实例存在即计费，即使停止）+ 带宽费（上传/下载）。
- **无 markup 加价**：Vast.ai 不在 host 定价上额外加价，收入来自平台服务费（具体比例未公开）。
- **启动门槛低**：最低 $5 即可开始使用。
- **对比传统云**：通常比 AWS/GCP 便宜 60-80%。

### 用户规模与关键数据
| 指标 | 数据 |
|------|------|
| GPU 数量 | 20,000+ |
| 数据中心 | 40+ |
| GPU 型号 | 68+ |
| 月交易量 | 700,000+ |
| 安全认证 | SOC 2 Type I, ISO 27001 |
| 知名客户 | IBM, Brave, Speechify, Cognition (Devin), Bosch |

### 信任保障机制
- **Host 可靠性评分**：用户可筛选高可靠性（99%+ 在线率）的提供者。
- **SOC 2 认证**：平台通过 SOC 2 Type I 审计。
- **预配置模板**：PyTorch、CUDA、TensorFlow 等环境开箱即用，降低配置风险。
- **持久存储**：支持直接数据复制和云同步。

### 与我们的异同
| 维度 | 相同点 | 不同点 |
|------|--------|--------|
| **痛点** | 闲置资源（GPU算力）未被充分利用，供需双方信息不透明 | 资源类型是**技术基础设施**而非消费品；用户需具备DevOps能力 |
| **模式** | P2P 撮合市场，价格由供需决定 | 完全去中心化的提供者网络，平台仅做撮合；我们的项目可能涉及更重的资产验证 |
| **信任** | 需要平台提供信誉/评级系统来降低交易风险 | GPU 资源可通过标准化测试验证性能；礼品卡等资产验证更复杂（余额、真伪、有效期） |
| **用户** | 双边市场（供给方 + 需求方） | 供给方是数据中心/矿工/个人，需求方是AI开发者/研究者；用户画像高度技术化 |

### 活跃度
- **状态**：✅ 非常活跃，持续运营
- **最新动态**：2026年仍持续更新，支持最新 NVIDIA B200、H200、RTX 5090 等型号；文档站点频繁更新（2026-04-29）

## 5. AWS Spot Instances

### 基本信息
| 字段 | 内容 |
|------|------|
| **产品名称** | Amazon EC2 Spot Instances |
| **网址** | https://aws.amazon.com/ec2/spot/ |
| **所属公司** | Amazon Web Services（AWS） |
| **产品形态** | 超大规模云厂商内部 Spot 市场（闲置容量拍卖） |

### 核心功能
- **闲置容量再利用**：AWS 将未售出的 EC2 容量以折扣价出售。
- **动态定价**：每个实例类型在每个可用区有独立的 spot price，基于实时供需波动。
- **自动伸缩集成**：与 Auto Scaling Groups、Spot Fleet、EC2 Fleet 无缝集成，自动管理容量和中断。
- **多样化策略**：支持容量优化分配、最低价格分配、多样化实例类型以降低中断风险。
- **中断处理**：2 分钟中断通知（通过 EventBridge 和实例元数据），支持终止、停止、休眠三种行为。

### 商业模式
- **动态定价（2017年后模式）**：用户设置最高价格（默认即 On-Demand 价格），实际支付当前 spot price，与竞价无关。中断由容量需求触发，而非价格。
- **折扣幅度**：比 On-Demand 便宜 50-90%。
- **无承诺**：无预付、无长期合同，纯按使用付费。
- **混合策略**：成熟团队通常采用 Reserved（基线容量）+ On-Demand（峰值）+ Spot（批处理/容错负载），综合节省 35-60%。

### 用户规模与关键数据
| 指标 | 数据 |
|------|------|
| 所属平台 | AWS（全球最大云厂商，2026年AI资本支出 ~$2000 亿） |
| 服务成熟度 | 2009年推出，2017年重构定价模型，极其成熟 |
| 中断通知 | 2 分钟 |
| 可用场景 | 批处理、CI/CD、渲染、大数据分析、ML 训练、无状态微服务 |

### 信任保障机制
- **2 分钟中断警告**：通过 CloudWatch Events 和 EC2 实例元数据服务提前通知。
- **Spot Instance Advisor**：官方提供历史中断率和价格趋势分析工具。
- **容量再平衡**：AWS 可在中断前发出早期信号（虽不保证），帮助主动迁移。
- **多样化容错**：通过 Spot Fleet 跨实例类型、跨区域、跨可用区分散风险。

### 与我们的异同
| 维度 | 相同点 | 不同点 |
|------|--------|--------|
| **痛点** | 闲置资源（算力）未被充分利用，通过价格机制释放供给 | 单一供应商（AWS）内部的资源调度，不是真正的双边市场；平台同时是供给方和需求方 |
| **模式** | 拍卖/动态定价机制 | 不是 P2P，而是**垄断供应商的二级定价**；没有独立供给方，AWS 自身就是唯一供给方 |
| **信任** | 平台（AWS）完全担保 | 信任来自 AWS 品牌和服务等级协议；无需解决陌生人之间的不信任 |
| **中断风险** | 买方需承担资源被回收的风险 | 资源被回收的补偿仅为低价；用户需自行架构容错；我们的项目需要设计类似但更友好的中断机制 |

### 活跃度
- **状态**：✅ 非常活跃，AWS 核心服务之一
- **最新动态**：持续作为 AWS 成本优化的标准工具，无中断运营记录

## 6. GCP Spot VMs / Preemptible

### 基本信息
| 字段 | 内容 |
|------|------|
| **产品名称** | Google Cloud Spot VMs（原 Preemptible VMs） |
| **网址** | https://cloud.google.com/spot-vms |
| **所属公司** | Google Cloud |
| **产品形态** | 超大规模云厂商内部 Spot 市场 |

### 核心功能
- **Spot VMs**：新版产品，无最大运行时间限制，随时可能被抢占（回收），30 秒警告。
- **Preemptible VMs**：旧版产品，最大运行时间 24 小时，30 秒警告（已逐步被 Spot VMs 取代）。
- **全实例类型支持**：所有 Compute Engine 机器类型均可作为 Spot VMs。
- **Managed Instance Groups（MIG）**：自动重启被抢占的实例，实现自愈容错。
- **GKE 集成**：Google Kubernetes Engine 原生支持 Spot VMs 作为节点池。

### 商业模式
- **固定折扣定价**：折扣幅度 60-91%（相对 On-Demand），spot price 每月最多变动一次。与 AWS 的实时动态定价不同，GCP 价格更稳定。
- **按分钟计费**：最少计费 1 分钟，之后按秒计费。
- **无 SLA**：不提供服务等级协议，不保证可用性。

- **持久磁盘保留**：抢占后启动磁盘保持完整，可快速重新启动。

|--------|------|
| **资产类型** | 算力是标准化技术资源（性能可量化）；我们的资产可能是非标准化的（如不同品牌的礼品卡、不同有效期的算力券），验证逻辑更复杂 |
| **用户画像** | 算力平台用户是技术专业人士；我们的用户可能是普通消费者，UX 要求更高、技术门槛更低 |
| **中断风险** | GPU 可中断实例是设计特性；我们的交易中"资产失效"（如礼品卡被原卖家盗刷）是欺诈问题，需要不同机制解决 |
| **基础设施** | 算力平台需要处理 SSH、容器、网络等技术栈；我们的基础设施是交易/支付/验证流程 |

#### 与礼品卡市场的主要差异

| 差异点 | 说明 |
|--------|------|
| **资产范围** | 传统礼品卡市场只处理礼品卡；我们的项目可能涉及更广泛的"预付资产"（算力券、API额度、订阅时长等） |
| **验证方式** | 礼品卡验证相对简单（查询余额）；算力券/技术资源需要更复杂的验证（如使用权限转移、API key 安全交接） |
| **实时性** | 礼品卡可以异步交易（买后几天使用）；算力资源通常需要即时交付 |
| **价值波动** | 礼品卡面值固定；算力券/技术资源可能因市场供需（如 GPU 短缺）产生更大价值波动 |

### 11.3 我们的差异化机会

#### 机会 1：跨品类资产撮合（礼品卡 + 算力券 + 其他预付资产）

- **现状**：Raise/CardCash 只处理礼品卡；Vast.ai/RunPod 只处理 GPU 算力。两类市场完全割裂。
- **机会**：如果我们的项目能同时处理**消费品预付资产**（礼品卡）和**技术预付资产**（算力券、API额度、云积分），可以创造独特的跨品类市场。例如：用户可以用闲置的 Starbucks 礼品卡换取 AWS 积分，或反之。

#### 机会 2：更先进的信任机制

- **现状**：
  - Raise.com：1年退款保证，但盗刷问题频发（买家购卡后原卖家立即使用）。
  - CardCash：平台做市商模式，承担风险但利润率受限。
  - Gift Card Granny：不做交易，信任完全外包给第三方。
- **机会**：
  - **智能托管（Smart Escrow）**：交易资金在托管账户中，买家确认资产有效后才释放。对于礼品卡，可要求卖家在交易期间锁定卡密（通过平台接口查询余额，交易完成前卖家无法操作）。
  - **链上验证**：利用区块链/智能合约记录交易和余额快照，提供不可篡改的审计追踪。
  - **声誉系统**：多维信誉评分（交易历史、响应速度、纠纷率），而非简单星级。
  - **保险池**：平台收取小额保险费，建立赔付池处理欺诈损失。

#### 机会 3：即时变现 + 市场定价双模式

- **现状**：CardCash 提供即时变现（但价格较低）；Raise 提供市场定价（但需等待匹配）。
- **机会**：同时提供两种模式：
  - **即时模式**：平台以固定折扣（如80%面值）立即收购，适合急需现金的用户。
  - **市场模式**：用户自主定价，平台撮合匹配，适合追求更高收益的用户。
  - 平台可根据库存情况动态调整即时收购价，优化库存周转。

#### 机会 4：B2B 企业礼品卡/算力券回收

- **现状**：现有平台主要面向 C2C；B2B 市场（企业多余礼品卡、员工福利卡、未使用云积分）服务不足。
- **机会**：企业通常有大量未使用的预付资产（营销礼品卡、员工激励卡、云服务商积分），需要一个合规、批量、可审计的渠道来变现。这是 Raise/CardCash 尚未充分覆盖的市场。

#### 机会 5：动态定价与套利检测

- **现状**：Raise 的定价完全由卖家手动设定，缺乏智能定价工具。
- **机会**：
  - 提供**AI 定价建议**：基于历史交易数据、品牌热度、余额大小、有效期等因素推荐最优定价。
  - **套利检测**：监控异常价格模式（如大量低折扣卡突然上架），预防欺诈和洗钱。
  - **价格趋势**：类似 Vast.ai 的"实时价格查询"，提供各品牌的折扣率历史和市场趋势。

#### 机会 6：技术资产的特殊处理（如算力券）

- **现状**：算力券/云积分类资产目前只能通过非正式渠道（如论坛、微信群）交易，风险极高。
- **机会**：
  - **API 集成验证**：与云服务商 API 对接，实时验证算力券/积分的有效性和余额。
  - **使用权限转移**：通过 OAuth/API key 安全转移算力资源的使用权，而非共享账号密码。
  - **使用追踪**：监控技术资产的使用情况，防止"一券多卖"或超额使用。
