# V0.2_0831 实现文档索引

本目录定义 TokenMarket V0.2 的版本范围、实现边界、子功能依赖与发布验收标准。
V0.2 的定位是“可公开上线的交易沙盒产品”：真实用户、真实上游调用、完整平台
流程和生产级质量门禁，但只使用不可购买、不可转让、不可提现的测试额度，不处理
真实充值、Escrow 或提现。

## 文档优先级

发生冲突时按以下顺序解释：

1. `.specify/memory/constitution.md`：安全、数据、架构、测试和交付最高约束。
2. [V0.2 实现总纲](./V0.2_0831_实现总纲.md)：版本目标、范围和已确认产品决策。
3. 本目录的横切实现文档：协议、架构、UI、账本和发布验收共同规则。
4. [子功能索引](./specs/README.md)及各 SF 文档：单一功能的详细需求与验收。
5. `项目开发/产品需求文档（PRD）.md`、`项目开发/产品迭代路线图.md`：长期产品语境。
6. `项目开发/1-项目架构与目录结构.md` 至 `4-前端与DevOps监控规范.md`：工程参考。

旧路线图中真实充值、等值人民币 TMP、Escrow 和提现要求与本版本已确认的交易沙盒
边界冲突，因此不进入 V0.2；后续版本若恢复真实资金能力，必须重新完成法律、支付、
财务和安全评审。

## 已确认的关键决策

- 只做原生同协议透传，不做 OpenAI、Anthropic、Vertex 之间的格式转换。
- 覆盖发布基线中全部公开稳定的模型数据面 API；账号、组织、IAM、支付和上游
  凭据管理控制面明确拒绝。
- Project 优先；一个 Project 可启用多个协议，但整个 Project 只能是共享型或专享型。
- 共享型只允许无状态端点；专享型独占 Provider Connection，支持状态型资源。
- 专享连接故障时失败关闭，不自动更换；更换必须由买家确认且不承诺迁移上游资源。
- 卖家按平台规定区间报价；共享路由按健康、延迟、容量和价格综合评分。
- 优先使用上游明确返回的货币花费；否则按原生 token 用量和版本化费率计算。
- 交易沙盒额度不等同人民币，不可充值、转让、兑换或提现。
- 统一手机号验证入口；每个账户最多一个有效 Web 会话。
- 普通用户使用统一应用壳并切换买家/卖家工作区；管理员后台独立。
- 发布能力目标：500 RPS 短请求、500 条长连接、数据面 99.9% 月可用性、
  RPO 5 分钟、RTO 30 分钟。
- 公开上线前必须通过严格发布门禁和独立渗透测试。

## 从版本文档到实施 Spec

本目录的 `SFxx` 是版本级功能来源文档。真正开始实现某个 SF 时，再在根
`specs/` 中创建一个独立 Spec Kit 功能目录，并建立一对一映射。不得创建覆盖整个
V0.2 的超级 Spec，也不得在一个实现分支中同时混入多个无关 SF。
