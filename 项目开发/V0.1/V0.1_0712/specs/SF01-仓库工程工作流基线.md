# Feature Specification: SF01 仓库工程工作流基线

**Feature ID**: `SF01`  
**Short Name**: `repository-workflow-baseline`  
**Created**: 2026-07-13  
**Status**: Draft  
**Source**: 周度 Spec F01、工程宪章、项目架构与 DevOps 规范

## 目标与价值

建立 TokenMarket 的最小可复现工程基线，使开发者无需记忆各组件内部命令，就能从仓库根目录完成启动、停止、格式化、静态检查、测试、构建和数据库迁移。该功能只交付工程骨架与稳定工作流，不实现注册、Key 管理或代理业务。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用统一入口完成日常开发 (Priority: P1)

作为开发者，我希望所有常用动作都能从仓库根目录通过一致的命令执行，以便快速进入开发并减少误操作。

**Why this priority**: 后续所有功能都依赖稳定、可重复的开发入口。

**Independent Test**: 在全新检出的仓库中查看帮助并依次运行格式化、静态检查、测试和构建入口，验证无需进入子目录手工拼接命令。

**Acceptance Scenarios**:

1. **Given** 仓库依赖已安装，**When** 开发者在根目录执行标准命令，**Then** 命令按组件顺序执行并返回统一的成功或失败状态。
2. **Given** 任一组件检查失败，**When** 根命令执行到该组件，**Then** 整体以非零状态退出，并明确指出失败组件和动作。
3. **Given** 开发者不知道可用命令，**When** 查看根目录帮助，**Then** 能看到每个标准入口的用途和必要前置条件。

---

### User Story 2 - 在清晰边界内新增组件代码 (Priority: P2)

作为开发者，我希望仓库目录直接表达服务所有权，避免把代理流量、领域规则和运维文件混在一起。

**Why this priority**: 明确边界可以减少跨服务耦合和后续迁移成本。

**Independent Test**: 对照目录契约检查网关、领域服务、前端、共享契约、基础设施和运维目录是否存在且职责说明完整。

**Acceptance Scenarios**:

1. **Given** 仓库工程基线已建立，**When** 开发者定位代理网关、API 服务或共享契约，**Then** 能在约定的唯一目录中找到对应入口。
2. **Given** 新增跨服务接口，**When** 进行结构检查，**Then** 接口契约先出现在共享契约区，而不是复制到多个服务内部。

---

### User Story 3 - 安全地准备环境配置 (Priority: P2)

作为开发者，我希望配置项有完整示例且不会把真实凭证提交到仓库。

**Independent Test**: 从安全示例生成本地配置，验证必需项可发现，且仓库扫描不包含真实密钥或 `.env.*` 实例文件。

**Acceptance Scenarios**:

1. **Given** 开发者首次配置项目，**When** 阅读配置示例，**Then** 每个必需变量都有用途说明和安全占位值。
2. **Given** 本地配置包含真实值，**When** 检查版本控制状态，**Then** 该文件被忽略且不会进入提交范围。

### Edge Cases

- 某一语言工具链未安装或版本不满足约束时，入口必须在执行组件任务前给出明确错误。
- 某组件尚未落地时，根命令必须显式说明“未实现/未配置”，不得静默跳过并报告全绿。
- 重复执行格式化、构建或初始化命令时，结果应稳定，不产生无关文件漂移。
- 从带空格或中文路径的工作区执行命令时，不应依赖未经引用的相对路径。
- 工作区存在用户未提交改动时，工作流不得自动清理、覆盖或重置这些改动。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 仓库 MUST 按 `services/proxy-gateway/`、`services/api-service/`、`services/billing-service/`、`services/admin-service/`、`frontend/`、`shared/`、`infra/` 和 `ops/` 表达组件边界。
- **FR-002**: 根工作流 MUST 提供 `make dev`、`make dev-down`、`make test`、`make lint`、`make fmt`、`make build` 和 `make migrate` 稳定入口。
- **FR-003**: 根工作流 MUST 汇总各受影响组件的退出状态；任何必需步骤失败时整体 MUST 失败。
- **FR-004**: 每个入口 MUST 有帮助文本，说明用途、前置条件、是否修改状态及常见失败处理。
- **FR-005**: 现有标准入口能够覆盖的动作 MUST 通过扩展该入口实现，不得新增功能重复的一次性脚本。
- **FR-006**: 仓库 MUST 提交带注释的 `.env.example`，并忽略 `.env.dev`、`.env.test`、`.env.prod`、`.env.local` 及其他真实配置文件。
- **FR-007**: 配置示例 MUST 只包含不可用的安全占位符；不得包含提供商 Key、数据库密码、令牌或生产地址。
- **FR-008**: 各组件 MUST 使用受版本约束的工具链和提交的依赖锁文件；同一提交在本地和 CI 使用同一入口。
- **FR-009**: HTTP 与事件契约 MUST 在消费者实现前放入 `shared/` 的版本化位置，并标明所有者和兼容规则。
- **FR-010**: 根 README 或等价开发文档 MUST 给出从检出仓库到首次验证成功的最短路径。

### Engineering Requirements *(mandatory)*

- **ER-001 — Contracts**: Make 目标名称、退出码和副作用属于开发者契约；变更目标语义时必须同步文档和 CI。
- **ER-002 — Security & Privacy**: 提交前检查必须覆盖敏感信息扫描；生产必需安全配置缺失时不得使用弱默认值继续运行。
- **ER-003 — Data Integrity**: 数据结构变更只能经评审迁移入口执行；应用启动不得隐式修改生产 Schema。
- **ER-004 — Performance & Capacity**: 在依赖缓存有效的普通开发机上，非测试类入口的启动开销应可接受且不重复安装全部依赖；具体基线在计划阶段记录。
- **ER-005 — Reliability**: 命令必须可重复执行；中途失败后再次执行不得依赖手工删除未知状态。
- **ER-006 — Observability**: 每个入口必须输出当前动作和失败组件，但不得输出环境变量值或凭证。
- **ER-007 — Accessibility**: 本功能无图形界面；命令帮助必须使用纯文本可读输出，不仅依赖颜色表达状态。

### Failure and Recovery Scenarios *(mandatory)*

1. **Given** 某组件依赖缺失，**When** 根工作流执行，**Then** 在修改持久状态前失败，指出安装或版本要求，修复后可直接重试。
2. **Given** 测试或构建在中途失败，**When** 开发者重新运行，**Then** 已生成缓存可安全复用，最终结果不受上次半成品影响。
3. **Given** 数据库迁移失败或需要回退，**When** 执行恢复流程，**Then** 使用已评审迁移的 backout 指令恢复，不修改已应用迁移文件。

### Key Entities

- **Workflow Command**: 根目录公开的开发动作；关键属性为名称、用途、前置条件、子任务、退出状态和副作用。
- **Component Boundary**: 一个可独立检查和构建的仓库组件；具有明确所有者、依赖方向和测试根目录。
- **Configuration Definition**: 可提交的配置名称、用途、类型和安全默认；不包含任何环境真实值。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新开发者可在 15 分钟内从仓库帮助定位并执行全部标准入口，无需查找组件私有命令。
- **SC-002**: 100% 标准入口在失败时返回非零状态并指出失败组件，不存在静默失败。
- **SC-003**: 同一提交在本地与 CI 使用相同根入口，连续两次执行不产生非预期版本控制差异。
- **SC-004**: 仓库敏感信息扫描对已知配置示例零告警，且不存在被跟踪的 `.env.*` 真实配置。
- **SC-005**: 目录与契约结构检查能够检测缺失的必需组件目录、错误依赖方向和未版本化共享契约。

## Scope

### In Scope

- Monorepo 目录骨架、根工作流、配置示例、忽略规则、开发说明和组件级入口聚合。

### Out of Scope

- 业务接口、云部署流水线、Kubernetes、真实生产密钥、自动发布和任何前端页面。

## Test Requirements

- 结构测试验证必需目录、契约位置、忽略规则和帮助文本。
- 命令冒烟测试验证成功、组件失败、工具链缺失和重复执行。
- CI 契约测试验证 CI 调用的目标与本地文档一致。
- 安全测试验证配置示例和命令输出不含凭证。

## Assumptions

- 直接依赖：无；SF02 在此基线上提供具体本地中间件。
- 根 Makefile 是唯一对开发者承诺的工作流入口。
- 工具链版本和组件职责以工程宪章为准；替换技术或服务职责需要 ADR。
