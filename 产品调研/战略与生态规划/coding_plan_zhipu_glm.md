### 1.2 额度机制（双限额 + 倍率）

#### 1.2.1 请求次数配额（官方预估值）

| 套餐 | 每5小时限额 | 每周限额 | 每月估算（按4.3周） |

#### 1.2.2 Token配额（社区测算，非官方直接披露）

| 套餐 | 每5小时限额 | 每周限额 | 每月估算 |

> **来源**：基于社区60组后台数据差值计算，仅使用GLM-5.1时的精确数字。平均1 prompt ≈ 25万Token。

#### 1.2.3 模型消耗倍率（核心规则）

| 时段 | GLM-4.7 | GLM-5.2/GLM-5-Turbo |
|------|---------|---------------------|
| 非高峰期（00:00-14:00, 18:00-24:00） | 1倍 | **1倍**（限时福利至2026-09-30） |
| 高峰期（14:00-18:00 UTC+8） | 1倍 | **3倍** |

> **关键影响**：高峰期使用GLM-5.2，Max套餐一周实际可用约10亿Token（非高峰4亿+高峰翻倍消耗），而非理论上的20亿。

#### 1.2.4 重置与过期机制

| 维度 | 规则 |
|------|------|
| **重置周期** | 每5小时滚动窗口（动态刷新，从请求消耗起算5小时后重置）+ 每周7天周期（自下单时开启） |
| **Rollover** | ❌ **不支持**。未用完额度不累积到下期，每5h/每周清零重置 |
| **过期机制** | 套餐本身按月/季/年有效期；额度周期内未用完即作废 |
| **超额后** | 等待下一个5小时/每周周期恢复额度；**不会**自动扣除账户余额或资源包（仅限支持的编码工具内使用） |
| **退款政策** | 订阅服务一经购买即视为确认，**不支持退款**（2026年2月特殊事件期间曾开放Lite/Pro退款通道） |

> **重要限制**：套餐仅限在官方支持的指定工具（Claude Code、Cline、OpenCode、TRAE等20+款）中使用。通过API直接调用、自建应用等场景**单独计费**，不消耗Coding Plan额度。

### 1.3 浪费可能性评估

#### 1.3.1 实际使用率分析

| 用户类型 | 典型使用模式 | 浪费风险 |
|----------|-------------|----------|
| **学生/初学者** | 低频学习、小型作业 | **中高**——Lite套餐每周400 prompts对轻度使用已充足，但双限额机制下容易"用不完"或"不够用" |
| **个人开发者（兼职）** | 间歇性项目、周末集中开发 | **高**——项目空闲期额度完全浪费，高峰期又可能触发限额 |
| **全职开发者** | 每日高频使用 | **低**——Pro/Max用户通常能用完额度，但需规避高峰期3倍消耗 |
| **Agent工作流用户** | 自动化长任务 | **极高**——长上下文+多轮调用快速耗尽限额，非高峰期策略性使用至关重要 |

#### 1.3.2 社区浪费抱怨（实证）

- **"消耗变快"**：2026年2月GLM-5发布后，大量老用户反馈同样使用习惯下额度消耗明显加速。智谱官方解释称GLM-5参数规模是GLM-4.7的两倍以上，高峰期3倍/非高峰2倍倍率导致。
- **"用不完月底清零"**：因每5小时+每周双限额机制，用户无法将空闲时段额度累积到高频时段使用。Lite用户尤其抱怨"平时用不完，周末不够用"。
- **模型循环浪费**：有用户反馈模型陷入循环无法正常输出，但仍消耗Token额度，造成"白白浪费"。
- **规则不透明**：2026年2月事件前，看板1小时刷新一次，用户无法实时感知额度消耗；倍率规则未在购买页显著展示。
- **抢购焦虑**：Max套餐每日仅开放约20%库存，10:00刷新后秒售罄，导致用户被迫购买更高或更低档位，进一步错配需求。

#### 1.3.3 浪费根源

1. **双限额机制**：5小时滚动窗口天然适配"均匀分布"使用，但开发者实际工作模式是项目制、间歇性、集中爆发。
2. **高峰期惩罚**：14:00-18:00是工作核心时段，3倍消耗迫使用户改变工作节奏，否则快速耗尽。
3. **不支持Rollover**：未使用额度无法跨周期累积，也无法转让或共享。
4. **套餐与API割裂**：套餐额度仅限编码工具，API调用另计费，用户易误操作导致双重支出。

### 2.2 额度机制

| 维度 | 规则 |
|------|------|
| **席位起购** | 2席位起，无上限 |
| **额度共享** | ❌ **按席位独立限制**，非团队池化共享。一个成员超限不影响其他成员，但也无法共享闲置额度 |
| **超额后** | 可选开启"超额按量付费"，按API刊例价**9折**计费；支持按成员设置消耗上限 |
| **并发建议** | 标准版1-2项目，高级版2+项目；低峰期动态提升并发 |
| **MCP额度** | 联网搜索+网页读取+开源仓库MCP共享月度次数；视觉理解MCP与模型额度共享5h/周限额 |
| **管理员席位** | 主管理员默认不占用席位，可自分配席位使用额度 |

### 2.3 企业级特性

- **组织席位与权限统一管理**：支持角色分配、人员变动追踪
- **团队用量与研发效能监测**：按成员/时间周期追踪消耗趋势
- **集中式账单与发票**：企业专票、统一对账
- **IP白名单管控**：仅允许指定IP访问，确保工作用途
- **数据不用于模型训练**：保护企业核心研发资产
- **首发接入最新旗舰模型**（限高级版）
- **高峰期专属资源优先保障**（限高级版）

### 2.4 团队版浪费评估

- **席位独立限制 = 闲置浪费**：A成员用不完，B成员超限，无法调剂。对于中小型团队（3-8人），这种"各自为政"的配额设计导致整体利用率下降。
- **无池化机制**：与GitHub Copilot Business/Enterprise的"组织共享额度池"形成对比，智谱团队版缺乏弹性。
- **建议改进**：企业需精细评估每个成员的用量曲线，避免为低频使用者购买全额席位。

## 六、商业模式特点分析

### 6.1 模式类型：混合订阅+按量+私有化

| 模式 | 产品 | 占比（收入贡献） |
|------|------|------------------|
| **固定订阅** | GLM Coding Plan（个人/团队） | C端/MaaS主要形式 |
| **按量付费** | GLM API（标准OpenAI兼容接口） | 开发者灵活调用 |
| **预付费资源包** | 模型资源包（官网提及但细节未公开） | 企业批量采购 |
| **私有化部署** | 本地/云端私有化、软硬一体机 | **B端收入主体（73.7%）** |

### 6.2 与典型模式的对比

| 特征 | 智谱GLM | 阿里云百炼Token Plan | GitHub Copilot |
|------|---------|----------------------|----------------|
| **订阅类型** | 固定订阅+严格限额 | 固定订阅+Credits池 | 订阅+按量混合（2026.6起全面AI Credits） |
| **Rollover** | ❌ 不支持 | ❌ 不支持 | 部分支持（企业版共享池） |
| **超额后** | 等待周期重置 | 自动暂停/降速 | 按量扣费/降速 |
| **团队池化** | ❌ 席位独立 | ✅ Credits共享 | ✅ 组织共享额度池 |
| **节省计划** | ❌ 无 | ✅ 有（承诺消费折扣） | ❌ 无 |
| **免费层** | 2000万Token+Flash免费 | 100万Token/模型×3月 | Copilot Free有限功能 |
| **退款政策** | 严格（特殊事件除外） | 未明确 | 较灵活 |

### 6.3 关键商业特征

1. **"量价齐升"策略**：2026年2月涨价30%+后，API调用量仍增长400%，证明定价权在握
2. **抢购稀缺性**：Max套餐每日限量发售，人为制造稀缺，提升 perceived value
3. **分层模型消耗倍率**：通过"高峰期3倍"机制，在不改变名义价格的前提下实现动态定价
4. **工具生态锁定**：支持20+编码工具，但仅限指定工具使用套餐额度，增强生态粘性
5. **免费漏斗设计**：CodeGeeX免费插件 + 2000万Token + Flash免费模型 → 逐步引导至付费订阅
6. **B端为锚、C端为矛**：73.7%收入来自B端私有化，但C端Coding Plan是品牌声量和生态入口
