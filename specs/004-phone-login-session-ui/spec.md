**Feature Branch**: `004-phone-login-session-ui`

**Created**: 2026-07-25

**Status**: Draft

**Source Spec**: `项目开发/V0.1/V0.1_0712/specs/SF04-手机号验证登录与会话签发.md`（SF04）；本规格保留其安全登录与会话目标，并将原“V0.1 无前端”边界修订为可交付的登录与会话基础界面。

## 目标与价值

为已注册用户提供经过手机号所有权验证的登录、受保护访问和当前会话退出能力，替代“仅提交手机号即可登录”的不安全做法；同时把已有应用壳层扩展为可操作的登录界面和会话感知界面，让用户能完成“找到登录入口 → 获取并提交验证码 → 进入受保护区域 → 刷新后保持有效会话 → 安全退出”的完整旅程。

本功能为后续买家代理 Key、卖家 Key 和账单等受保护能力建立可信认证上下文，但不实现这些业务工作台。

## Clarifications

### Session 2026-07-25

- Q: 浏览器如何持有会话凭证？ → A: 服务端通过 `HttpOnly + Secure + SameSite` Cookie 交付，前端脚本不可读取，并对状态变更请求实施 CSRF 防护。
- Q: 同一用户可以同时拥有多少个有效会话？ → A: 每个用户仅允许一个 active 会话；新登录成功时立即撤销该用户的所有旧会话。
- Q: 重复的“获取验证码”请求应如何处理？ → A: 使用幂等键；同键同手机号在 60 秒内重放首次结果且不重复发送，同键不同手机号返回冲突。
- Q: 验证码频率限制中的“来源”具体指什么？ → A: 来源为通过可信代理链解析出的客户端公网 IP，与规范化手机号分别计数。
- Q: 一次性验证码采用什么格式？ → A: 使用均匀随机生成的 6 位十进制数字，允许且保留前导零。
- Q: 短信投递失败如何同时满足防枚举？ → A: 仅 provider-wide 故障统一返回暂时失败；单个号码的 reject/timeout/unknown 对外保持中性受理，但内部不保留可用挑战且不得声称已发送。
- Q: 首次可部署 MVP 必须包含哪些会话能力？ → A: 必须同时包含 US1、US2 和完整 US3；登录、防滥用、会话识别、替换、恢复与退出作为一个可部署认证闭环交付。
- Q: 如何消除 active 与不可登录账户的响应时序差异？ → A: 对所有合法手机号先持久化请求并快速返回统一 202；由 API Service 内部的持久化 dispatcher 异步处理 eligible challenge 投递，请求线程不等待 recipient-specific 供应商结果。
- Q: 统一 202 响应采用什么可测时延标准？ → A: active、未知、suspended、deleted 每类 100 次请求的 p95 均不超过 500ms，任意两类 p95 差值不超过 100ms。
- Q: 认证数据清理由什么机制按时触发？ → A: 测试和生产环境由部署平台定时调用 API Service 的一次性清理命令，通过数据库锁确保单一执行者，并对执行失败或逾期未运行告警；本地环境仅手动执行。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过界面验证手机号并登录 (Priority: P1)

作为已注册用户，我希望在登录页获取并提交一次性验证码，以便在不使用密码的情况下安全进入平台。

**Why this priority**: 经手机号所有权验证的登录是所有后续受保护功能的入口，也是本功能最核心的用户价值。

**Independent Test**: 使用 active 合成账户进入登录页，输入已注册手机号，获取并提交正确验证码；验证界面进入已登录状态、只建立一个会话，并可访问受保护占位页。

**Acceptance Scenarios**:

1. **Given** 未登录访客位于应用壳层，**When** 通过主导航或显式链接进入登录页，**Then** 页面展示手机号输入、获取验证码动作、验证码输入、登录动作以及前往注册页的入口。
2. **Given** 用户提交格式合法的手机号，**When** 请求通过防滥用检查并持久化待处理 challenge，**Then** 页面进入不证明账户存在或实际送达的中性受理状态，显示脱敏手机号和 60 秒再次获取倒计时；eligible challenge 由 API Service dispatcher 异步投递。
2a. **Given** 首次验证码请求的响应丢失，**When** 客户端在 60 秒内使用相同幂等键和手机号重试，**Then** 获得首次结果且不重复创建挑战或发送短信。
3. **Given** 最新验证码挑战未过期且验证码正确，**When** 用户提交验证，**Then** 挑战只被消费一次、建立一个 60 分钟有效会话、撤销该用户所有旧会话，界面进入已登录状态并按原始目标进入受保护页面。
4. **Given** 用户直接从登录入口开始且没有原始受保护目标，**When** 登录成功，**Then** 用户进入基础受保护首页占位，而不是停留在验证码表单。

### User Story 2 - 拒绝无效、滥用或重放的登录尝试 (Priority: P1)

作为账户所有者，我希望错误、过期、旧版或重复使用的验证码不能建立会话，并且频繁发送与暴力猜测受到限制。

**Why this priority**: 验证码是唯一登录因子；若挑战可猜测、可重放或可无限请求，后续所有授权能力都不可信。

**Independent Test**: 分别提交错误、过期、旧挑战和已使用验证码，并覆盖第 5 次失败、频繁获取、未知手机号、停用账户及 100 个并发正确提交；验证未授权场景建立会话数为零，并发正确提交最多成功一次。

**Acceptance Scenarios**:

1. **Given** 验证码错误、过期、属于更早挑战或已经使用，**When** 用户提交验证，**Then** 登录失败且不建立会话，界面给出“重试”或“重新获取”类型的可行动提示。
2. **Given** 单个挑战已连续失败 5 次，**When** 再次提交任何验证码，**Then** 挑战失效，用户必须重新获取验证码。
3. **Given** 同一手机号或来源已达到获取验证码频率上限，**When** 再次请求，**Then** 请求被拒绝且界面展示中性稍后重试提示，不泄露账户是否存在。
4. **Given** 手机号未知或账户为 suspended / deleted，**When** 请求验证码，**Then** 对外响应的形状、状态和文案不透露账户状态，也不建立可用挑战或会话；安全事件仍可被内部审计。
5. **Given** 同一正确验证码被 100 个请求并发提交，**When** 系统处理验证，**Then** 最多一个请求建立会话，其余均判定挑战不可再用。

### User Story 3 - 维持、识别并安全结束会话 (Priority: P1)

作为已登录用户，我希望页面刷新后仍能识别尚未过期的会话，并能主动退出，使当前会话不能继续访问受保护能力。

**Why this priority**: 只有可恢复、可撤销且状态明确的会话，登录能力才形成可部署闭环；本故事与 US1、US2 同属首次可部署认证增量。

**Independent Test**: 登录后刷新页面、访问受保护占位页、执行退出并重放退出动作；验证有效会话可恢复、退出立即拒绝后续访问、重复退出不会产生错误状态。

**Acceptance Scenarios**:

1. **Given** 浏览器持有尚未过期且未撤销的会话，**When** 刷新应用或重新进入，**Then** 界面恢复已登录状态，无需再次输入验证码。
2. **Given** 用户持有有效会话，**When** 访问受保护占位页，**Then** 页面展示脱敏身份与角色信息，不信任用户自行提交的身份标识。
3. **Given** 用户执行退出，**When** 退出完成，**Then** 当前会话立即撤销、界面清除已登录状态并返回公共入口，后续受保护访问被拒绝。
4. **Given** 相同退出动作被重复提交，**When** 系统再次处理，**Then** 仍返回安全成功结果，不产生新的会话或额外副作用。
5. **Given** 会话已过期、被撤销或账户已停用，**When** 用户刷新或访问受保护页面，**Then** 界面清除过期状态并引导重新登录，不展示受保护内容。
6. **Given** 用户已在设备 A 登录，**When** 同一用户在设备 B 登录成功，**Then** 设备 A 的旧会话在 1 秒内失效，设备 B 成为唯一有效会话。

### User Story 4 - 使用一致且可访问的基础认证界面 (Priority: P2)

作为访客或已登录用户，我希望应用壳层清楚呈现注册、登录、当前身份和退出入口，并在不同设备与错误状态下保持可操作。

**Why this priority**: 用户要求本分支搭建基本 UI；一致的会话导航与可访问交互能成为后续业务页面的稳定基础。

**Independent Test**: 分别以未登录和已登录状态访问根路径、登录页、注册页与受保护占位页；在 320 像素宽视口和仅键盘条件下完成获取验证码、登录和退出，验证无白屏、焦点丢失或横向滚动阻断。

**Acceptance Scenarios**:

1. **Given** 用户未登录，**When** 浏览任一公共页面，**Then** 壳层提供可发现的“注册”和“登录”入口，不显示伪造的已登录信息。
2. **Given** 用户已登录，**When** 浏览应用，**Then** 壳层显示脱敏身份、角色、受保护入口和退出动作，并隐藏重复登录主入口。
3. **Given** 用户只使用键盘和辅助技术，**When** 获取验证码、提交登录或处理错误，**Then** 焦点顺序合理，标签、倒计时、忙碌态和错误信息可被正确识别。
4. **Given** 用户在窄屏设备访问认证页面，**When** 完成主流程，**Then** 所有输入和主要动作均可见、可触达，不需横向滚动才能继续。

### Edge Cases

- 手机号包含空格、`+86` / `86` 前缀或全角数字但可规范为同一中国大陆 11 位号码。
- 非大陆号码、错误位数或无法规范化的输入不得进入账户存在性判断。
- 用户在 60 秒倒计时结束前刷新页面或打开多个标签页并重复请求验证码。
- 同一手机号在允许再次发送后获得新挑战；旧挑战即使未自然过期也不得再用于登录。
- dispatcher 调用验证码投递方时发生超时、明确拒绝、返回受理后用户未收到，或重复返回结果。
- provider-wide 故障与单个号码的 reject/timeout/unknown 必须采用不同内部分类，但后者不得形成可枚举的公开差异或可用挑战。
- API Service 在持久化待处理 challenge 后、dispatcher 调用供应商前崩溃或重启。
- 用户连续点击获取或登录动作，或网络恢复时重复送达同一请求。
- 相同验证码请求幂等键被用于不同的规范化手机号时，必须返回冲突且不得发送短信或创建挑战。
- 挑战即将过期时，验证请求与过期判断同时发生。
- 两个实例同时消费同一正确验证码。
- 登录成功响应丢失，但挑战已被消费且会话已建立。
- 会话签发后账户立即被停用，或当前会话在另一路径被撤销。
- 同一用户从两个设备并发完成登录时，只能保留一个最终 active 会话，较早成功的会话不得恢复有效。
- 服务进程或临时加速层重启后，挑战消费与会话撤销事实不能倒退。
- 用户从受保护深层路径被引导登录，登录成功后原始目标已经不存在或无权访问。
- 合成验证码或测试投递方式被误配置到生产环境。
- 浏览器时钟明显偏差时，安全有效期仍以可信服务端时间为准。
- 客户端伪造或追加转发头时，未经信任代理提供的值不得改变限流使用的客户端公网 IP。
- 验证码以 `0` 开头、包含不足或超过 6 位数字、字母、符号、全角数字或内部空白。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 应用 MUST 提供稳定且可导航的登录页，包含手机号、验证码、获取验证码、提交登录以及前往注册页的入口。
- **FR-002**: 手机号 MUST 在服务端按既有注册契约规范化；V0.1 仅接受可规范为 `1[3-9]\d{9}` 的中国大陆 11 位号码，并至少处理空白、全角数字和可选 `+86` / `86` 前缀。
- **FR-003**: 手机号格式校验失败 MUST 返回字段级错误，不得执行账户查找或验证码投递。
- **FR-004**: 对格式合法的验证码请求，系统 MUST 在持久化幂等结果与待处理 challenge 后、调用 recipient-specific 短信投递前返回统一 HTTP 202；外部结果不得通过状态、业务码、响应时长目标或文案区分 active、未知、suspended 与 deleted 账户。正常验收环境中每类账户 100 次请求的 p95 必须 ≤500ms，任意两类 p95 差值必须 ≤100ms。
- **FR-005**: 系统 MUST 仅为 active 已注册账户创建可验证挑战；未知、suspended 或 deleted 账户不得获得可建立会话的挑战。
- **FR-006**: 每个可用验证码 MUST 使用均匀安全随机方式生成 6 位十进制数字，有效期为 5 分钟；前导零属于验证码内容并必须保留，保存和审计的数据不得包含可直接使用的验证码明文。
- **FR-006a**: 验证提交 MUST 只接受恰好 6 位 ASCII 十进制数字；不足或超过 6 位、字母、符号、全角数字及内部空白均作为字段格式错误处理且不消耗挑战失败次数，格式合法但值不匹配才计入最多 5 次失败验证。
- **FR-007**: 同一手机号成功创建新挑战后，此前所有未消费挑战 MUST 立即失效；验证码仅能用于其所属的最新挑战。
- **FR-008**: 同一规范化手机号 60 秒内 MUST 最多成功发起一次验证码投递；默认每个手机号每小时最多 5 次、每个客户端公网 IP 每小时最多 20 次，两个维度分别计数，任一维度超限即拒绝。
- **FR-008a**: 每次获取验证码操作 MUST 携带客户端生成的幂等键；自首次受理起 60 秒内，相同幂等键与相同规范化手机号的重放必须返回首次确定结果，且不得重复创建挑战、发送短信或重复累计业务尝试。
- **FR-008b**: 60 秒幂等窗口内，相同幂等键用于不同规范化手机号 MUST 返回确定冲突且不产生投递；窗口结束后旧键失效，新的获取操作 MUST 使用新幂等键。
- **FR-008c**: 客户端公网 IP MUST 从受控的可信代理链解析；只有由已配置可信代理添加的转发信息可被采用，直接客户端或非可信代理提供的转发头不得覆盖实际网络来源。无法安全解析时 MUST 使用最接近服务端的可验证网络来源或拒绝请求，不得跳过 IP 维度限流。
- **FR-009**: 单个挑战 MUST 最多允许 5 次失败验证；成功消费或达到失败上限后立即不可再次使用。
- **FR-010**: 验证码消费 MUST 保证原子性；并发提交同一正确验证码时最多一个请求成功建立会话。
- **FR-011**: 只有 active 账户通过当前有效挑战后才能建立会话；客户端提供的用户标识、角色或账户状态不得作为认证依据。
- **FR-011a**: 每个用户 MUST 最多存在一个 active 会话；新登录成功必须在新会话可用前原子撤销该用户所有旧会话，并发登录完成后也只能保留一个最终 active 会话。
- **FR-012**: 每个会话 MUST 具有不可变会话标识，并关联用户、角色、签发时间、过期时间、撤销时间和当前状态；默认有效期为 60 分钟。
- **FR-012a**: 浏览器会话凭证 MUST 仅由服务端通过 `HttpOnly + Secure + SameSite` Cookie 交付，不得出现在登录响应正文中，也不得暴露给前端脚本、`localStorage`、`sessionStorage` 或其他脚本可读的持久存储。
- **FR-013**: 每次受保护访问 MUST 校验凭证真实性、有效期、会话撤销状态和当前账户状态；任一校验失败均不得返回受保护内容。
- **FR-013a**: 所有依赖浏览器 Cookie 身份的状态变更请求 MUST 校验可信来源和服务端认可的 CSRF 防护材料；仅配置 `SameSite` 不得作为唯一的 CSRF 防线，校验失败不得产生业务状态变化。
- **FR-014**: 当前会话退出 MUST 可重复安全执行；首次成功退出立即撤销会话，后续相同退出不得创建额外状态或泄露内部差异。
- **FR-015**: 登出撤销 MUST 在 1 秒内对所有新发起的受保护请求生效。
- **FR-016**: 本地和自动化测试 MAY 使用合成验证码投递；生产环境若未配置获批准的真实投递方式，认证能力 MUST 拒绝启动或保持不可用，不得回退到合成验证码。
- **FR-017**: 验证码、完整手机号、访问凭证和可用于重放的会话校验材料 MUST NOT 出现在 URL、页面可见调试信息、日志、错误、指标、分析数据或测试产物中。
- **FR-018**: 验证码请求、验证码验证、会话识别和退出结果 MUST 使用稳定、版本化且可机读的业务契约，包含结果码、用户可理解消息和请求标识。
- **FR-019**: 登录页 MUST 明确呈现空闲、请求中、请求已中性受理、60 秒倒计时、验证中、成功、字段错误、验证码错误/过期、限流和服务暂不可用状态；公开流程不得声称验证码已发送或展示 recipient-specific 投递结果，请求进行中不得因重复点击产生额外业务动作。
- **FR-020**: 登录页对未知、suspended 或 deleted 账户 MUST 使用相同中性流程和提示，不得在界面中暴露账户是否存在或具体状态。
- **FR-021**: 登录成功后，应用 MUST 恢复用户原本试图访问且仍允许访问的受保护路径；无原始目标或目标无效时进入基础受保护首页占位。
- **FR-022**: 有效会话 MUST 能在正常页面刷新后恢复；过期、撤销或账户不可用时，应用 MUST 清除已登录界面状态并引导重新登录。
- **FR-023**: 公共壳层 MUST 在未登录时提供注册与登录入口；已登录时提供脱敏身份、角色、受保护入口与退出动作。
- **FR-024**: 基础受保护首页只用于证明认证与导航闭环，MUST NOT 在本功能内加入买家、卖家、账单、Key 或管理业务行为。
- **FR-025**: 界面 MUST 提供可见标签、字段错误关联、键盘可操作顺序、可识别的忙碌/倒计时/结果状态，并在 320 像素及以上视口保持主流程无需横向滚动。
- **FR-026**: 在账户类别分支前确认的 provider-wide 不可用或配置故障 MUST 对所有格式合法手机号统一返回可重试的暂时失败。单个号码投递的 reject、timeout 或 unknown MUST 清除验证码校验材料并使挑战不可用，但对外仍返回与其他账户类别一致的中性受理结果，且界面不得声称验证码已发送或透露 recipient-specific 结果。
- **FR-026a**: API Service MUST 使用 PostgreSQL 中已提交的 pending challenge 作为 durable dispatch queue，由内部 dispatcher 以并发安全方式领取 eligible work；每个 `provider_request_ref` 最多调用一次 send。进程崩溃或重启后必须恢复未处理 work，无法确认既往调用结果时只能查询状态或作废，禁止自动重发。

### Engineering Requirements *(mandatory)*

- **ER-001 — Contracts**: 请求验证码、验证验证码、识别当前会话和退出的对外契约必须先定义并保持版本兼容；未认证统一为未认证结果，已认证但无业务权限留给后续授权功能处理；前端使用的字段与错误分类必须与契约一致。
- **ER-002 — Security & Privacy**: 认证默认拒绝并由服务端建立身份；挑战须防猜测、防重放、防并发重复消费，登录入口须防账户枚举和暴力尝试；手机号和认证凭证按敏感数据处理，显示时脱敏，保留遵循最小化原则。
- **ER-003 — Data Integrity**: 持久认证记录是挑战消费与会话撤销的事实来源；临时加速数据丢失、进程重启或并发竞争不得令已消费挑战重新可用、已撤销会话恢复有效或同一挑战建立多个会话。
- **ER-004 — Performance & Capacity**: 在正常验收环境中，验证码请求对 active、未知、suspended、deleted 每类 100 次采样的 p95 均 ≤500ms 且任意两类 p95 差值 ≤100ms；不含外部短信投递时间的验证码验证与会话建立，95% 在 500 毫秒内完成；会话识别给受保护操作增加的 95% 延迟不超过 50 毫秒；登录首屏在常规验收设备上 3 秒内可交互，并支持至少 100 个并发验证码验证请求而不破坏单次消费约束。
- **ER-005 — Reliability**: 外部投递必须由 durable dispatcher 使用有界超时，单次调用默认 10 秒内形成内部 accepted/rejected/timeout/unknown 结果；不得盲目自动重试可能重复发送的操作。pending challenge、挑战消费、会话和撤销语义须在进程重启后恢复，认证依赖不可确认时受保护访问须失败关闭。
- **ER-006 — Observability**: 每个认证动作须关联请求标识，并记录脱敏的发送结果、验证成功/失败分类、限流、并发重放、会话撤销和异常失效率；持续 5 分钟认证不可用或失败率异常须触发由认证能力责任团队拥有且有处置说明的告警。
- **ER-007 — Accessibility**: 手机号与验证码字段、倒计时、错误、忙碌态、登录和退出动作须具有可感知名称与状态；仅键盘可完成主流程，焦点在验证失败后移动或保持在可修复位置，文本与主要操作满足常规可读对比度。
- **ER-008 — Retention & Audit**: 可用验证码校验材料在过期后不得继续使用，并在 24 小时内清除；会话记录在过期或撤销后默认保留 90 天用于安全审计后删除或匿名化；安全审计记录默认保留 180 天，任何调整须通过受控的数据保留政策。测试和生产环境 MUST 由部署平台按足以满足上述期限的频率调用 API Service 一次性清理命令；命令 MUST 使用数据库锁确保单一执行者、支持幂等分批重试，并为执行失败、上次成功时间逾期或待清理积压触发责任明确的告警。本地环境仅提供相同命令的手动执行入口，不运行常驻调度循环。

### Failure and Recovery Scenarios *(mandatory)*

1. **Given** provider-wide health 在账户类别分支前被判定为不可用，**When** 任一格式合法手机号请求验证码，**Then** 10 秒内统一返回安全的暂时失败、记录脱敏故障信号，且不创建可用挑战。
1a. **Given** 获取验证码请求已统一返回 202，**When** dispatcher 对单个号码的投递返回 reject、timeout 或 unknown，**Then** 清除验证码校验材料并使挑战不可用，不向浏览器暴露 recipient-specific 结果。
1b. **Given** pending challenge 已提交但 dispatcher 尚未完成，**When** API Service 崩溃或重启，**Then** dispatcher 恢复未处理 work；已经发起但结果未知的调用不得自动重发。
2. **Given** 两个请求同时提交正确验证码，**When** 消费同一挑战，**Then** 只有一个请求建立会话，另一个获得挑战已不可用结果，且不存在重复会话。
3. **Given** 认证进程或临时加速层重启，**When** 恢复挑战或会话校验，**Then** 以持久事实恢复已消费和已撤销状态，任何无法确认的状态均失败关闭。
4. **Given** 会话已经建立但成功响应在到达客户端前中断，**When** 用户再次提交同一验证码，**Then** 不建立第二会话；界面提供重新开始登录的安全路径。
5. **Given** 退出请求结果在到达客户端前中断，**When** 用户重试退出，**Then** 返回安全成功，当前会话保持撤销。
6. **Given** 新版本回退到仍兼容的前一版本，**When** 读取已签发会话或已创建挑战，**Then** 安全有效期和撤销语义保持一致；无法识别的新状态不得被当作有效认证。
7. **Given** 验证码投递已被确认受理但响应未到达客户端，**When** 客户端在 60 秒内以相同幂等键和手机号重试，**Then** 返回首次确定结果，不创建第二个挑战、不重复发送短信，也不将该重放额外计入频率限制。
8. **Given** 测试或生产环境的计划清理执行失败或超过规定窗口未成功，**When** 监控检测到上次成功时间逾期或待清理积压，**Then** 向认证能力责任团队告警；后续一次性命令通过数据库锁以幂等分批方式继续处理，不并发重复清理，也不延长任何认证材料的可用期。

### Key Entities

- **Verification Challenge（验证挑战）**: 代表一次手机号所有权验证机会，并兼作 API Service dispatcher 的 durable delivery work；关联挑战标识、用户或规范化手机号引用、6 位十进制验证码的不可逆校验材料、失败次数、创建/过期时间、`provider_request_ref`、领取租约以及投递与消费状态。由认证域拥有，属于敏感认证数据。不变量：公开 202 必须发生在 pending 状态提交后；只有 eligible 且明确 accepted 的 challenge 可验证；每个 provider request 最多 send 一次；验证码可含前导零，只有最新挑战可用、最多成功消费一次、过期或达到 5 次失败后不可恢复。验证码校验材料过期后 24 小时内清除，安全结果以脱敏审计事件保留。
- **Verification Request Idempotency Record（验证码请求幂等记录）**: 关联幂等键、规范化手机号的不可逆引用、首次确定结果、创建时间和 60 秒失效时间；用于安全恢复响应丢失，不保存验证码或完整手机号。同键异手机号必须冲突；记录在窗口结束后失去重放作用，并在 24 小时内清除。
- **Verification Rate Limit Bucket（验证码限流桶）**: 分别按规范化手机号的不可逆引用和可信代理链解析出的客户端公网 IP 累计小时窗口内的验证码请求；任一维度超限即拒绝。该状态用于防滥用，不是账户或会话事实来源；不得通过未经信任的转发头选择限流桶。
- **Session（会话）**: 代表一次已验证登录；关联不可变会话标识、用户、角色快照、签发/过期/撤销时间和状态。由认证域持久保存并作为撤销事实来源。不变量：只属于一个用户、每个用户最多一个 active 会话、默认 60 分钟有效、撤销不可逆、账户不可用时不得继续授权；新登录使该用户全部旧会话失效。过期或撤销后默认保留 90 天用于安全审计。
- **Access Credential（访问凭证）**: 由服务端通过 `HttpOnly + Secure + SameSite` Cookie 交付给浏览器、用于证明会话的敏感凭证；不得出现在响应正文或任何脚本可读存储中，只暴露验证所需的最少声明，不得保存可直接重放的完整值或展示在界面、URL 与日志中。所有依赖该凭证的状态变更同时受 CSRF 防护。
- **Authentication UI State（认证界面状态）**: 浏览器中当前手机号输入、挑战倒计时、提交状态、错误类别、已登录摘要和原始目标路径；仅用于交互，不是身份事实来源。完整手机号不得写入长期浏览历史或分析数据，退出或会话失效后须清除认证状态。
- **Authentication Security Event（认证安全事件）**: 脱敏记录验证码请求结果、验证失败分类、限流、可疑重放、会话建立和撤销，用于检测与审计；不得包含验证码、访问凭证或完整手机号，默认保留 180 天。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 正确、最新且未过期验证码的首次提交建立且只建立一个会话；错误、过期、旧版或重放验证码建立会话数为零。
- **SC-001a**: `000000`、`012345` 和 `999999` 等全部 6 位数字边界值均按其原始 6 位内容验证；不足或超过 6 位、字母、符号、全角数字及内部空白输入的拒绝率为 100%，且不增加挑战失败次数。
- **SC-002**: 同一验证码 100 个并发提交中最多一个成功，且系统内对应 active 会话增量最多为 1。
- **SC-002a**: 同一用户从两个设备并发完成 100 轮登录后，每轮最终 active 会话数均为 1；新登录成功后 1 秒内，所有旧会话发起的受保护请求拒绝率为 100%。
- **SC-003**: 未培训用户或等价验收脚本可在 3 分钟内从公共首页找到登录入口、获取并提交验证码、进入受保护占位页并完成退出（不计真实短信供应方超出 10 秒的外部延迟）。
- **SC-004**: 95% 验证码验证与登录结果在提交后 1 秒内呈现给用户；95% 登录首屏在 3 秒内可交互。
- **SC-005**: 会话退出后 1 秒内，100% 新发起的受保护请求被拒绝；重复退出 10 次均保持安全成功且不创建新状态。
- **SC-006**: 对 active、未知、suspended 与 deleted 手机号各执行 100 次验证码请求，对外状态、业务码和文案类别无可区分的账户存在性差异；每类请求 p95 均不超过 500ms，任意两类 p95 差值不超过 100ms。
- **SC-007**: 在默认阈值下，同一手机号每小时第 6 次或同一可信客户端公网 IP 每小时第 21 次验证码请求均被拒绝；伪造或追加非可信转发头的 100 次尝试均不能切换 IP 限流桶。
- **SC-007a**: 同一幂等键与手机号在 60 秒内并发重放 100 次时，短信发送数和新挑战数均最多为 1，全部响应保持首次确定结果；任一同键异手机号请求均产生零次投递。
- **SC-008**: 自动化扫描确认响应、界面、日志、指标和测试产物中验证码、完整访问凭证与完整手机号的泄露数为零。
- **SC-009**: 未登录、已过期、已撤销和账户停用四类状态访问受保护占位页的拒绝率均为 100%，且界面均提供可理解的重新登录路径。
- **SC-010**: 在 320 像素及以上视口和仅键盘操作下，获取验证码、登录与退出主流程的任务完成率为 100%，无横向滚动阻断或无法识别的字段错误。
- **SC-011**: 在受控时钟验收中，过期验证码校验材料和验证码请求幂等记录均在 24 小时内清除；测试和生产的清理命令并发触发时只有一个执行者取得数据库锁，模拟执行失败或逾期未运行均产生告警，恢复执行不遗漏或重复破坏记录。

## Assumptions

- 依赖 `003-user-registration-ui` 提供 active 用户、手机号规范化规则、注册页、公共应用壳层和基础导航；本功能在其上增加登录与会话状态，不重复定义注册行为。
- “基本的 UI 界面”解释为登录页、认证状态导航、受保护首页占位、会话恢复与退出闭环，以及必要的加载/成功/错误/空状态；不等同于完整产品工作台或完整视觉设计系统。
- 登录成功后默认进入基础受保护首页；若用户先访问受保护路径，则安全保存并恢复原始站内目标，不接受外部开放重定向地址。
- V0.1 每个用户只允许一个 60 分钟 active 会话，不提供刷新令牌；新登录会使其他设备的旧会话失效，过期后用户重新获取验证码登录。
- 首次可部署 MVP 必须同时完成 US1、US2 与完整 US3；只签发 Cookie 而缺少会话识别、替换、恢复或退出的版本只能作为关闭状态的本地技术预览，不得激活认证入口。
- 浏览器会话使用服务端设置的安全 Cookie；前端只维护脱敏身份摘要和加载状态，不持有或读取访问凭证。
- V0.1 退出只撤销当前会话；“退出所有设备”、会话设备列表和管理员强制全量下线为后续功能。
- V0.1 仅支持中国大陆手机号，并复用注册功能已经确定的规范化契约；国际号码为后续增量。
- 验证码请求的来源限流维度为可信代理链解析出的客户端公网 IP；部署必须显式配置可信代理边界，默认不信任客户端自报的转发头。
- 本地和自动化验收使用合成账户与合成验证码；生产必须使用获批准的真实投递方式。
- dispatcher 属于现有 API Service，不新增长期运行服务；pending work 以 PostgreSQL 为事实源，进程内队列或 Redis 不得成为唯一副本。
- 测试和生产环境复用部署平台的定时调度能力触发 API Service 一次性认证数据清理命令，不新增常驻清理服务；本地开发只保留手动执行入口。
- 短信供应商采购、模板报备、费用结算和送达率运营不在本功能内，但投递适配必须满足本规格的安全失败语义。
- 买家/卖家/管理员的细粒度授权属于 SF05；本功能只建立可信用户与角色认证上下文，不以界面隐藏替代服务端授权。
- 会话记录与认证安全事件复用认证数据责任团队既有备份、恢复和删除流程；本功能不新增独立备份产品能力，但恢复不得使撤销状态倒退。

## Scope

### In Scope

- 手机号验证码请求、投递结果处理、挑战验证、单次消费、防枚举、防暴力与频率限制。
- 60 分钟访问会话签发、服务端会话识别、账户状态校验、当前会话撤销和安全审计。
- 稳定、版本化的验证码、会话识别与退出业务契约。
- 登录页及其手机号、验证码、倒计时、加载、成功、错误和限流状态。
- 公共壳层的登录/注册入口、已登录身份摘要、受保护首页占位、会话恢复和退出交互。
- 认证相关单元、契约、集成、并发重放、安全脱敏、可访问性和关键用户旅程验证。

### Out of Scope

- 密码登录、OAuth、2FA、找回密码、刷新令牌和“记住我”长期会话。
- 多设备会话列表、退出所有设备、管理员会话管理和设备风险评分。
- 账户注册与恢复、手机号变更、实名认证和角色变更。
- SF05 细粒度授权，以及买家、卖家、账单、Key、额度市场和管理业务页面。
- 完整设计系统、主题切换、国际化多语言包、原生移动应用和无障碍正式认证。
- 短信供应商采购、商业合同、模板报备、送达率运营与营销短信。
