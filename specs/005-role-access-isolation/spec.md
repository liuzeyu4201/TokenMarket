# 功能规格：角色授权与自买自卖隔离

**功能分支**: `005-role-access-isolation`

**创建日期**: 2026-08-01

**状态**: 草案

**源规格**: `项目开发/V0.1/V0.1_0712/specs/SF05-角色授权与自买自卖隔离.md`（SF05）；本规格将其角色权限矩阵、资源所有权与自买自卖隔离要求纳入 Spec Kit 可规划、可验收的功能规格。

## 目标与价值

在服务端统一执行买家、卖家和双角色账户的最小权限规则，并用所有权排除规则阻止同一账户的买家流量消费其自己接入的卖家 Key。客户端角色判断仅用于体验，不得替代本功能。

本功能为后续代理路由、卖家 Key 管理与计费等受保护能力建立可信授权边界，防止越权操作、身份伪造和自买自卖导致的统计污染。

## Clarifications

### Session 2026-08-01

- Q: 授权时以谁的角色与账户状态为准？ → A: 每次受保护请求以持久事实源上的当前角色与账户状态做授权；会话仅证明已登录用户身份，不把会话内角色快照当作权限依据。
- Q: 跨用户资源访问失败时对外返回什么？ → A: 不存在与非所有者（含不可见软删）统一返回 404 及稳定、不区分的业务码，对外不可枚举资源是否存在。
- Q: 本功能必须落地的权限矩阵动作范围是什么？ → A: 矩阵绑定声明动作族（买家代理 Key 创建/撤销/使用；卖家 Key 接入/读/改/停用；路由候选自买自卖排除）并提供可测授权执行；完整 Key 产品 API 可由后续功能补齐，但本功能须可用桩/夹具完成 100% 角色×动作组合验收。
- Q: 纯拒绝（无状态变更）时审计写失败怎么办？ → A: 拒绝立即返回；审计至少一次可恢复投递，禁止静默丢弃；状态变更路径仍强制审计（失败则整体失败）。
- Q: 授权通过时是否写审计事件？ → A: 拒绝与敏感管理/状态变更全量审计；高频 use 与成功路由候选排除仅聚合指标、不逐条授权审计。
- Q: （分析收口 I1）纯拒绝与审计落盘顺序？ → A: 先成功提交审计事件或可恢复 pending 意图，再返回业务拒绝（403/404/401）；若意图无法落盘则返回 503，禁止「无证据的业务拒绝」。
- Q: （分析收口 I2）性能成功标准如何分层？ → A: 默认直读路径 P95≤50ms；若启用加速则命中路径 P95≤10ms；任意路径 fail-open=0。
- Q: （分析收口 U1）批量授权是否在 V0.1 范围？ → A: 否；无批量授权 API；单资源决策；若未来批量接口出现则默认全有或全无并独立授权每资源。
- Q: （分析收口 C1）会话已撤销如何表现？ → A: 与无会话/过期相同，对外 `UNAUTHENTICATED`（401），不得进入授权允许路径。

## 用户场景与测试 *(必选)*

### 用户故事 1 - 按角色使用允许的能力 (优先级: P1)

作为已登录用户，我希望账户只能访问与其角色匹配的能力，避免他人伪造身份操作我的资产或凭证。

**优先级理由**: 角色边界是所有受保护业务动作的前置条件；没有可靠授权，后续 Key 管理与代理能力均不可信。

**独立测试**: 使用 `buyer`、`seller`、`both` 三类账户分别调用买家和卖家受保护能力，验证权限矩阵中允许组合成功、禁止组合拒绝。

**验收场景**:

1. **Given** `buyer` 用户已认证，**When** 请求买家代理 Key 能力，**Then** 授权通过；请求卖家原始 Key 管理时返回拒绝（已认证但权限不足）。
2. **Given** `seller` 用户已认证，**When** 管理自己拥有的卖家 Key，**Then** 授权通过；请求买家代理 Key 能力时返回拒绝。
3. **Given** `both` 用户已认证，**When** 分别使用买家或卖家能力，**Then** 两类角色检查均可通过，但仍受资源所有权和自买自卖规则约束。
4. **Given** 客户端请求体携带另一个用户的身份标识，**When** 服务端授权，**Then** 始终采用认证会话身份并拒绝越权资源访问。
5. **Given** 会话已撤销、过期或不存在，**When** 调用受保护授权判定，**Then** 返回未认证结果（与「需重新登录」同类），不得返回角色允许或资源级成功。

---

### 用户故事 2 - 阻止自买自卖路由 (优先级: P1)

作为平台，我希望双角色用户的代理请求永远不会选中该用户自己拥有的卖家 Key，从根源上避免自买自卖和统计污染。

**优先级理由**: 双角色是 V0.1 产品假设；若买家流量可命中本人卖家 Key，会破坏市场公平与计量可信度。

**独立测试**: 构造包含本人和其他卖家 Key 的候选池，验证本人 Key 始终被排除；只有本人 Key 时返回无可用资源。

**验收场景**:

1. **Given** 候选池包含当前买家本人和其他卖家的可用 Key，**When** 生成路由候选集，**Then** 本人拥有的全部 Key 被排除。
2. **Given** 候选池只包含当前买家本人的 Key，**When** 请求路由，**Then** 返回无可用 Key，不允许作为降级选择本人 Key。
3. **Given** 卖家 Key 所有权刚发生变更，**When** 新请求到达，**Then** 授权使用持久事实或已可靠失效的加速副本，不沿用陈旧所有权。

---

### 用户故事 3 - 审计敏感授权结果 (优先级: P2)

作为安全维护者，我希望越权、伪造身份和自路由尝试可追踪，但审计内容不暴露凭证。

**优先级理由**: 可追溯的拒绝与状态变更是安全运营与事后取证的基础；无审计则无法验证授权是否被绕过。

**独立测试**: 触发角色拒绝、所有权拒绝与自路由阻止，查询对应请求标识的审计记录；并确认正常通过路径不落敏感凭证。

**验收场景**:

1. **Given** 请求因角色或所有权被拒绝，**When** 写入审计事件，**Then** 事件包含操作者、动作、资源脱敏标识、原因和请求标识。
2. **Given** 正常高频代理请求通过授权（`use`）或路由候选排除成功完成，**When** 记录遥测，**Then** 仅更新聚合指标，不写逐条授权审计，且不得包含原始 Key 或完整代理 Key。
3. **Given** 敏感管理动作成功（如卖家 Key 接入/停用）并产生状态变更，**When** 提交完成，**Then** 存在对应脱敏审计事件（与 FR-010b 一致）。

---

### 边界情况

- 用户会话中的角色快照与账户当前角色不一致：以事实源当前角色授权；不得因会话仍持有旧角色而放行已撤销能力。
- 用户在请求执行期间被 suspended 或 deleted：授权阶段读取到非 active 状态则拒绝全部受保护动作。
- 会话已撤销或凭证无效：在授权矩阵之前失败为未认证，不区分撤销原因细节。
- 资源标识合法但属于另一用户，或资源已软删除：对外与「不存在」相同，统一 404，不得可枚举。
- 加速副本不可用或所有权加速副本已过期：回源事实；事实不可达则拒绝（非允许）。
- 请求未认证但同时携带伪造的角色和用户标识。
- 角色或所有权变更与正在处理的请求并发发生：单次授权读取一致的事实源快照，不出现同请求内半旧半新角色判定。
- 审计意图无法落盘时：不得返回「看似成功的业务拒绝」；应服务暂时不可用，且状态变更不得提交。

## 需求 *(必选)*

### 功能需求

- **FR-001**: 服务端 MUST 定义并执行默认拒绝的角色权限矩阵；未显式允许的动作一律拒绝。
- **FR-001a**: V0.1 矩阵 MUST 至少包含以下声明动作族，并有可自动化的允许/拒绝验收：
  - 买家代理 Key：`create`、`revoke`、`use`（代表使用代理 Key 发起受保护代理调用的授权判定）
  - 卖家原始 Key：`register`（接入）、`read`、`update`、`disable`（停用/撤销管理侧）
  - 路由候选：`route_candidate_exclude_self`（生成候选时排除本人卖家 Key）
  完整 Key 产品 REST/工作流 API 可由后续功能交付；本功能 MUST 提供授权判定入口与可测执行点（含测试桩/夹具），使 SC-001 不依赖未实现的产品 UI。
- **FR-002**: `buyer` MUST 仅被允许代理 Key 的 `create`/`revoke`/`use`（且仅限本人资源），MUST 拒绝卖家 Key 的 `register`/`read`/`update`/`disable`。
- **FR-003**: `seller` MUST 仅被允许卖家 Key 的 `register`/`read`/`update`/`disable`（且仅限本人资源），MUST 拒绝代理 Key 的 `create`/`revoke`/`use`。
- **FR-004**: `both` MAY 使用买家与卖家声明动作族，但 MUST 同时满足对应动作的资源所有权检查，且 MUST 在 `route_candidate_exclude_self` 上排除本人卖家 Key。
- **FR-005**: 授权身份（用户标识）MUST 来自已验证会话（SF04）；客户端提供的 user_id、seller_id、buyer_id 或 role 不得覆盖认证上下文。
- **FR-005a**: 角色与账户状态 MUST 在每次受保护请求的授权阶段从持久事实源读取当前值；会话内角色/状态快照 MUST NOT 作为权限判断依据。事实源角色与会话快照不一致时，以事实源为准。
- **FR-006**: suspended、deleted（含 `is_deleted`）的账户 MUST 被拒绝所有受保护动作；账户状态判定以事实源当前值为准。
- **FR-006a**: 会话缺失、过期或已撤销时，MUST 在角色/所有权判定之前失败为未认证（稳定码与「需重新登录」同类）；MUST NOT 进入授权允许路径或返回角色/资源级成功。
- **FR-007**: 卖家与买家资源的读写 MUST 校验资源所有者等于当前认证用户。
- **FR-007a**: 对受保护资源的按 ID 读写，当资源不存在、已软删除不可见、或不属于当前用户时，MUST 统一返回 404 与稳定、不区分的业务码；MUST NOT 用 403/404 差异或差异化文案泄露「该 ID 是否存在于系统」。角色不足（有权访问该类资源但角色不允许该动作）仍按 ER-001 返回 403。
- **FR-008**: 路由候选生成 MUST 排除「卖家所有者等于当前买家」的全部 Key，且不得在无其他候选时降级绕过。
- **FR-009**: 角色、账户状态和所有权变更 MUST 在新请求上立即或在明确小于 1 秒的失效窗口内生效。
- **FR-010**: 下列决策 MUST 形成脱敏审计事件（全量）：角色拒绝、所有权拒绝、自路由阻止（因仅剩本人 Key 等导致无可用候选的阻止）、账户停用/拒绝，以及敏感管理类状态变更（含成功与失败且产生或试图产生状态变更的路径，成功路径见 FR-010b）。
- **FR-010a**: 对无状态变更的纯拒绝路径，处理顺序 MUST 为：（1）判定为拒绝；（2）在返回调用方之前，将脱敏审计事件或可恢复的 pending 投递意图与请求标识一并成功提交；（3）再返回业务拒绝（403/404 等，未认证为 401）。步骤（2）失败时 MUST 返回服务暂时不可用（fail-closed），MUST NOT 返回无投递证据的业务拒绝，MUST NOT 静默丢弃审计。投递意图已提交后允许异步刷写最终事件（至少一次）。
- **FR-010b**: 对敏感状态变更路径：审计写入与变更提交 MUST 同成败（可恢复补写或整体回滚）；不得在无法满足强制审计时静默成功变更。
- **FR-010c**: 高频授权**通过**路径——代理 Key `use` 允许、以及路由候选生成中成功完成自排除后的继续——MUST NOT 写逐条授权审计事件；MUST 通过按动作与结果（及拒绝原因，如适用）聚合的指标满足可观测性。遥测与审计均 MUST NOT 包含原始 Key 或完整代理 Key。
- **FR-011**: V0.1 **不提供**批量授权 API 或多资源一次提交的部分成功语义。本功能仅定义**单资源/单动作**授权决策。若后续接口引入批量敏感操作，MUST 对每个资源独立授权，且默认全有或全无（除非该接口契约显式支持部分成功）——该批量行为**不在本功能交付范围**。

### 工程需求 *(必选)*

- **ER-001 — 契约**: 未认证（含会话撤销/过期）返回 401；已认证但角色不允许该动作返回 403；按 ID 访问不存在、不可见软删或非所有者资源统一返回 404（与 FR-007a 一致）；审计意图无法落盘返回 503。策略必须在契约中写死且跨接口一致。
- **ER-002 — 安全与隐私**: RBAC 与所有权校验必须位于服务端、默认拒绝；敏感写操作含审计；错误不得披露其他用户资料。只读授权判定（evaluate / exclude-self）重放不改变状态即视为安全；状态变更夹具/写路径复用既有会话写保护（如 Origin/CSRF，属 SF04 边界），本功能不另发明牌重放协议。
- **ER-003 — 数据完整性**: 用户角色、状态和资源所有权以持久事实源为准；加速副本（若启用）只做加速且必须有可靠失效机制。V0.1 可不实现加速层。
- **ER-004 — 性能与容量**: （a）默认直读事实源时，授权判定 P95 小于 50 毫秒；（b）若启用加速且命中，P95 小于 10 毫秒；（c）加速或事实源故障时 fail-open 次数为 0。
- **ER-005 — 可靠性**: 事实源不可达且无法确认权限时必须失败关闭；不得用「允许」作为加速副本错误降级；审计意图无法落盘时不得伪造成功业务拒绝。
- **ER-006 — 可观测性**: 暴露按动作、结果与拒绝原因聚合的授权计数（覆盖允许与拒绝）；强制审计事件携带 correlation/request ID；禁止凭证和完整手机号。
- **ER-007 — 可访问性**: V0.1 本功能无前端界面交付；错误码应稳定区分重新登录、角色不足和资源不可用，便于未来界面提供准确提示。

### 失败与恢复场景 *(必选)*

1. **Given** 权限加速副本不可用，**When** 敏感请求到达，**Then** 回源事实库；事实库也不可用时拒绝请求并记录故障。
2. **Given** 角色变更与请求并发，**When** 请求进入授权阶段，**Then** 从事实源按明确版本读取一致的当前角色（非会话快照），不出现一半按旧角色、一半按新角色的写入。
3. **Given** 审计写入暂时失败，**When** 敏感状态变更准备提交，**Then** 该变更不得在无法满足强制审计的情况下静默成功；使用可恢复机制补写或整体回滚。
4. **Given** 审计事件或 pending 投递意图无法在响应前成功提交，**When** 请求仅为授权拒绝且无状态变更，**Then** 返回服务暂时不可用（非业务 403/404），不得让调用方收到无审计证据的业务拒绝。
5. **Given** 审计事件或 pending 意图已成功提交，**When** 异步刷写尚未完成，**Then** 调用方已收到业务拒绝，且最终可按请求标识查到脱敏审计（或等价投递成功证据）。

### 关键实体

- **Authorization Policy（授权策略）**: 角色、动作、资源类型和条件的默认拒绝规则；版本化并由领域所有者维护。不变量：未列出即拒绝；策略版本随变更可追溯。
- **Resource Ownership（资源所有权）**: 用户与卖家 Key、代理 Key 的所有权关系；以持久层为事实源。分类：业务敏感；变更须可审计。
- **Authorization Audit Event（授权审计事件）**: 操作者、动作、资源脱敏引用、决策、原因、策略版本、时间和请求标识；不可修改且有保留策略。分类：安全审计；不得含凭证明文。

## 成功标准 *(必选)*

### 可度量结果

- **SC-001**: 对 FR-001a 声明动作族，在 `buyer`/`seller`/`both` × 各动作的全部组合上，自动化测试中禁止组合拒绝率 100%、允许组合（且满足所有权时）成功率 100%。
- **SC-002**: 包含本人 Key 的 1000 次路由候选生成中，本人 Key 被选择次数为 0。
- **SC-003**: 角色或账户状态变更后 1 秒内，100% 新请求采用新状态。
- **SC-004a**: 在默认直读（无加速或未命中）配置下，授权判定自动化样本的 P95 不超过 50 毫秒量级目标（记录样本量与环境）。
- **SC-004b**: 若启用加速且命中，命中路径样本 P95 不超过 10 毫秒量级目标。
- **SC-004c**: 加速层故障与事实源故障场景下，fail-open（错误放行）次数为 0。
- **SC-005**: 100% 强制审计范围内的敏感拒绝与状态变更可按请求标识查询到脱敏审计事件；高频 `use`/路由通过路径不要求逐条授权审计，但对应聚合指标可观测。
- **SC-006**: 会话撤销后，100% 受保护授权调用返回未认证类结果，允许成功次数为 0。

## 范围

### 范围内

- 默认拒绝权限矩阵及声明动作族（见 FR-001a）
- 买家、卖家、双角色对声明动作的允许/拒绝执行
- 账户状态（suspended / deleted）与会话无效/撤销对受保护动作的拒绝
- 资源所有权校验（单资源）
- 自路由排除（自买自卖隔离）及可测授权/排除执行点
- 强制范围内的脱敏授权审计（拒绝与敏感管理/状态变更）及高频通过路径的聚合指标
- 用于矩阵 100% 组合验收的测试桩/夹具（若产品 API 尚未齐备）

## 假设

- 依赖 SF03 的角色与状态、SF04 的认证上下文已可用或在本功能集成验收前可用。
- SF13（或等价路由功能）消费本功能产生的「排除卖家 ID」约束；本功能不实现实际轮询算法。
- 当前产品采用 `both + 自路由排除`；若产品改为角色互斥，需先修订父索引和本规格。
- V0.1 本功能不交付前端界面；错误语义需对未来客户端友好。
- 「加速副本」指可选的只读加速层；持久事实源始终是权威来源；首版可不实现加速。
- `proxy_key.revoke` 将资源生命周期置于 `disabled`（非 `soft_deleted`），除非后续 Key 产品契约另有规定。
