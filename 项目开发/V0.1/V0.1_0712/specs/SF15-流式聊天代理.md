# Feature Specification: SF15 流式聊天代理

**Feature ID**: `SF15`  
**Short Name**: `streaming-chat-proxy`  
**Created**: 2026-07-13  
**Status**: Draft  
**Source**: 周度 Spec F04、Go 流式适配/并发规范、OpenAI-compatible SSE 契约

## 目标与价值

为买家提供火山方舟流式 Chat Completions 代理，按到达顺序即时转发兼容 SSE 事件，不等待完整模型响应。流开始前的失败使用统一错误结构；响应头发出后的中断只能通过流终止和可关联日志表达，不能混入非流式 JSON 错误体。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 实时接收兼容事件流 (Priority: P1)

作为买家，我希望 `stream=true` 时尽快收到第一个事件，并按官方兼容方式处理直到 `[DONE]`。

**Independent Test**: 用有效 Key 调用流式入口，验证事件顺序、逐块刷新、完成原因、usage 和唯一终止标记。

**Acceptance Scenarios**:

1. **Given** 认证、路由和上游连接成功，**When** 火山方舟发出首个完整事件，**Then** 网关不等待后续事件即向客户端刷新兼容 SSE。
2. **Given** 上游正常发送多个事件并结束，**When** 客户端读取，**Then** 顺序、delta、finish_reason 保持一致并只收到一个 `[DONE]`。
3. **Given** 上游末块提供 usage，**When** 流正常结束，**Then** usage 被保留并向 SF17 产生一个完整用量观察。

---

### User Story 2 - 在流开始前安全失败 (Priority: P1)

作为买家，我希望无效凭证、非法请求、无可用 Key 或上游无法建立连接时获得普通可解析错误，而不是半开的 SSE。

**Acceptance Scenarios**:

1. **Given** 认证、参数、路由或容量检查失败，**When** 响应头尚未发出，**Then** 返回统一错误结构和正确 HTTP 状态，不建立 SSE。
2. **Given** 上游在发送任何事件前拒绝或超时，**When** 网关仍未开始客户端流，**Then** 返回 429/502/504 等映射错误。

---

### User Story 3 - 正确处理中断、取消与慢客户端 (Priority: P1)

作为平台，我希望客户端取消、上游中断和下游背压都能在有界资源内结束，不泄漏 goroutine、连接或容量租约。

**Independent Test**: 故障注入客户端断开、上游截断、慢读取、取消和超时，检查资源释放及唯一完成观察。

**Acceptance Scenarios**:

1. **Given** 客户端断开，**When** 取消信号到达，**Then** 上游调用被取消、容量租约释放、流结果记录为 client_cancelled。
2. **Given** 上游在已发送事件后中断，**When** 网关检测错误，**Then** 关闭客户端流、不伪造 `[DONE]`、不重试到其他 Key，并记录 upstream_interrupted。
3. **Given** 客户端读取速度持续低于上游产生速度，**When** 缓冲达到上限，**Then** 应用背压或有界终止，不无限增长内存。

### Edge Cases

- SSE 事件跨多个网络块、一个块含多个事件或 UTF-8 字符被拆分。
- 上游只发送注释/心跳，长时间没有数据事件。
- `[DONE]` 重复、缺失或后面仍有数据。
- usage 出现在末块、独立事件、缺失或与累计值冲突。
- 客户端在响应头写出前一刻取消。
- 网关优雅关闭时仍存在长连接。
- 发生 panic 后 Header 已经发送，不能改写状态码。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 本功能 MUST 处理 `POST /v1/proxy/volcano/chat/completions` 且 `stream=true` 的请求，要求标准 Bearer Key 与 JSON Schema。
- **FR-002**: 在写出 SSE 响应头前 MUST 完成 SF11 认证、SF05 授权、SF13 路由、SF14 容量租约及上游连接建立。
- **FR-003**: 成功流 MUST 使用 `text/event-stream`、禁用不当缓存并携带 `X-Request-ID`。
- **FR-004**: 完整上游事件一旦转换完成 MUST 尽快刷新给客户端，不得聚合完整响应。
- **FR-005**: 事件顺序、choices 索引、delta、finish_reason、usage 和 `[DONE]` MUST 符合 SF07 兼容契约。
- **FR-006**: 流开始前失败 MUST 使用统一错误结构；流开始后 MUST NOT 插入非 SSE JSON envelope 或伪造成功终止。
- **FR-007**: 上游中断、客户端取消、idle timeout、hard timeout 和 panic MUST 关闭资源并只释放一次容量租约。
- **FR-008**: 客户端取消 MUST 传播到上游；已开始的流 MUST NOT 自动切换 Key 或重放请求。
- **FR-009**: 整体 hard timeout MUST 为 60 秒；同时定义短于 hard timeout 的连接和无数据进展超时，具体值在公开契约中说明。
- **FR-010**: 每连接缓冲 MUST 有明确上限；慢客户端触发背压或安全断开，不得无限缓存。
- **FR-011**: 正常、截断、取消和超时均 MUST 向 SF17 产生且只产生一个完成观察，包含已知 usage、结束原因、状态和耗时。
- **FR-012**: 请求消息、响应内容、代理 Key 和原始 Key MUST NOT 被日志或追踪记录。
- **FR-013**: 优雅关闭 MUST 停止接收新流，并在既定宽限期内等待现有流完成，之后取消剩余流并释放资源。

### Engineering Requirements *(mandatory)*

- **ER-001 — Contracts**: SSE 头、事件边界、终止和中途错误语义须有机器可验证契约；流式成功是统一响应包络的明确例外。
- **ER-002 — Security & Privacy**: TLS、输入/头允许列表、正文不记录、取消传播和凭证脱敏为强制要求。
- **ER-003 — Data Integrity**: request_id、选中 key_id 和唯一完成观察保持一致；usage 标明官方/估算/缺失与完整性。
- **ER-004 — Performance & Capacity**: 代理额外 TTFB P95 小于 800 毫秒；单事件转发开销 P95 小于 5 毫秒；连接内存受上限控制。
- **ER-005 — Reliability**: 明确 idle/hard timeout、背压、连接池、优雅关闭和不重试规则；所有 goroutine 受 context 管理并可回收。
- **ER-006 — Observability**: 暴露活跃流、TTFB、事件数、字节数、结束原因、取消、超时、背压断开和资源释放计数。
- **ER-007 — Accessibility**: 本功能为开发者 API；协议错误必须带 request_id，文档解释流开始前后不同的错误处理方式。

### Failure and Recovery Scenarios *(mandatory)*

1. **Given** 上游在发送三条事件后断开，**When** 网关检测 EOF，**Then** 不发送 `[DONE]`、释放租约并记录三条已交付事实与 interrupted 结束原因。
2. **Given** 客户端持续不读取，**When** 缓冲达到上限，**Then** 有界关闭连接、取消上游且内存回落到基线。
3. **Given** 网关开始优雅关闭，**When** 存在活跃流，**Then** 新流被 readiness 拒绝，现有流在宽限期内完成或被可观测取消。

### Key Entities

- **Streaming Proxy Context**: request_id、buyer、proxy_key_id、seller key 脱敏 ID、模型、容量租约和时间边界。
- **SSE Event**: 有序兼容事件、序号、类型和大小；内容只在内存中转发。
- **Stream Completion Observation**: 结束原因、HTTP/上游状态、首字节/总耗时、事件数、usage 完整性和 request_id。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 1 万个多样化事件流测试中事件丢失、重复、乱序和伪造 `[DONE]` 次数均为 0。
- **SC-002**: 代理额外 TTFB P95 小于 800 毫秒，单事件转发 P95 小于 5 毫秒。
- **SC-003**: 客户端取消、上游中断、超时和 panic 后连接、goroutine 与容量租约全部在既定超时内释放。
- **SC-004**: 慢客户端压力测试中单连接内存不超过计划定义上限，进程内存不随流时长无限增长。
- **SC-005**: 每个流恰好产生一个完成观察，所有阶段可按 request_id 关联。

## Scope

### In Scope

- 火山方舟流式 Chat Completions、SSE 转发、取消、背压、超时、优雅关闭和完成观察。

### Out of Scope

- 中断续传、跨 Key 流迁移、自动重试、WebSocket、计费和前端逐字展示。

## Test Requirements

- SSE 解析/转发单元与模糊测试覆盖所有边界。
- 集成测试覆盖真实 HTTP 流、取消、截断、超时和 Header 已发送错误。
- 竞态与泄漏测试覆盖 goroutine、连接和租约。
- 慢客户端、并发流和优雅关闭负载测试记录 TTFB、内存和资源回收。
- 流式网关包至少 80% 行覆盖，中断和资源释放分支直接覆盖。

## Assumptions

- 依赖 SF07、SF11、SF13、SF14。
- SF17 持久化完成观察；本功能不等待用量落库再向客户端交付事件。
- V0.1 hard timeout 沿用周度 Spec 60 秒，若真实 Coding Plan 需要更长须先修订契约。
