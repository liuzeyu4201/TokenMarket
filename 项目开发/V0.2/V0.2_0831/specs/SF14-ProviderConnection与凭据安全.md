# SF14 Provider Connection 与凭据安全

**优先级：** P0　**依赖：** SF01、SF09、V0.1 卖家 Key

## 功能描述

Provider Connection 是卖家供给的最小单位，封装厂商、鉴权材料、upstream 项目/组织、区域、base URL 和能力。平台安全保存并最小化使用凭据，任何角色均不能回读明文。

## 功能要求

- 支持目录定义的三厂商稳定鉴权方式；字段按 provider/auth type 验证。
- 凭据在进入服务后立即加密，使用带版本的 envelope encryption/KMS 接口；数据库只存密文和密钥版本。
- 解密仅允许代理执行路径和受控验证任务，采用最小权限服务身份并记录审计。
- UI 创建后仅展示安全元数据；更新凭据通过整体替换和验证，旧版本按策略销毁。
- base URL、项目和区域受 allowlist/SSRF 规则约束，禁止内网/元数据地址和重定向绕过。

## 边界与异常

平台不代理厂商 credential-management API。管理员也不能查看明文；支持人员排障使用脱敏指纹和验证结果。

## 验收标准

1. 数据库备份、日志、trace、事件、前端缓存均无明文凭据。
2. 非授权服务身份和普通/管理员 API 均无法调用解密能力。
3. KMS key rotation 后新旧合法密文可过渡读取，完成迁移后旧 key 被停用。
4. SSRF 测试覆盖 localhost、RFC1918、link-local、DNS rebinding 和重定向。
5. 凭据替换并发请求使用完整旧或新版本，不出现字段混搭。
6. 删除 Connection 后凭据按保留策略不可再用于新请求，审计仍可验证其历史指纹。

## 验收证据

加密设计、权限策略、秘密扫描、SSRF 测试、轮换演练和删除验证。
