# Feature Specification: SF04 手机号验证登录与会话签发

**Feature ID**: `SF04`  
**Short Name**: `phone-login-session`  
**Created**: 2026-07-13  
**Status**: Draft  
**Source**: 周度 Spec F02、宪章安全要求、API 与配置规范

## 目标与价值

为已注册用户提供经过手机号所有权验证的登录和会话签发能力，替代原周度 Spec 中不安全的“仅提交手机号即可登录”。本功能建立后续卖家 Key 管理和买家代理 Key 管理所需的认证上下文。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过一次性验证码登录 (Priority: P1)

作为已注册用户，我希望验证手机号后获得有时效的访问令牌，以便安全调用受保护 API。

**Independent Test**: 为合成用户创建验证码挑战，提交正确验证码，验证只签发一次会话且令牌能识别同一用户。

**Acceptance Scenarios**:

1. **Given** active 用户请求登录验证码，**When** 请求通过频率限制，**Then** 系统创建单次挑战并向已注册手机号发送或在非生产环境安全投递验证码。
2. **Given** 挑战未过期且验证码正确，**When** 用户完成验证，**Then** 系统消费挑战并签发带用户、角色、签发时间和过期时间的访问令牌。
3. **Given** 有效令牌访问受保护接口，**When** 认证完成，**Then** 下游收到服务端建立的用户身份，而不是信任客户端传入的 user_id。

---

### User Story 2 - 拒绝验证码和账户滥用 (Priority: P1)

作为账户所有者，我希望错误、过期或重放的验证码无法创建会话，并且暴力尝试受到限制。

**Independent Test**: 覆盖错误码、过期、重复使用、超次数、频繁发送、停用用户和未知手机号。

**Acceptance Scenarios**:

1. **Given** 验证码错误、过期或已使用，**When** 提交验证，**Then** 请求失败且不签发任何令牌。
2. **Given** 单挑战连续失败达到 5 次，**When** 再次验证，**Then** 挑战失效并要求重新发起。
3. **Given** 账户 suspended 或 deleted，**When** 请求或验证验证码，**Then** 不创建有效会话。
4. **Given** 手机号未注册，**When** 请求验证码，**Then** 外部响应不泄露账户是否存在，内部仍记录安全事件。

---

### User Story 3 - 撤销会话 (Priority: P2)

作为已登录用户，我希望主动退出后当前会话不能继续访问敏感能力。

**Acceptance Scenarios**:

1. **Given** 用户持有有效会话，**When** 执行退出，**Then** 当前会话被撤销，后续请求返回未认证。
2. **Given** 相同退出请求被重放，**When** 再次处理，**Then** 返回幂等成功且不产生额外状态。

### Edge Cases

- 验证码投递供应方超时、返回成功但用户未收到，或重复回调。
- 用户连续请求验证码导致旧挑战与新挑战并存。
- 服务节点时钟轻微偏差影响验证码或令牌过期判断。
- 验证成功和验证码重放同时到达不同实例。
- 令牌签发后账户立即被停用。
- 合成验证码误用于生产环境。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为已规范化手机号创建一次性验证码挑战；验证码有效期为 5 分钟。
- **FR-002**: 同一手机号 60 秒内 MUST 最多发起一次新挑战，并应用按手机号和来源的小时级频率限制。
- **FR-003**: 验证码 MUST 使用安全随机值，持久层只保存不可逆校验材料，不保存可直接使用的明文验证码。
- **FR-004**: 单挑战 MUST 最多允许 5 次失败验证；成功或达到上限后立即不可再次使用。
- **FR-005**: 只有 active 账户通过有效挑战后才能获得访问令牌。
- **FR-006**: 访问令牌 MUST 包含不可变会话标识、用户标识、角色、签发时间和过期时间，默认有效期 60 分钟。
- **FR-007**: 服务端 MUST 校验令牌真实性、有效期、会话撤销状态和当前账户状态。
- **FR-008**: 登出 MUST 撤销当前会话并具备幂等行为；撤销在后续新请求上立即生效。
- **FR-009**: 测试和本地环境 MAY 使用合成验证码通道，但生产环境缺少批准的真实验证通道时 MUST 启动失败。
- **FR-010**: 令牌、验证码、会话校验材料和完整手机号 MUST NOT 出现在日志、错误、指标或接口回显中。
- **FR-011**: 验证与登出接口 MUST 使用版本化契约和统一响应包络，并透传 `request_id`。
- **FR-012**: 相同幂等键的登出重放 MUST 返回首次结果；验证码消费必须通过原子状态转换防止并发成功两次。

### Engineering Requirements *(mandatory)*

- **ER-001 — Contracts**: 请求验证码、验证验证码、校验会话和登出契约须版本化；未认证统一返回 401，已认证但账户无权由 SF05 返回 403。
- **ER-002 — Security & Privacy**: 默认拒绝、服务端认证、验证码哈希、会话撤销、重放防护和速率限制均为发布门槛；个人数据按最小化原则处理。
- **ER-003 — Data Integrity**: 用户状态以 PostgreSQL 为事实源；Redis 可加速挑战或撤销查询，但丢失后不得导致已撤销会话恢复有效。
- **ER-004 — Performance & Capacity**: 不含外部投递的验证码校验和令牌签发 P95 小于 300 毫秒；令牌校验 P95 小于 20 毫秒。
- **ER-005 — Reliability**: 验证码投递设置有界超时且不自动重试非幂等发送；挑战创建和消费必须可从进程重启恢复。
- **ER-006 — Observability**: 记录发送结果、验证成功/失败、频率限制、撤销和异常重放计数，所有维度均脱敏并带请求标识。
- **ER-007 — Accessibility**: V0.1 无前端；错误结构须区分可重试、需重新获取验证码和账户不可用，支持未来界面无障碍提示。

### Failure and Recovery Scenarios *(mandatory)*

1. **Given** 验证码供应方超时，**When** 用户请求验证码，**Then** 在有界时间内返回安全的暂时失败，不创建可被猜测为已投递的有效状态。
2. **Given** 两个请求同时提交正确验证码，**When** 消费挑战，**Then** 只有一个原子操作成功，另一个被判定为已使用。
3. **Given** Redis 或进程重启，**When** 校验已有会话，**Then** 从持久事实恢复挑战/撤销语义，不把无效会话变为有效。

### Key Entities

- **Verification Challenge**: 挑战标识、用户或规范化手机号引用、验证码摘要、失败次数、过期时间、消费状态和审计信息；属于敏感认证数据，短期保留后清除。
- **Session**: 会话标识、用户、角色快照、签发/过期/撤销时间和状态；不可保存完整访问令牌。
- **Access Token**: 仅创建时交付给用户的认证凭证；服务端保存校验或撤销所需的最小材料。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 正确且未过期验证码首次提交可创建一个会话，错误、过期或重放验证码创建会话数为零。
- **SC-002**: 同一验证码 100 个并发提交中最多一个成功。
- **SC-003**: 会话撤销后 1 秒内，所有新请求均被拒绝。
- **SC-004**: 令牌校验 P95 小于 20 毫秒，验证码本地校验与签发 P95 小于 300 毫秒。
- **SC-005**: 认证日志、错误和测试产物扫描不出现验证码、令牌或完整手机号。
- **SC-006**: 暴力尝试和频繁发送的负面测试 100% 触发既定限制。

## Scope

### In Scope

- 手机验证码挑战、验证码消费、访问令牌、会话校验、当前会话撤销和安全审计。

### Out of Scope

- 密码登录、OAuth、刷新令牌、多设备会话管理、找回密码、2FA、短信供应商商业采购和前端页面。

## Test Requirements

- 单元测试覆盖过期、尝试次数、频率限制、令牌声明和错误映射。
- 集成测试覆盖数据库/缓存交互、进程重启、投递超时和撤销。
- 并发及重放测试直接覆盖验证码单次消费和幂等登出。
- 安全测试覆盖令牌伪造、算法降级、日志泄露、账户枚举和生产合成验证码禁用。
- 认证领域相关包至少 80% 行覆盖，所有安全分支直接覆盖。

## Assumptions

- 依赖 SF03 提供 active 用户和规范化手机号。
- V0.1 本地与自动化测试使用合成验证码；生产部署必须配置批准的真实通道。
- 访问令牌有效期默认 60 分钟；刷新令牌留待后续独立功能。
